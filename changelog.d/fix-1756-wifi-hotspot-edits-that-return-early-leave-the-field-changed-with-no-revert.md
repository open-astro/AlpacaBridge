### Fixed

- **A hotspot edit that cannot be applied now puts the field back** (WiFi web UI, issue #1756): when the hotspot is busy, or the name is empty or 5 GHz has no country on a configured hotspot, the edited name, password or band returns to its previous value and the hotspot toggle returns to its previous position, instead of looking saved. Tests in `wifi-confirm.test.js` ("hotspot name edit while busy", "hotspot toggle while busy", "hotspot name emptied", "hotspot edit on 5 GHz with no country", "hotspot toggled off on 5 GHz with no country") assert the restored value and no PUT. On a hotspot that is not configured yet, the name and password you type stay until both are set, then one PUT sends both (tests "hotspot not configured, no password", "name emptied by password first", "name then password sends one PUT with both").
