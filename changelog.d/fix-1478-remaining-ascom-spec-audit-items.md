### Breaking changes

- **Telescope `DoesRefraction` throws `PropertyNotImplemented`** (Bisque, Celestron NexStar, iOptron, SynScan, Sky-Watcher, ZWO mount; issue #1478): these drivers stored the flag and read it back without applying any refraction, so a client that switched it on was told a correction was active. Read and write now raise the ASCOM "not implemented" error, as ITelescopeV4 requires of a driver that neither knows nor computes refraction. OnStep is unchanged (it reads the firmware). **After upgrading:** a client that wrote `DoesRefraction` sees an error instead of an echo; the telescope does not refract.
- **Telescope `SiteElevation` throws `InvalidOperation` until it is set** (Bisque, Celestron NexStar, iOptron, SynScan, ZWO mount; issue #1478, decision 0019): an unset elevation read 0 m, which is a real place. It now reads as unset until the device config or a client writes it, as the ASCOM time-and-place FAQ requires. Sky-Watcher and Celestron CGX already behaved this way. **After upgrading:** for the ZWO mount, enter the elevation in the device's web UI form; for Bisque, Celestron NexStar, SynScan and iOptron, whose forms have no elevation field, have the client write `SiteElevation` once: the bridge saves a client-written site to the device config (unless `learnSiteFromClient` is false) and reads it at the next start.
- **Celestron NexStar `PulseGuide` takes at most 25500 ms** (issue #1478): a longer pulse was cut to 25.5 s on the wire while the driver kept reporting the full length, so it now throws `InvalidValue`. **After upgrading:** a client that asks for a pulse over 25.5 s gets an error and must split the pulse.

### Fixed

- Gemini, WandererAstro, iOptron, QHY, SynScan, Celestron, ZWO and Bisque (issue #1478): `MaxBrightness`, `MaxStep`, `MaxIncrement`, `RightAscensionRate` and `DeclinationRate` now throw `NotConnected` while disconnected (the contract sweep probes each). The Gemini focuser raises `DriverException` when the `TempComp` read fails instead of reporting false (`Gemini Focuser Driver - a failed TempComp read raises DriverException, not false`). The Gemini flat panels report `Brightness` 0 while `CalibratorState` is Off after connect and `CoverMoving` true exactly when `CoverState` is Moving (`test_gemini_flatpanel*.cpp`).
- **`DestinationSideOfPier` rejects out-of-range coordinates** (Bisque, Celestron NexStar, SynScan, Sky-Watcher; issue #1478): RA outside [0, 24) hours or Dec outside [-90, 90] degrees throws `InvalidValue`, even while disconnected, where it used to return a pier side (`spec audit - DestinationSideOfPier rejects out-of-range RA and Dec` in each driver's test file). iOptron, ZWO and Celestron CGX already validated.
- **Celestron NexStar `PulseGuide` validates before the connection check** (issue #1478): a negative duration, a duration over 25500 ms or a direction outside 0-3 throws `InvalidValue` first (`Celestron spec audit - PulseGuide rejects ...` cases).
- **Celestron NexStar `UTCDate` no longer answers with the host clock** (issue #1478, decision 0014): when the mount's clock cannot be read, `UTCDate` throws `InvalidOperation` instead of reporting the host time as the mount's (`Celestron spec audit - UTCDate throws InvalidOperation when the mount clock cannot be read`).
