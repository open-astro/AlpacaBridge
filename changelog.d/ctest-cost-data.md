### Changed (tooling)
- **The all-vendors CI job starts its slowest tests first** (CI, `.github/workflows/ci.yml`, `run_all_tests.sh`, `scripts/ctest_cost.py`, `AlpacaCore/cmake/CTestCost.cmake`): `ctest -j` starts tests in descending `COST` order, but every CI run had no timings to go on, so it started them in the order they were added. The slowest case, the OnStep Park and FindHome race at 266 s, started about 7 minutes into a 679 s run and finished last. ctest's own memory of timings cannot fix this: it lives in the build tree, which `run_all_tests.sh` deletes, and ctest splits each of its lines at the first space, so no Catch2 case ever matched its timing (CMake 3.28 and 3.31). `run_all_tests.sh` now takes `CTEST_COST_DATA=<file>`: ctest writes a JUnit report, `scripts/ctest_cost.py` turns it into one `set_tests_properties(... COST ...)` line per test when the script exits, and `AlpacaCore/cmake/CTestCost.cmake`, added to the tests' `TEST_INCLUDE_FILES` after Catch2 discovery, reads the file on the next run. `build-vendors` keeps the file in the Actions cache, saved on each push to `main` and read by pull requests and the merge queue. Replaying that run's 4,063 test times through ctest's scheduler at `-j 16` gives 470 s in the added order and 326 s slowest-first. `build-test` and the ASan job do not use it: one test, `test_server_socket`, already takes their whole ctest run.
