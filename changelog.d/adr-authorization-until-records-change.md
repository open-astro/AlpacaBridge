### Changed (tooling)
- **One decision-record authorization lasts until the records change** (`scripts/check_adr_authorization.py`, `.github/workflows/decision-records.yml`, `docs/decisions/README.md`, PR template, ci-gates instructions): `ADR authorized <sha>` used to hold only while `<sha>` was the PR head, so every push, even a code-only review fix, needed a new comment. It now holds for a later head as long as every decision-record file the PR changes has the same content there as at `<sha>`, compared by git object over the whole `docs/decisions/` subtree (a record added in a subdirectory counts), so a merge of the base branch or a rebase that leaves the records alone keeps it. A push that edits, adds or removes one of those records still needs a new authorization, and a commit GitHub cannot resolve does not count.

### Fixed (tooling)
- **A decorated "Issues found" sign-off no longer fails the review** (`scripts/check_adr_scope.py --checklist`, from the #1516 review): the checklist gate compared the review's last line with the bare sign-off, so a bold, italic or period-ended "Issues found" under a `defect` line failed the job and posted nothing. That emphasis and a closing period or exclamation mark are now ignored; a last line that only contains the words still does not count.
