### Changed
- **The Host header check is now off by default and opt-in**, AlpacaHTTP, issue #392. Since the check landed, a web UI or API request whose `Host` was a router or reverse-proxy name (`astropi.lan`, `astropi.fritz.box`) got HTTP 403, and only an edit over SSH fixed it. After this upgrade every `Host` is served unless you set `http.host_check_enabled: true` (or `ALPACAHTTP_HOST_CHECK=true`); a config file with no such key means off. With the check on, behaviour is unchanged and `http.allowed_hosts` still lists the extra names. The Origin-versus-Host cross-origin guard stays on always. With the check off, a DNS-rebinding page can reach the device PUTs again; turn it on if the board is reachable from untrusted browsers.
