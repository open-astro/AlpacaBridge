### Breaking changes
- **Celestron CGX/CGX-L direct USB: a mount that stops answering reads Connected false after 30 s** (AlpacaCore, issue #1940, decision 0009): a fault from three failed state polls that stands for 30 s (`util::kLinkStalenessBound`) is now a lost link. `Connected` reads false, every member answers `NotConnected`, `DeviceState` is empty and the port is released; nothing reconnects on its own. Before, `Connected` stayed true and every read failed with "communications compromised" for as long as the service ran. A poll that times out also counts as a session error (decision 0011 rule 2), so the pointing reference is gone even when the client was not reading at the time. **After upgrading:** reconnect the CGX after it reads Connected false (no Disconnect is needed first), then run FindHome before the next slew, Sync or PulseGuide.

### Changed
- **Celestron CGX/CGX-L direct USB: getters answer from a 250 ms state poll and never wait on the mount** (AlpacaCore, issue #1940, decisions 0009, 0010, 0011): one poll per connection reads the RA and Dec encoders every 250 ms, and RightAscension, Declination, Altitude, Azimuth, SideOfPier and `DeviceState` (its `TimeStamp` is when the frame was measured) are served from it, stale but served under the 30 s loss bound. IsPulseGuiding is driver state and no longer reads the guide status from the mount. The coordinate getters no longer wait behind a Sync, a slew, a tracking write or a stop, and the 30 ms stationary raw-pair cache is gone. The tracking rollback, the stop retry and an ambiguous guide start flush the AUX stream on the port already held and never reopen it; for the loss behaviour, see Breaking changes.

### Changed (tests)
- **Celestron CGX snapshot and link-loss cases** (AlpacaCore, issue #1940): `test_celestron_cgx_link_loss.cpp` (staleness loss, the loss stamp, a fault cleared inside the bound, no reopen from a stop in flight), coordinate getter-wait and IsPulseGuiding cases, `test_celestron_cgx_telemetry.cpp` rewritten for the snapshot, the CGX contract-sweep snapshot hook (CS3) and a `[stress]` storm with the poll running. Existing CGX cases hold the poll (`cgx_clock_cleanup.h`) and read a new frame through a test seam.
