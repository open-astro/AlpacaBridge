### Fixed

- **An iOptron iEAF or iAFS2/3 focuser whose USB cable is pulled reads Connected false at once and reconnects with one Connect**, iOptron iEAF focuser driver, issue #1723, decision 0009 rule 2. A hangup on a reply read used to throw a `DriverException` "iEAF serial link lost (errno N)", and `EIO`/`ENXIO`/`ENODEV` on a command write a `DriverException` "Write failed", while `Connected` stayed true and the dead port stayed claimed; a hangup while waiting for a move, halt or zero ack was taken for a silent firmware and the command reported success. The wrapper now releases the port at once, `Connected` reads false, every member throws `NotConnected` (a status frame cached before the loss is not served), `DeviceState` is empty, the web UI firmware is hidden, and `get_link_fault()` gives the loss reason until the next Connect or Disconnect. Nothing reopens the port until the client's next Connect, which reopens it without a Disconnect first and polls the focuser afresh. A cable pulled during the connect handshake fails that Connect with `NotConnected` and keeps no loss reason. No loss time is stamped (no #521 motion-on-relink consumer). Calls on a pulled focuser already failed before this change, so nothing that worked stops working. Tests: seven `iEAF Link - ...` cases in `AlpacaCore/tests/test_ioptron_ieaf_focuser.cpp`. Pty fake evidence only; not checked on the rig.
