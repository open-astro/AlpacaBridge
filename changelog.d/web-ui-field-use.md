### Added
- **Devices tab shows whether a client is actually using a device** (AlpacaHTTP, issue #1764): `GET /management/v1/configureddevices` now reports per device `ActiveClients` (client registrations refreshed inside the 10 minute window) and `LastClientRequestAgeMs` (age of the newest client request, absent when there is none), read from the router's per-client registry without touching hardware. The status dot is green only when the device is connected and a client made a request in the last 60 s; a connected device with no client request for longer is yellow with "Connected, no client request for N s". The web UI's own device requests (sent with `X-AlpacaBridge-Client: web-ui`) do not count. The 10 minute disconnect window is unchanged.

### Changed
- **Web UI uses its own dialogs instead of browser pop-ups** (AlpacaHTTP web UI, issue #1764): every `alert()`, `confirm()` and `prompt()` is replaced by a dark in-page dialog (title, text, Cancel and Confirm, danger style for destructive actions) or a toast for results. Esc and Cancel return focus to the button that opened the dialog. Form validation errors now show under the field they are about, and the WiFi 5 GHz country reminder shows in the WiFi card.
- **Keyboard and screen-reader use of the web UI** (AlpacaHTTP web UI, issue #1764): the Devices, Configure and Server Info tabs are a proper tab list (selected state announced, arrow keys, Home and End move between tabs), every control shows a focus ring when reached by keyboard, and transitions are turned off for users who ask for reduced motion.
- **Empty Devices tab and narrow-screen clock** (AlpacaHTTP web UI, issue #1764): with no devices configured the Devices tab shows an "Add device" button that opens Configure, and at 480 px and below the header clock drops its seconds.
- **Host check warning** (AlpacaHTTP web UI, issue #1764): the "Restrict Host names" toggle now says that other clients (NINA, a phone, a second browser) that use a name that is not allowed will be refused, so every name they use should be added first.

### Added (tests)
- **Client activity and web UI field-use cases** (issue #1764): two `test_routing` cases over an injectable registry clock (`Router::set_client_clock_for_test`), twelve `field_use.test.js` cases for the status dot, dialogs, tab semantics, focus ring, empty state, header clock (including real `formatServerClock` output in every zone tier) and Host check note, and ten `ui_dialog.test.js` cases that run the real dialog, toast and field-error code of `app.js` (Cancel and Esc resolve no, a destructive dialog opens on Cancel, a success toast closes on its timer and an error toast stays, a field error clears and restores `aria-describedby`).
