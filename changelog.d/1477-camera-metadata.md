### Breaking changes
- **QHY requires trustworthy exposure limits at connect** (AlpacaCore, issue #1477): if the camera advertises exposure control but its SDK range query fails, connection now fails instead of using guessed limits. **After upgrading:** correct the SDK/device range-query failure and reconnect.
- **Expired acquisitions no longer publish late frames** (AlpacaCore, issue #1477): QHY, GPhoto, iGuider and ToupTek/Altair reject a frame past its watchdog deadline even when no client polled during acquisition. Completion reads report the failure and LastExposure retains the previous success, or remains unset. **After upgrading:** treat a completion error as a failed acquisition and start a new exposure rather than using the late frame.
- **QHY failed mode changes invalidate exposure limits** (AlpacaCore, issue #1477): range-dependent reads and acquisitions fail instead of trusting the previous mode's limits after a mode-change or range-refresh failure. **After upgrading:** retry the mode change successfully or reconnect before acquiring another frame.
- **ToupTek/Altair pending metadata reads now fail until an image succeeds** (AlpacaCore, issue #1477): `LastExposureDuration` and `LastExposureStartTime` no longer return candidate values during the first pending or failed acquisition. **After upgrading:** clients must wait for a successful image before reading metadata; later pending or failed acquisitions retain the previous successful values.
- **iGuider no longer invents an exposure start time** (AlpacaCore, issue #1477): after a successful image, `LastExposureStartTime` now raises `PropertyNotImplemented` because the UVC stream has no verified photon-start timestamp. Before the first image it still raises `InvalidOperation`, and disconnected reads raise `NotConnected`. **After upgrading:** clients must accept an unavailable start time; use an externally verified timing source when accurate acquisition UTC is required.

### Fixed
- **Camera review follow-up** (AlpacaCore, issue #1477): QHY exposure limits fail fast while connecting, disconnect invalidates their cache, and nonfinite durations are rejected before acquisition. ZWO direct image retrieval reports a failed retry immediately; GPhoto no longer rejects disconnected requests against an unknown 30-second placeholder limit. Align both SVBONY watchdog tests' abort ordering and correct older metadata release notes.
- **Camera replacement failure cleanup** (AlpacaCore, issue #1477): retire cancelled QHY acquisitions before replacement setup can fail, without erasing successful metadata. Keep the SVBONY watchdog regression's read held until abort so its result does not depend on worker scheduling.
- **Camera metadata timing and duration** (AlpacaCore, issue #1477): align acquisition metadata with applied exposure settings and SDK acquisition boundaries, preserve the previous successful exposure during pending or failed acquisitions, and close metadata-read disconnect races. The ToupTek implementation also serves Altair, and Player One also serves iCAM; physical sensor-start accuracy still requires vendor-specific hardware evidence.
- **Camera metadata regression coverage** (AlpacaCore and AlpacaHTTP, issue #1477): extend session, failure, timing and duration checks over camera fakes and verify exact HTTP error codes, numeric durations and UTC serialization.
