### Changed

- **A stored device is identified by device type and number, vendor is data** (AlpacaHTTP, issue #2482): the persisted device list now matches an entry by device type and number only, the rule the live device registry already uses. `PersistedConfigStore` has one lookup, `matches()`, in place of `matches_type_and_number`, `matches_vendor_type_and_number` and `matches_vendor_when_given`. Configuring a different vendor at a stored type and number replaces the entry instead of adding a second one, and its stored uniqueId counts as free for the new config. `removedevice` removes the stored entry at the type and number whatever vendor the request names (it already removed the live device that way). When the file already holds two entries at one type and number, the load keeps the first in file order, drops the later one with a warning and saves the file without it. Covered by `AlpacaHTTP/tests/test_persisted_config_store.cpp`.
