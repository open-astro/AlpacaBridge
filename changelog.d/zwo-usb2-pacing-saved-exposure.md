### Fixed

- **ZWO camera: RAW16 no longer streams above the USB Limit after the SDK restores a long exposure**, ZWO camera driver, issue #2413. ASI SDK 1.41 saves the last exposure and sensor clock in `ASIconfig.xml` and restores them at every open; with the exposure register above 100 ms the sensor runs at its slowest clock, and a frame-format or USB Limit write there paces RAW16 at 23.95 MB/s instead of the 17.20 MB/s that USB Limit 40 allows, so a camera without a frame buffer (ASI120MM Mini) loses bytes mid-frame on a Raspberry Pi 4 USB2 path. The driver now writes a 10 ms exposure before the USB Limit at connect and before every Bin or ROI format write, so the SDK computes the pacing at the normal clock and keeps it when the exposure goes long; each exposure still writes its own value before it starts. Covered by `ZWO frame-format writes run with a sub-100 ms exposure register` in `AlpacaCore/tests/test_zwo_fake_sdk.cpp`; checked on an ASI120MM Mini with the SDK debug log (pacing 1735 after connect and after a Bin change, was 9c2); ConformU not re-run.
