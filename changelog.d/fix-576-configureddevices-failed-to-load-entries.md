### Changed
- **`configureddevices` no longer lists saved devices that failed to load** (AlpacaHTTP, issue #576): a persisted entry whose driver did not register used to appear in `GET /management/v1/configureddevices` as `"<vendor> (failed to load)"` with an empty `UniqueID` and no route, so an Alpaca client such as ConformU saw a device it could not reach. The standard list now holds only registered devices. The entries moved to a new web UI extension endpoint, `GET /management/v1/faileddevices` (also `/management/faileddevices`; other methods answer 405), which returns them in the old row shape (`LoadError: true`, `Vendor`, `Config`), and the web UI merges it into the Devices tab, so the red error card can still be edited or removed. Covered by `test_routing` ("failed-to-load entries are served by faileddevices, not configureddevices (#576)").
