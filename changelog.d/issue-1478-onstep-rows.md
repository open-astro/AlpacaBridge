### Breaking changes

- **OnStep `SiteElevation` throws `InvalidOperation` until it is set** (issue #1478, decision 0019): an unset elevation read 0 m, which is a real place. It now reads as unset until the device config or a client writes it. **After upgrading:** the OnStep form has no elevation field, so have the client write `SiteElevation` once: the bridge saves a client-written site to the device config (unless `learnSiteFromClient` is false) and reads it at the next start. Test: `test_onstep_telescope.cpp` "OnStep Telescope Driver - SiteElevation throws InvalidOperation until it is set".
- **OnStep `UTCDate` no longer answers with the host clock** (issue #1478, decision 0014): the connect reads the mount clock once, and when that read fails `UTCDate` throws `InvalidOperation` (until a `UTCDate` write or the next connect) instead of reporting the host time as the mount's. `UTCDate` and `DeviceState` never wait on a serial read. **After upgrading:** a client that reads `UTCDate` from a mount whose clock does not answer gets an error; writing `UTCDate` (or `syncTimeOnConnect`) sets the mount clock. Test: `test_onstep_telescope.cpp` "OnStep Telescope Driver - UTCDate throws InvalidOperation when the mount clock cannot be read".

### Fixed

- **OnStep: the rate getters throw `NotConnected` while disconnected, and PulseGuide refuses a duration it cannot send** (issue #1478): `RightAscensionRate` and `DeclinationRate` read 0 even with no mount connected; they now throw `NotConnected`, as every other telescope driver does, and the contract sweep's OnStep exemption is gone. A `PulseGuide` longer than 9999 ms (the most OnStep's 4-digit `:Mg` command holds) was clamped to 9999 ms and reported as done; it is now refused with `InvalidValue`. Tests: `test_onstep_telescope.cpp` "OnStep Telescope Driver - PulseGuide refuses a duration over 9999 ms"; `test_contract_sweep.cpp` the OnStep telescope's disconnected rate-getter case.
- **OnStep `DestinationSideOfPier`, `PulseGuide` and `SyncToCoordinates` check their arguments first** (issue #1478): RA outside [0, 24) hours or Dec outside [-90, 90] degrees, and a PulseGuide direction outside 0-3 or duration outside 0-9999 ms, throw `InvalidValue` before the connected, link-fault and parked checks; `DestinationSideOfPier` used to return a pier side for any RA and Dec, and a bad argument sent while the link was faulted got the fault's `DriverException`. Tests: `test_onstep_telescope.cpp` "OnStep Telescope Driver - DestinationSideOfPier and PulseGuide check arguments before the connection"; `test_onstep_link_loss.cpp` "OnStep link loss - a mount that stops answering latches a fault and a reply clears it".
