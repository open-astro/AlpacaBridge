### Fixed
- **Celestron NexStar: Slewing stays true after a MoveAxis that takes over a failed slew** (Celestron driver, issue #2431): a MoveAxis that superseded a slew body still winding down from a failed GOTO set its axis moving and returned, but Slewing read the old body's published false until that body ended, because the getter checked the running body before the moving axes. It now checks the moving axes first. This was the intermittent "Celestron MoveAxis - successful dispatch clears a stored slew error" failure.
- **Sky-Watcher rate writes made as a pulse ends are no longer dropped** (Sky-Watcher driver, issue #2431, from #2444 on main): a `DeclinationRate` or `RightAscensionRate` write between a pulse's end-of-pulse restore and its release of the axis saw the axis busy and stored the rate for a restore that had already run, so the mount kept the old Dec offset or RA drive rate until the next rate write. The pulse now applies such a write when it releases the axis, also when it moves RA out of the duty-cycled or stopped drive, returns Dec to the rate the restore had applied, or lands while the restore waits for Dec to stop. A new `set_pulse_release_hook()` test seam parks a pulse in that window.

### Fixed (tests)
- **Five flaky cases wait on the event they check** (issues #2431, #2447, #2448): "Celestron CGX link loss - a cable pulled mid-operation loses the link and the body ends on its own" (#2447) and the other link-loss cases now wait for the paused state poll to park after Connect before they count clock waiters. "GPhoto camera fake - Name and identity getters answer while a connect holds the SDK" (#2448) no longer meets a sensor-cache line that a sibling test process restored after this one's reset: every fake camera model now carries a per-call serial. From #2444 on main: the Sky-Watcher "#1706" duty-stop case waits for the duty worker to leave the clock and then for the DeclinationRate write while the pulse still owns Dec; the iGuider fake V4L2 camera takes one frame interval for a dropped frame, as uvcvideo does; "Celestron CGX USB Telescope Driver - disconnect waits only for the active pulse packet" waits for a guide-status read made after its second pulse.
