### Changed
- **WandererAstro cover calibrator, rotator, filter wheel and WandererBox switch moved into the device catalog** (AlpacaCore, AlpacaHTTP, issue #969): one schema (`wandererastro_schema.cpp`, every build) and one factory (`wandererastro_catalog.cpp`, only under `ALPACACORE_ENABLE_WANDERERASTRO`) replace the router's four register arms, its sanitize branch and four driver includes (tests `Builtin catalog - register_builtin_schemas describes the WandererAstro devices in every build`, `Builtin catalog - register_builtin_factories makes the WandererAstro devices available only when built`). The factories call the hardware-free `create_*_by_index` paths, so no port scan runs at registration. The filter wheel's `filterNames` is now a declared string list, so the catalog rejects a non-array or non-string value (test `Builtin catalog - WandererAstro normalize refuses a missing port, a negative index or a bad switchType`). Each type still refuses a `serial` connection with no `portPath`, a negative index and (switch) an unknown `switchType` with the same texts. `GET /management/v1/devicecatalog` now lists the four `wandererastro` descriptors, and a saved WandererAstro entry keeps only the fields its device type declares (a cover calibrator drops a stale `rotatorIndex`; test `Builtin catalog - WandererAstro sanitize keeps the declared fields per device type`). `scripts/check_layering.py`'s AlpacaHTTP vendor-include baseline drops from 17 to 13.
