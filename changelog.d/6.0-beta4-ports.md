### Changed
- **ZWO cameras accept a 0 s exposure and run it at the shortest exposure the camera supports** (AlpacaCore, issue #2259): `StartExposure(0)` (a bias frame) and any duration below the SDK minimum used to answer `InvalidValue`; they now run at `ExposureMin`. Ported to 6.0 from main's PR #2325, StartExposure only; main's argument-order changes stay in 6.1.

### Fixed
- **QHY cameras run a 0 s exposure at ExposureMin instead of 0 microseconds** (AlpacaCore, issue #2259): `StartExposure(0)` (a bias frame) and any duration below the camera's minimum now write the minimum to the SDK, the same value `ExposureMin` reports, including 1 microsecond on a camera whose exposure range reads no minimum or is not listed. Ported to 6.0 from main's PR #2343, StartExposure only.
- **A failed QHY frame read no longer ends the server** (AlpacaCore, issue #2292): the frame read was the one SDK call in the exposure worker outside a `try`, so a throw from it (the SDK wrapper's "camera not open") ended the process; the exposure now fails with that text, raised by `ImageReady`. Ported to 6.0 from main's PR #2372, the QHY frame read only; main's PulseGuide duration bound stays in 6.1.

### Fixed (tests)
- **Gemini flat panel lost-link checks wait for the port release** (AlpacaCore tests, issue #2402): the flat panel's `require_lost` checked the port registry as soon as `Connected` read false, before the thread that met the hangup had closed the port; it now waits up to 1 s for the release. Ported to 6.0 from main's PR #2404.
- **AsyncConnectable race cases hold the task with `ConnectHoldGate`** (AlpacaCore tests, issue #2402): seven cases slept 10-20 ms and assumed the task had reached its connect or disconnect work by then, which an ASan+UBSan runner missed; they now wait for the test-only `connect_hold_gate.h` to report the task inside that work. Ported to 6.0 from main's PR #2404; main's PDH staleness case does not exist on 6.0.
- **Gemini focuser, iOptron iEAF and iEFW lost-link checks wait for the port release; the CGX AbortSlew re-home case waits for the AbortSlew, not a 2 s grace** (AlpacaCore tests, issue #2466): each `require_lost` helper checked the port registry as soon as `Connected` read false, the race #2402 fixed for the flat panel, and now waits up to 1 s for the release. "AbortSlew during a re-home sends no further home" gave the AbortSlew 2 s of real time before stepping the clock; it now requires the AbortSlew to have returned, which is when it has cancelled the home body.
