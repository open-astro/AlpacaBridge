### Fixed
- **A device config can no longer choose which GPIO line, chip node or device file the server opens** (issue #765): `configuredevice` for a ZWO ASIAIR switch now refuses (HTTP 400, config not saved) any `ports[].gpio` other than 12, 13, 26 and 18 and any `gpioChip` other than `/dev/gpiochip0`; the ASIAIR Plus (RK3568) accepts only `devicePath` `/dev/pwm-gpio-misc`; the iOptron iMate and ToupTek StellaVita PowerBoxes accept only their board's `gpioChip`. A repeated `ports[].gpio` value is refused the same way (HTTP 400). A new test with recording libgpiod stubs covers it.
