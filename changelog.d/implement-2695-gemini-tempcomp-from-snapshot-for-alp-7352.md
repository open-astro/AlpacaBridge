### Changed

- **Gemini focuser serves `TempComp` from the polled state** (Gemini, issue #2695). The 250 ms poll now also reads `:24#`, so a `TempComp` read no longer waits on the wire behind the poll (on the fake it missed ConformU's 0.1 s FAST target in 3 of 6 local runs). `set_temp_comp` writes the new value through, so the next read returns it at once. A failed `:24#` read leaves only `TempComp` unavailable (`DriverException`, never `false`) and is not asked again for 30 s; it does not count toward the link fault. Covered by `test_gemini_focuser_snapshot.cpp` (`TempComp reads between poll ticks cause no wire reads`, `TempComp is true right after a successful set_temp_comp`, `a TempComp probe that fails keeps Position and backs off`, `a cable pulled during a poll's TempComp read ends the poll at once`); [decision 0016](docs/decisions/0016-getters-never-wait-on-device-io.md) Gemini focuser row updated.
