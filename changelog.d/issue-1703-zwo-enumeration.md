### Fixed
- **ZWO EFW, EAF and CAA: unreadable devices no longer hide healthy devices** (AlpacaCore, issue #1703): enumeration skips a failed SDK ID read with a warning, and a failed property read on an EAF or CAA (on an EFW only when it says the wheel is removed or the id is invalid; issue #1668 lists any other EFW property failure by its id), preserves the original SDK slot of each readable device, and binds configured indexes by SDK slot rather than filtered list position; for entries with unreadable properties, see Breaking changes.

### Breaking changes
- **ZWO EAF and CAA index binding no longer uses incomplete enumeration entries** (AlpacaCore, issue #1703): an index-based Connect now refuses a slot whose SDK property read fails during enumeration, even if a later read after opening the device could succeed. Explicit-ID binding is unchanged. The ZWO EFW is not affected: a wheel whose property read fails before it is opened is still listed by its id (issue #1668). **After upgrading:** restore readable device properties and retry Connect; do not change the index to the position of another readable device in the filtered list.
