### Changed (tooling)
- **`run_all_tests.sh` builds both suites in one tree** (CI, issue #1251): it now configures `AlpacaHTTP/build` once with `ALPACACORE_BUILD_TESTS=ON`, so `alpacacore_tests` lands in `AlpacaHTTP/build/AlpacaCore/tests` and every AlpacaCore source is compiled once per run instead of twice (141 of the 173 objects the old AlpacaHTTP step compiled were AlpacaCore sources it had already built). One `ctest` runs both suites in one parallel pool, the AlpacaCore floor is counted in the AlpacaCore subdirectory and the AlpacaHTTP floor as the rest of the tree, and the `coverage` job's gcovr reads the one tree instead of merging two. `AlpacaCore/build` is no longer built; the script still deletes it so an old binary there cannot be mistaken for a fresh one.

### Changed (tests)
- **Slow Sky-Watcher cases run their slews on virtual time** (AlpacaCore tests, issue #1221, slice 1 of #1220): 23 cases in `test_skywatcher_async.cpp`, `test_skywatcher_motion_limits.cpp` and `test_skywatcher_backlash.cpp` put the fake mount on a `FakeTaskClock` and pump it (goto legs jumped, everything else following wall time so tracking stays consistent with host-clock LST, decision 0001); the backlash landing and pulse cases also put the driver on the clock. Every assertion, tolerance and case name is unchanged. The goto-jump helpers that `test_skywatcher_pointing.cpp` and `test_skywatcher_backlash.cpp` each carried now live once in `AlpacaCore/tests/skywatcher_fake_clock.h`. Cases whose time is a driver wall-clock timer, a host-clock measurement or real I/O stay on real time; the slow pointing cases were already on the fake clock.
