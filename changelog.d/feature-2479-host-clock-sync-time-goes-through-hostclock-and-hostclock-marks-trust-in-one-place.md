### Changed

- **Sync Time goes through `HostClock`**, AlpacaHTTP and AlpacaCore, issue #2479. `POST /management/v1/synctime` now calls the new `HostClock::set_from_operator()`, which sets the clock, writes the hardware RTC and marks the host clock trusted; `HostClock` also marks trust for a client `UTCDate` step or confirmation, so the router and the telescope route no longer call `HostClockTrust::mark_set()` (the server timer's observed-step mark stays in `Router::check_host_clock()`, where it never reaches the RTC write). The responses, the `clock_settime failed (requires CAP_SYS_TIME): <strerror>` error text and `ClockSource` are unchanged. Sync Time can now be driven through `Router::set_host_clock_hooks()`, which gained a `write_rtc` hook; covered by the `open-astro#2479` cases in `AlpacaHTTP/tests/test_routing.cpp` (setter gets the epoch, RTC written, trust latched, refusal text returned with nothing latched) and `AlpacaCore/tests/test_host_clock.cpp`.
