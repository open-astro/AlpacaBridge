### Fixed
- **ZWO ASIAIR Pro: a PWM port is no longer released low at disconnect** (AlpacaCore, issue #772): `close()` stopped each soft-PWM worker wherever it was in the cycle and released the GPIO lines, so a port at a partial duty (a dew heater at 50 %) was left off at disconnect about half the time. It now drives each PWM line to its steady level before the release, high for duty > 0 and low for duty 0, as the iMate and StellaVita PowerBoxes already did.
- **Gemini PDH Advanced 3: the reader no longer spins a core after an unplug** (AlpacaCore, issue #772): a hung-up tty returns 0 from `read()` at once, and the frame reader backed off only on an error, so after an unplug it used a full core until disconnect. It now waits 50 ms after a read that returns no byte. `Connected` stays true and the unanswered status polls still latch the link fault (issue #237).
- **Bisque/TheSkyX: a late reply no longer shifts every later reply by one** (AlpacaCore, issue #772): after a read timed out, the reply that arrived later stayed in the socket and was read as the next command's reply, and every later reply stayed one behind. The wrapper now discards bytes already waiting in the socket before it sends each command.

### Added (tests)
- **Regression cases for the three fixes** (issue #772): an ASIAIR Pro case over a libgpiod stub in the test file (a 50 % PWM port must be high at release across 20 closes), a Gemini PDH case over `FakeGeminiPdh::sever_link()` (process CPU stays under 0.5 s in the 2 s after the cut), and a Bisque case over `FakeMountServer` (a reply delayed past the timeout is not returned to the next two queries). The pty fakes' comments and AGENTS.md now say that a read on a severed pty returns 0; only writes fail with EIO.
