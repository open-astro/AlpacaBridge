### Fixed
- **Parallel `imagearray` GETs share one copy of the encoded frame** (AlpacaHTTP, Camera, issue #1716): GETs that join one image build no longer each hold their own copy of the encoded body. Each response carries its own small head (the 44-byte ImageBytes header or the JSON envelope head, with its ClientTransactionID and ServerTransactionID) and points at the one shared body, which the server sends without joining the two. Before, six parallel JSON downloads of a 6000x4000 colour frame held six copies of a body of several hundred MB, which could get a 4 GB Pi out-of-memory killed. Decision 0007 finding NS-12 is now fixed.
