### Fixed
- **Remote Alpaca ObservingConditions: a reconnect keeps its first frame when an AveragePeriod write races it** (Remote Alpaca driver, issue #2446): an AveragePeriod write whose caller passed its NotConnected check before a Disconnect could start its body behind the next Connect's join and write through while that Connect sampled its first frame. The write moved the snapshot's write epoch, so the Connect dropped its frame and still reported Connected, and every getter answered "has not answered since the Connect" until the next poll (decision 0010 rule 8). A body now writes nothing while the driver is disconnected; the upstream still gets the PUT and the next poll reads the value back. New test seam `set_caller_hook_for_testing()`.
- **Gemini PDH: a write to a pulled adapter is NotConnected** (Gemini PDH switch driver, issue #2451): a loss the reader thread latched between a member's NotConnected check and its link-fault check surfaced as DriverException "communications compromised" about one run in ten. The link-fault check now answers NotConnected for a lost link first (decision 0009).

### Added (tests)
- **Remote Alpaca reconnect race** (issue #2446): "Remote Alpaca ObservingConditions Driver - a write racing a reconnect keeps the Connect's frame" holds an AveragePeriod caller past its check while a Disconnect and a Connect run, and releases its write while the Connect samples.
