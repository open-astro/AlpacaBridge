### Fixed

- **Open NAT-sharing hotspot from an empty passphrase**, WiFi manager, issue #1715. `PUT /management/v1/wifi/ap` with an empty `Passphrase` is now refused (message names `Passphrase`) unless the hotspot profile already has a security section, so the API can no longer create or re-activate an open hotspot; an empty passphrase still keeps the stored secret on a secured profile. The `wifi.share.open` polkit grant is dropped. An empty passphrase with `Enabled: false` still turns an open hotspot from an earlier release off; NetworkManager still starts such a hotspot at boot until it is turned off or given a passphrase. Covered by `AlpacaHTTP/tests/test_wifi_manager.cpp` ("set_ap refuses an empty passphrase unless a secured hotspot profile exists", "set_ap lets an empty passphrase turn off an open hotspot profile").
