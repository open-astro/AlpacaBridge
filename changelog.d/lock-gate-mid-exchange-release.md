### Changed (docs)
- **Driver lifecycle rules cover the state lock released inside a wire call and a full lock table** (docs, issues #1729 and #1730): `driver-lifecycle.instructions.md` now says that in a converted driver a `*_locked` helper that reaches the wire can release `mutex_` partway through, so state read before the exchange is re-read after it or checked against a counter, and that a full per-thread lock table throws `DriverException` before taking any lock. Decision 0016 gains item 8 and Rule 6 for both. Two drivers do not follow the second rule yet: Sky-Watcher (#1730) and OnStep's single-read path (#1729); no code changes.
- **Decision 0016 states the leaf-lock rule once; decision 0009 tidied after the ZWO AM identity change** (docs, #1772 follow-up): 0016 item 5 and Rule 2 now say any helper mutex may nest under `mutex_` only as a leaf (no other lock, no I/O, no joins) instead of naming the ZWO identity registry; the driver lifecycle instructions list the shared leaves and the ZWO instructions name ZWO's own. 0009 drops its stale "five drivers, this slice" wording, cuts the ZWO AM identity row to one line marked done, moves the ZWO replacement how-to back to the ZWO instructions and fixes Rule 4's check to "re-runs the connect probe". The ZWO instructions and changelog now say that saving the device again in the web UI also admits a replaced mount, not only a service restart.
