### Fixed

- **The Celestron NexStar mount, the Celestron CGX mount and the Celestron focus motor drop `Connected` on `EBADF` too** (issue #2262 PR 9, decision 0009 point 2a). Their serial links now judge a failed read or write with the shared `util::SerialLink` verdict, so `EBADF` on the port's fd is a lost link at once, as `EIO`, `ENXIO` and `ENODEV` already were (`Connected` false, operations `NotConnected`, the port released, the loss reason in `get_link_fault()` until the next Connect or Disconnect: "Celestron serial link lost (write): Bad file descriptor" on the NexStar mount, "Celestron CGX mount serial link lost (write: Bad file descriptor)" or "Celestron focuser serial link lost (write: Bad file descriptor)" on the AUX link). Before, the NexStar write failed with `DriverException` and the AUX link closed the port with `DriverException`, both with `Connected` still true. An `EBADF` logs one ERROR line naming the port, since it means a driver bug. Over TCP nothing changes.
