### Fixed (docs)
- **5.0.0-beta.1 release notes: the ZWO unique ID change and `CanSlew` described correctly** (docs, issue #914): 4.2.0 read a ZWO camera's serial only on connect and cleared it on disconnect, so a disconnected camera reported `ZWO_<device number>` and a connected one `ZWO_SN_<serial>`; 5.0 reports the serial-number ID in both states. The notes now say that, instead of saying every camera gets a new ID, and no longer name the ASI120MM Mini as a camera with no serial (the rig's unit returns one, `2004480016020900`; #914's `ZWO_0` was that camera while disconnected). The same correction is made in the #914 changelog fragment and in `SUPPORTED-DRIVERS.md`. The sync-slew item now says mounts report `CanSlew` and `CanSlewAltAz` false.
- **Changelog: refused GPIO switch entries are listed as "(failed to load)"** (docs, issues #765 and #818): the breaking-changes entry said a saved ASIAIR, iMate or StellaVita entry with non-board GPIO values goes missing from the device list. On 5.0.0-beta.1 it is listed as "(failed to load)", which is what the release notes already said (checked on the rig with all four board types, 2026-10-11).

### Changed (validation)
- **ZWO ASI533MC Pro, ASI120MM Mini and EAF re-validated on 5.0.0-beta.1** (AlpacaCore): ConformU 4.5.1 (build 54507), Raspberry Pi 5, Debian 13 arm64, the released `alpacabridge_5.0.0-beta.1_arm64.deb`: 0 errors, 0 issues, 0 warnings and no timing marks on all three. The EAF report replaces one made with ConformU 4.2.1.
