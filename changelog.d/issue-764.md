### Fixed

- **A non-UTF-8 string no longer makes a JSON response fail** (AlpacaHTTP, issue #764; `response.cpp`): `Response::set_body(const AlpacaResponse&)` serialised with the strict UTF-8 handler, so one string holding invalid UTF-8 (reproduced with a nearby Wi-Fi SSID from NetworkManager, in `GET /management/v1/wifi/scan`) made `json.dump()` throw `type_error.316` and the whole response returned an error with no networks. The same shared sink serves the other Wi-Fi routes and every other Device and Management API response, so they are covered too, though only the scan was reproduced. The sink now uses `error_handler_t::replace`: invalid bytes are shown as U+FFFD and every valid value is returned. Trade-off: such an SSID displays with the replacement character and cannot be joined by that displayed name. Covered by `test_response_utf8.cpp`.
