### Changed (tooling)
- **Merge-queue support for `main`** (CI, `.github/workflows/ci.yml`, `.github/workflows/claude-review.yml`, `/pr-checker`, `/submit-pr`): CI now also runs on `merge_group`, so `main` can land PRs through GitHub's merge queue instead of requiring every open PR to be brought up to date (and re-run CI and the review) after each merge. `sanitizers-tsan` and `package-deb` skip a PR into `main` and run in the queue on the merged commit, a push and a dispatch; a PR into `stable/**`, which has no queue, still runs them. Only pull-request CI runs cancel each other, so a run the queue waits on is never cancelled. The review bot no longer waits for the TSan job. `/pr-checker` and `/submit-pr` detect whether `main` requires the queue: with it on they stop running `update-branch` because `main` moved, add a clean PR to the queue, and wait for it to merge or leave the queue; with it off they behave as before. The queue itself is switched on in the repository ruleset after this merges.
