### Added

- **OnStep: Focuser devices on the controller's shared link** (OnStep driver, web UI, issue #2223): an OnStepX controller's focusers (1 to 6) can be added as **OnStep** Focuser devices, with the telescope's connection fields (Auto-Detect with the mount index, Serial, Network) and a focuser number. The telescope and every focuser on one controller share one serial port or TCP connection, whichever connects first; each connects and disconnects on its own, and a lost link reaches every device on it (decision 0009). Connect refuses OnStep 4.x ("requires OnStepX firmware") and a focuser the firmware does not have ("OnStepX reports no focuser N"). `Position` and `MaxStep` count raw steps from the focuser's minimum (`:F<n>g#`, `:F<n>i#`, `:F<n>m#`), `Move` goes to an absolute position (clamped to 0..`MaxStep`, #2028) and reports a refusal with its `:GE#` reason, `Halt` stops at once, `IsMoving` follows the polled `:F<n>T#`, `StepSize` is `:F<n>u#`, `Temperature` is the focuser's probe (not implemented without one), and temperature compensation (`:F<n>c#`, `:F<n>c0#`/`:F<n>c1#`) is offered when the probe is there. Only the addressed `:F<n>...#` commands are sent, so the controller's active focuser, which the handset and the OnStepX web page use, never changes. Fake-tested only; the ConformU Focuser check on an OnStepX rig is tracked in #2126.

### Changed

- **OnStep: one link per controller instead of one per process** (OnStep driver, issue #2223): the protocol wrapper is no longer a process-wide singleton; devices take the controller's link through `OnStepProtocolWrapper::acquire()`, keyed by serial port or host and port, under the serial owner name `OnStep` (was `OnStep mount`). A command whose error code is read next with `:GE#` holds the link across both, so a sibling device's command can no longer replace the code. Two telescopes on two different OnStep controllers are no longer refused. The telescope's link-loss handling, its #521 relink stops and its timing are unchanged.

### Added (tests)

- **OnStep focuser and shared-link cases** (issue #2223): `AlpacaCore/tests/test_onstep_focuser.cpp` (the driver cases, the connect refusals, addressed commands only, both connect orders, one device disconnecting while the other polls, a link loss reaching both, `:GE#` never split by a focuser poll, a telescope pulse guide inside its settle and measure bounds with focuser exchanges queued), the focuser `[stress]` cases in `test_onstep_concurrency_stress.cpp` (both over the scripted controller in `onstep_controller.h`), the `onstep_focuser` contract sweep entry (tiers 1 to 3 and the snapshot cases), the catalog built-ins case and the AlpacaHTTP config round-trip. The wrapper-level OnStep tests drive a standalone link instead of the old singleton.
