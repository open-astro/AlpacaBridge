### Fixed
- **iOptron HAE29C FindHome at a false zero** (AlpacaCore): after a power loss the HAE29C reads status 7 (home) wherever it points. If it ignored the `:MSH#` zero search there, FindHome ended on that 7 and AtHome read true though the mount never moved. A zero search now lands on a 7 only once a status 2 showed it moving, as every traced search did (from the true zero too). Until it sees one, the zero search watchdog reads the status every second, so a short search is seen with no client polling. A 7 with no motion past the 5 s start grace gets one more `:MSH#`, and then a "did not start" error that Slewing raises. After a search that did not land, AtHome stays false while the mount reads 7, until a new FindHome or the mount moves.
