### Changed

- **The gphoto camera driver links a bundled libgphoto2 2.5.34** (gphoto driver, packaging, issue #933): the upstream tarball is vendored in `AlpacaCore/external/libgphoto2/` and built by `scripts/build_bundled_gphoto.sh` into `/usr/lib/alpacabridge/libgphoto2`, with the default camlib set and full RELRO (`-z now`, as Debian's own build has); only the libraries, camlibs, iolibs and the `print-camera-list` tool ship. The server finds it through a `DT_RPATH`, the directory is not registered with ldconfig, and the host's own libgphoto2 packages are untouched; the `.deb` no longer depends on `libgphoto2-6t64` or `libgphoto2-port12t64`. `scripts/check_bundled_gphoto.sh` checks this on an installed package, and the new `package-deb` CI job builds and installs the `.deb` and runs it. The camera udev rules (`61-alpacabridge-libgphoto2.rules`, group `plugdev`, mode 0660) are now generated from the bundled build. The release SBOM skips the built bundle. See [decision 0012](docs/decisions/0012-bundled-libgphoto2.md).
- **Canon bulb exposures use the libgphoto2 2.5.34 `eosremoterelease` names** (gphoto camera driver, issues #640 and #933): 2.5.34 renamed the choices, so the driver now holds the shutter with `Press Full MF` and closes it with `Release`, the same PTP calls 2.5.31's `Press Full` and `Release Full` made; 2.5.34's own `Release Full` releases only the full press and is not used with it. Without this, the bundled library left Canon bodies without bulb (`ExposureMax` 30 s instead of 3600 s on the EOS 70D and 250D).
- **libgphoto2 updates are tracked as a vendored SDK** (dependency checks, issue #1137): the `libgphoto2` row is gone from `system_libraries` in `scripts/dependency_sdk_versions.json`; its `AlpacaCore/external/libgphoto2` entry (2.5.34) is checked against the upstream tags page, so the open update tracking for it (issue #933) is handled by this change.
- **Upstream libgphoto2 changes from 2.5.31 to 2.5.34** (gphoto camera driver, issue #933): the bundled library brings these changes from the upstream `NEWS` file in `AlpacaCore/external/libgphoto2/libgphoto2-2.5.34.tar.xz`; the CVE fixes are listed under Security.
  - 2.5.34, ptp2: new Canon EOS SDRAM capture method; new Nikon Z series property code list method; better Sony generation 2 versus 3 handling; CHDK liveview bugfixes; Leica bodies not yet listed are detected better in generic mode.
  - 2.5.34, ptp2 config: Nikon `flashready` and `infodisperrstatus` added; Sony exposure program mode 3, `focusdistancemeters`, shutter lag timing, focus indication, shutter type, D-Range Optimizer and silent mode added; Canon EOS `remoterelease` values changed; Panasonic bulb added.
  - 2.5.34, new camera IDs: Sony ILCE-1M2; Nikon CoolPix P1100, S3500, Z50_2; Canon EOS R1, R6 Mark III; Fuji FinePix S4200, X-E5; Leica SL3.
  - 2.5.34, other: jd11 can export TIFF and DNG (needs libtiff); assorted bugfixes, and many `strcpy` calls replaced with `strncpy`; "gregorian" (as written upstream) and Spanish translations updated, Arabic added.
  - 2.5.33, ptp2: fixed a capture crash (regression); new IDs Sony ZV-E10M2, Fuji X-M5, Ricoh GR IIIx (corrected ID); libmtp IDs imported.
  - 2.5.33, other: the serial port driver caches, and the canon driver uses that cache; Romanian, Chinese, Polish and Ukrainian translations updated.
  - 2.5.32, ptp2: code and Canon EOS debug output cleanups; condensed `--summary` output; Canon EOS image format output changed; Canon `disablemodedial` added and `keepdeviceon` sent less often; Sony changes imported from Sony's now official documentation, newer Sony property format supported, `capturemode`, `focalposition`, `magnifysetting` and `spotfocusarea` added, crash in the movie option fixed; Panasonic and Fuji bugfixes; Fuji AF drive manual, `availableshots`, `graineffect` and `rawcompression` configs added; Nikon 32-bit properties supported.
  - 2.5.32, new camera IDs: Canon EOS R100, R3, R8, R50, PowerShot G7 X Mark III; Sony A6100, ZV-E10, A6700, NEX-5N, SLT-A99V, ILCE-9M3, ILX-LR1; Nikon Zf, Z6 III; Olympus OM-1 Mark II; Fuji X-H2S, X100V1 (as written upstream, likely the X100VI), GFX100 II; Ricoh GR III; Leica Q3, M11 Monochrom.
  - 2.5.32, camlibs: new Apple QuickTake (serial) driver `quicktake1x0`; Pentax K-1 II and K-3 III added, with pktriggercord fixes synced.
  - 2.5.32, ports and library: more Android USB support (passing in a file descriptor, new `gp_port_usb_set_sys_device` and `gp_port_usb_get_sys_device`); serial port fixes for QuickTake; `IOLIBS` and `CAMLIBS` configurable at runtime; silent build rules by default; Meson build support next to automake; `print-camera-list` can print JSON; new `gp_setting_set_get_func` and `gp_setting_set_set_func` for user-defined settings; Georgian, Friulian, Polish, Romanian, Ukrainian, Chinese and Brazilian Portuguese translations added.

### Security

- **libgphoto2 2.5.34 fixes CVE-2026-40333, CVE-2026-40334, CVE-2026-40335, CVE-2026-40336, CVE-2026-40338, CVE-2026-40339, CVE-2026-40340 and CVE-2026-40341** (gphoto camera driver, issue #933): Debian trixie ships 2.5.31, which does not have these fixes; the driver now uses the bundled 2.5.34 library.
  - CVE-2026-40333: information disclosure and denial of service through unbounded reads when unpacking Canon EOS events.
  - CVE-2026-40334: information disclosure and denial of service through a missing null terminator in `ptp_unpack_Canon_FE`.
  - CVE-2026-40335: information disclosure through an out-of-bounds read in `ptp_unpack_DPV`.
  - CVE-2026-40336: a memory leak in `ptp_unpack_Sony_DPD()` can lead to denial of service.
  - CVE-2026-40338: information disclosure and denial of service through an out-of-bounds read in the `PTP_DPFF_Enumeration` case of `ptp_unpack_Sony_DPD()`.
  - CVE-2026-40339: information disclosure through an out-of-bounds read in `ptp_unpack_Sony_DPD()`.
  - CVE-2026-40340: information disclosure and denial of service through an out-of-bounds read in `ptp_unpack_OI()`.
  - CVE-2026-40341: denial of service through an out-of-bounds read from untrusted USB devices in `ptp_unpack_EOS_FocusInfoEx`.
