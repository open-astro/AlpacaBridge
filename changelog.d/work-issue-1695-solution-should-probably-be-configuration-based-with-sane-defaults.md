### Changed

- **Log files now rotate at 5 MiB by default, and file logging never stops** (AlpacaHTTP, issue #1695): `logging.max_file_size_mb` (env `ALPACAHTTP_LOG_MAX_FILE_SIZE_MB`, `0` = no cap; a negative or unparsable value keeps the yaml/default value) caps one log file. At the cap the day's file becomes `alpacabridge-YYYY-MM-DD.1.log`, older parts shift up to `.19`, the oldest is deleted, and logging continues in a fresh file, so a day keeps up to 100 MiB of the newest lines at the default and TRACE left on or a driver error loop can no longer fill the SD card. Each part fits the web viewer's inline view. The parts appear in the log viewer and the archive, newest first, and retention prunes them by date. Covered by `test_log_size_cap.cpp`.
