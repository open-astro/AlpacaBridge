### Fixed

- **SynScan and Sky-Watcher refuse an out-of-range guide rate with `InvalidValue` while disconnected**, AlpacaCore SynScan and Sky-Watcher drivers, issue #1786. A `GuideRateRightAscension` or `GuideRateDeclination` write above 1x sidereal or below zero returned `NotConnected` on a disconnected mount because the 0 to 1x sidereal check ran after the connection check; each driver now runs its own check first, and an in-range write on a disconnected mount still returns `NotConnected` and keeps the stored rate. Writing one axis keeps the other, and a refused write keeps both (cases in `test_synscan_telescope.cpp` and `test_skywatcher_telescope.cpp`). On a SynScan mount whose link was lost, the same writes returned `DriverException` from the kept link fault; they now give `InvalidValue` for an out-of-range value and `NotConnected` otherwise, and `GuideRate`, `SiderealTime`, `SiteLatitude`, `SiteLongitude` and `TrackingRate` reads give `NotConnected` (cases in `test_synscan_telescope_snapshot.cpp`). Sky-Watcher now writes one axis under a single lock, so two concurrent single-axis guide-rate writes no longer overwrite each other (case `concurrent individual guide-rate writes both land`). While `Connected` stays true on a young communication fault, guide-rate writes (pair, RA, Dec) on both drivers now raise `DriverException` and store nothing, an out-of-range value stays `InvalidValue`, and the Sky-Watcher `GuideRate` read refuses the same way (`DriverException` on a fault, `NotConnected` once the link is lost; `test_skywatcher_serial.cpp` and `test_skywatcher_snapshot.cpp`), a good poll restores writes (cases `a faulted link refuses guide-rate writes ...` in `test_synscan_telescope_snapshot.cpp` and `test_skywatcher_snapshot.cpp`). The `GuideRate` read on both drivers is `NotConnected` before the first connect and after a disconnect (`... guide-rate range errors precede NotConnected` in both unit files; `an explicit disconnect refuses the guide rate and the targets` in both snapshot files). `TargetRightAscension` and `TargetDeclination` reads and writes on both drivers now follow the same rules: an out-of-range write is `InvalidValue` first, then `NotConnected` while disconnected or lost, then `DriverException` on a young fault; a refused write keeps the stored value and its set flag, and the two targets stay independent (cases `a faulted or lost link refuses the targets and the guide rate like the other reads` in `test_synscan_telescope_snapshot.cpp` and `test_skywatcher_snapshot.cpp`). Refs #1786; remaining: Celestron CGX individual guide-rate setters.
