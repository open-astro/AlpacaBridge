### Fixed

- **SynScan and Sky-Watcher refuse an out-of-range guide rate with `InvalidValue` while disconnected**, AlpacaCore SynScan and Sky-Watcher drivers, issue #1786. A `GuideRateRightAscension` or `GuideRateDeclination` write above 1x sidereal or below zero returned `NotConnected` on a disconnected mount because the 0 to 1x sidereal check ran after the connection check; each driver now runs its own check first, and an in-range write on a disconnected mount still returns `NotConnected` and keeps the stored rate. Writing one axis keeps the other, and a refused write keeps both (cases in `test_synscan_telescope.cpp` and `test_skywatcher_telescope.cpp`). On a SynScan mount whose link was lost, the same writes returned `DriverException` from the kept link fault; they now give `InvalidValue` for an out-of-range value and `NotConnected` otherwise, and `GuideRate`, `SiderealTime`, `SiteLatitude`, `SiteLongitude` and `TrackingRate` reads give `NotConnected` (cases in `test_synscan_telescope_snapshot.cpp`). Sky-Watcher now writes one axis under a single lock, so two concurrent single-axis guide-rate writes no longer overwrite each other (case `concurrent individual guide-rate writes both land`). While `Connected` stays true on a young communication fault, guide-rate writes (pair, RA, Dec) on both drivers now raise `DriverException` and store nothing, an out-of-range value stays `InvalidValue`, and a good poll restores writes (cases `a faulted link refuses guide-rate writes ...` in `test_synscan_telescope_snapshot.cpp` and `test_skywatcher_snapshot.cpp`). Refs #1786; remaining: Celestron CGX individual guide-rate setters.
