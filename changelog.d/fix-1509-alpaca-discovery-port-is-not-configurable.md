### Fixed

- **Alpaca discovery port is configurable**, AlpacaHTTP, issue #1509. The discovery responder bound a hard-coded UDP 32227; the Alpaca API Reference (section 5.8.1) requires the port to default to 32227 and be configurable by the user. `discovery.port` in the config file (1-65535, default 32227) and `ALPACAHTTP_DISCOVERY_PORT` now set it, and the web UI server settings gain a "Discovery port" field saved through `PUT /management/v1/description` (`DiscoveryPort`, a 400 for a value outside 1-65535); the responder binds the new port when the service restarts, still sharing it with other Alpaca processes. An invalid file or environment value logs a warning and keeps the earlier value (the file value, else the default). Covered by `AlpacaHTTP/tests/test_config.cpp`, `AlpacaHTTP/tests/test_discovery.cpp`, `AlpacaHTTP/tests/test_routing.cpp` and `AlpacaHTTP/tests/web/hostcheck.test.js`; [decision 0007](docs/decisions/0007-lan-surface-threat-model.md) surface 5 now reads "default 32227, configurable".
