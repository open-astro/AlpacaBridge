### Added
- **ToupTek and Altair cameras show their firmware and SDK version in the web UI** (AlpacaCore, issue #1997): the device card's Firmware row now shows the camera firmware with its hardware version, FPGA version and production date, read at connect (for example `4.1.2.20221031 (hardware 4.0, FPGA 4.34, production date 2026-03-10)`; a value the model does not report is left out), and the SDK Version row shows the libtoupcam or libaltaircam version. Both come from values cached by the driver, so a `configureddevices` poll makes no SDK call, and neither is added to the ASCOM `DriverInfo` string.

### Added (tests)
- **ToupTek StartExposure-during-disconnect regression** (AlpacaCore, issue #1995): a test hook in the ToupTek camera driver now runs in the window between the disconnect's stream stop and the capture session's close, on both the disconnect and the destructor paths, so `ToupTek Camera Driver - a StartExposure during a disconnect is refused and the disconnect returns promptly` and the new `ToupTek Camera Driver - a StartExposure during the destructor's disconnect is refused` fail when the driver's `closing_` guard is removed; before, the first case passed without it.
- **ToupTek and Altair firmware cases** (AlpacaCore, issue #1997): `ToupTek Camera Driver - firmware and SDK version are served from the connect-time cache`, `ToupTek Camera Driver - a version the camera does not report is left out of the firmware string`, `Altair Camera Driver - firmware and SDK version come from the Altair SDK at connect`, and `ToupcamFamilySDK - version reads return the SDK text and an empty string on a refusal`.
