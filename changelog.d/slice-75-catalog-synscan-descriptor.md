### Changed
- **SynScan telescope moved into the device catalog** (AlpacaCore, AlpacaHTTP): the schema (`synscan_schema.cpp`, every build) and factory (`synscan_catalog.cpp`, only under `ALPACACORE_ENABLE_SYNSCAN`) replace the router's register arm, its sanitize branch and its driver include. The vendors-OFF text stays "SynScan support not enabled. Rebuild with -DALPACACORE_ENABLE_SYNSCAN=ON", the API still refuses an unknown connection type with "Invalid connection type. Use 'auto', 'serial', or 'network'", an empty serial port with "Serial port path is required" and an empty host with "Host IP address is required", and a saved unknown connection type is still read as `serial` (test `Builtin catalog - SynScan normalize accepts '', auto, serial and network, refuses others from the API`). An unknown or non-string `alignmentMode` is still dropped and reads as `auto` (#860; test `Builtin catalog - SynScan alignmentMode keeps a known value and drops an unknown one (#860)`). `synscanVersion` is still read as `auto`, `v3`/`3` or `v4`/`4` in any case (test `Builtin catalog - SynScan synscanVersion defaults to auto and the factory builds for every spelling`). The auto-detect factory still constructs without a scan (the scan runs at connect, #659). `GET /management/v1/devicecatalog` now lists the `synscan` telescope descriptor. A saved config keeps its `portPath`/`baudRate` and `host`/`tcpPort` whatever its connection type, a saved config with an empty endpoint logs the catalog's "config normalized: ..." warning instead of "will refuse to connect: ...", and an out-of-range `siteLatitude` or `siteLongitude` sent through the API is now refused with the catalog's "siteLongitude is out of range (min -180) (max 180)" text (test `Builtin catalog - SynScan site range is per-field`). `scripts/check_layering.py`'s AlpacaHTTP vendor-include baseline drops from 30 to 29. A fractional or boolean baudRate, tcpPort, mountIndex or responseTimeoutMs (such as 9600.5 or true) is now refused as the wrong type instead of being truncated.
