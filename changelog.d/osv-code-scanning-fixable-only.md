### Changed (tooling)
- **Code scanning shows only OSV findings there is something to do about** (`scripts/dependency_updates.py --filter-sarif`, `.github/workflows/osv-scan.yml`): a finding in the `.deb`'s own runtime dependencies now reaches Security > Code scanning only when Debian trixie has a fixed version for it, or when it is Critical (CVSS 9.0 or more) with no fix, because a Critical finding may call for dropping or replacing the dependency rather than waiting. On the 2026-10-16 scan this leaves 7 findings (six curl advisories already dismissed with a reason, and libxml2 DEBIAN-CVE-2026-6653). An unfixed lower-severity finding is no longer uploaded, so code scanning closes its alert as fixed; it reappears under the same fingerprint the day Debian ships a fix, and every finding stays in the run's `osv-full-results` artifact. The summary-issue rule is unchanged.
