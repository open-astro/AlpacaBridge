### Changed

- **The Sky-Watcher motor controller judges a lost serial link with the shared `util::SerialLink` verdict** (issue #2262 PR 10, decision 0009 point 2a). Its own `poll()`-bounded serial reads and writes stay (they are the path through its test seams, decision 0017 rule 5), but each failed write, poll or read now feeds its errno to the link, and the wrapper's own errno list is gone: `EIO`, `ENXIO`, `ENODEV` and `EBADF` on the port's fd stay a lost link at once (`Connected` false, operations `NotConnected`, the port released, the loss stamped once, only the client's Connect relinks), and a removed device node still is one too. The driver already counted `EBADF`; an `EBADF` now also logs one ERROR line naming the port, since it means a driver bug. Over Wi-Fi (UDP) nothing changes, and every other link-loss behaviour is unchanged.
