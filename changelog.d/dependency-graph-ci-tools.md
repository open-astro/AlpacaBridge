### Changed (tooling)
- **Dependency graph lists the CI tools** (scripts, issue #1115): `scripts/dependency_snapshot.py` now also submits cppcheck and zizmor (`pkg:github`, at the `ver=` pin in their `ci.yml` install steps) and the tools CI installs from the runner's Ubuntu 24.04 apt, unversioned (Catch2, clang-format, clang-tidy, gcovr, nodejs, shellcheck) as development dependencies, and the ConformU 4.5.1 beta build `/conformu` pins for rig validation (`pkg:github/ASCOMInitiative/ConformU@4.5.1-beta`, read from `.claude/commands/conformu.md`), and every workflow job's `container:` image (`pkg:docker/debian@trixie`, the image the beta and nightly `.deb` are built in); `--check` fails if a `ver=` pin, an apt tool's install line or the ConformU build line can no longer be found. A container image on another registry keeps the registry in the purl's `repository_url` qualifier, and ConformU carries `-beta` only while `/conformu` installs from the ASCOM beta download.

### Added (tooling)
- **Weekly dependency update issues** (`.github/workflows/dependency-updates.yml`, `scripts/dependency_updates.py`): the GitHub-hosted pins in the dependency snapshot (cppcheck, zizmor, OSV-Scanner, nlohmann/json, ConformU) and libgpiod (new `updates` block in `scripts/dependency_sdk_versions.json`) are checked every Monday; each newer version opens one issue (`dependencies`, `enhancement`, `P4`) that is retitled on a further release and closes itself once the repository is at that version, and an unreadable source opens its own `bug` issue. Issue state lives in the issue body; the workflow never commits. Vendor SDK sources come later, one vendor at a time.
- **OSV vulnerability scan of the nightly .deb's runtime packages** (`.github/workflows/osv-scan.yml`): the `.deb`'s `Depends` are installed into `debian:trixie` and scanned daily with OSV-Scanner 2.7.0 (checksum-pinned); findings go to Security > Code scanning, and new High/Critical ones (CVSS >= 7.0) open one summary issue (`dependencies`, `bug`, `P2`).
