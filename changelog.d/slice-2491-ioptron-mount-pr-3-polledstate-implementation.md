### Changed

- **iOptron telescope served from a state poll**, iOptron driver, issue #2491. One poll (`util::PolledState`, 250 ms, [decision 0010](docs/decisions/0010-snapshot-served-state.md)) reads the status, the position and the Alt/Az and publishes one frame; RightAscension, Declination, Altitude, Azimuth, SideOfPier, Tracking, TrackingRate, Slewing, AtHome, AtPark and DeviceState read it and send nothing to the mount (`AlpacaCore/tests/test_ioptron_polled_state.cpp`). Three failed polls in a row fault the link and a fault standing 30 s loses it, found by the poll with no client call; the old getter-side `:GLS#` probe is gone. A failed `:GAC#` alone is not a failed poll (Altitude and Azimuth throw "Alt/Az is not available" and nothing else changes), and one that timed out is retried every 4th tick. The GOTO trim, the landing gate and the zero search's start check run in the poll; a failed one keeps its error for Slewing and does not fail the poll. A connect whose first reads fail still connects, and the getters throw `DriverException` until a poll answers. SideOfPier with no site cached serves the mount's own pier digit and sends nothing.
- **iOptron Tracking and TrackingRate hold a client's write for 2 s**, iOptron driver, issue #2491. After `set_tracking(true)` (or `set_tracking_rate`), Tracking and TrackingRate read the written value for the whole 2 s read-back window, where before a status read inside it could make Tracking read the mount's old value (case "a status read inside the Tracking read-back window does not undo the written value").
