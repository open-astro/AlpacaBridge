### Changed (tests)
- **SynScan and iOptron have a test seam for a send that fails on a live TCP link** (issue #2753): `set_send_fault_for_testing()` on each wrapper makes one command's send fail with a chosen errno (such as `EHOSTUNREACH`) with nothing written and the socket left up, so the non-hangup failure path runs as it does in production after #2718. Production behaviour is unchanged: with no hook set, the write path takes one empty-function check. Fifteen cases built on it restore the assertions #2718 had to rename: the SynScan #2412 bound after a failed start or stop (`SynScan MoveAxis - a start that threw is still bounded`, `- a stop that threw leaves the axis bounded`), the #1836 pulse window (`SynScan hold window - a failed pulse rate command leaves IsPulseGuiding false`), the #2263 older pulse kept after a failed replacement or MoveAxis, the stored slew error kept after a failed MoveAxis, the failed deadline, Unpark, Park and AbortSlew stops, and the iOptron AbortSlew, synchronous slew, Park and PulseGuide dispatch failures.
