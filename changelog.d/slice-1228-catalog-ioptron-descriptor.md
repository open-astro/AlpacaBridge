### Changed
- **iOptron telescope, iMate PowerBox switch, iEAF focuser, iEFW filter wheel and iCAM camera moved into the device catalog** (AlpacaCore, AlpacaHTTP, issue #1228): `ioptron_schema.cpp` (every build) and `ioptron_catalog.cpp` (only under `ALPACACORE_ENABLE_IOPTRON`) replace the router's five register arms, its sanitize chain, the five driver includes (four iOptron, one Player One) and the `read_site_coordinates()`, `reject_invalid_config()` and `normalize_persisted_connection_type()` helpers, so `router.cpp` holds no vendor include and `scripts/check_layering.py`'s AlpacaHTTP baseline drops from 5 to 0. The iCAM factory stays under `ALPACACORE_ENABLE_PLAYERONE` (it builds the Player One driver), so a build without Player One still tells the operator to rebuild with -DALPACACORE_ENABLE_PLAYERONE=ON (tests `Builtin catalog - register_builtin_schemas describes the iOptron devices in every build`, `Builtin catalog - register_builtin_factories makes the iOptron devices available only when built`). The auto-detect factories (`create_ioptron_telescope_auto`, `_auto_network`, `create_ieaf_focuser_by_index`, `create_iefw_filterwheel_by_index`) still scan at connect, not at registration (the `test_ioptron_*_deferred_connect.cpp` cases are unchanged). The telescope keeps its refusals and texts: an out-of-range `siteLatitude`/`siteLongitude`, an unknown `connectionType` and a serial mount with no `portPath` are rejected from the API and warned about (the first dropped) for a saved config, and a network mount with an empty `host` still sweeps the subnet (test `Builtin catalog - iOptron telescope normalize keeps the arm's refusals and texts`). The filter wheel still refuses a serial wheel with no `portPath` and a negative `filterwheelIndex`, and the PowerBox still refuses a `gpioChip` other than `/dev/gpiochip1` or `/dev/gpiochip0` with the same text (test `Builtin catalog - iOptron filter wheel and PowerBox normalize refuse what the arms refused`). `GET /management/v1/devicecatalog` now lists the five `ioptron` descriptors, and a saved iOptron entry keeps every field its device type declares whatever the connection type (a serial mount keeps `host`, a network mount keeps `portPath`; test `Builtin catalog - iOptron sanitize keeps the declared fields per device type`). Changed texts: a `filterNames` that is not an array of strings is now refused with "Device config field 'filterNames' has the wrong type", not "iOptron filter wheel filterNames must be an array (of strings)"; the registration log lines now read "Registered iOptron switch", "... focuser", "... filterwheel" and "... camera"; the iCAM not-built text now starts "iOptron support not enabled."; a `ports` that is not an array is now refused (it was ignored); a saved iOptron config's warnings are wrapped as "config normalized: ...". `scripts/check_contract_sweep.py` no longer reports a router function with no arm as a broken parser.
