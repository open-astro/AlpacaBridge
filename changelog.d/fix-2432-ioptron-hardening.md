### Fixed
- **iOptron HAE29C: the 120 s FindHome bound no longer waits for a client to poll** (AlpacaCore, issue #2432): the `:MSH#` zero search was stopped at 120 s only when a client read the status, so a client that sent FindHome and never polled left the mount searching. The bound now runs on its own operation slot: at 120 s it reads the status, lands a search that reports the zero, and otherwise sends `:Q#` and keeps the failure for Slewing, whether or not a client polls. If that slot cannot start, FindHome stops the search and throws `DriverException`. The search deadline is now set only for a zero search, not for a `:MH#` FindHome.
- **iOptron: a host clock re-sync no longer writes the mount clock under a motion that starts after its check** (AlpacaCore, issue #2432): the re-sync waited for driver motion to end and then wrote `:SG`, `:SDS`, `:SUT` and the site, so a GoTo, Park, FindHome or MoveAxis that started just after the wait still got those writes. Each re-sync write now checks for driver motion again inside its own exchange, under the lock that every motion command takes, and waits for the motion to end before it writes. A re-sync that runs as the connect's pass (after a connect pass that failed, or one it superseded) waited for no motion at all and wrote at once; it now waits and checks like any other re-sync.

### Changed
- **Docs: the host clock hook wording, and the iOptron clock-sync and zero search notes** (issue #2432): the ascom-contract bullet no longer says `on_host_clock_changed()` never blocks, because `AsyncOperation::start()` can wait up to 2 s; the iOptron notes describe the zero search watchdog, the re-sync's write check, why a failed connect pass makes later re-syncs act as connect passes (they still wait for motion), and the ConformU re-run the HAE29C needs before a release.

### Added (tests)
- **iOptron zero search and clock re-sync cases** (issue #2432): a search that no client polls is stopped at its bound; a FindHome during an overdue search stops it and starts a new one; a FindHome whose bound cannot start stops the search and throws; a status read past the bound stops the search while the watchdog is held; a MoveAxis that starts after the re-sync's motion wait gets no clock write; a host clock change during a held `set_connected()` re-syncs as that call returns; a re-sync after a failed connect pass waits for a MoveAxis to end. Two existing zero search cases now accept the stop from either the status read or the watchdog. The fake mount answers `:MSH#` from its own branch with the bare `1` the HAE29C sends.
