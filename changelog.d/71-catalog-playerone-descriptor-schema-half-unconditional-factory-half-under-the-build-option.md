### Changed
- **Player One camera, Phoenix filter wheel and thermal switch moved into the device catalog** (AlpacaCore, AlpacaHTTP): the schemas (`playerone_schema.cpp`, every build) and factories (`playerone_catalog.cpp`, only under `ALPACACORE_ENABLE_PLAYERONE`) replace the router's three register arms, its sanitize branch and the filter wheel and switch driver includes (the camera include stays for the iOptron iCAM arm). `Schema` gains an optional `vendor_label`, which the router's vendor-off refusal text uses before falling back to the first word of the display name, so the text stays "Player One support not enabled. Rebuild with -DALPACACORE_ENABLE_PLAYERONE=ON" for all three types. `GET /management/v1/devicecatalog` now lists the three `playerone` descriptors, `filterNames` as a string list. Two edges differ: the registration log line now reads "Registered Player One camera", "Registered Player One filterwheel" or "Registered Player One switch"; and a wrong-type value is refused with the catalog's "Device config field '<key>' has the wrong type" message, so a `filterNames` that is not an array of strings no longer gets the arm's "Player One filter wheel filterNames must be an array" text, and `cameraIndex` or `filterwheelIndex` as a JSON float with a fractional part or a boolean is refused where the deleted arms read it as an integer. For saved entries, see Breaking changes; a saved `filterNames` that is not a list of names already failed to load in 4.2.0.

### Changed (tooling)
- **Contract-sweep catalog pairs are checked from the catalog itself** (tests and tooling): two cases in `test_contract_sweep.cpp` walk `DeviceCatalog::describe()` and require a registry entry for every available descriptor and a descriptor for every registry entry of a catalog vendor; a vendor counts as one when it has a descriptor or a factory (new `DeviceCatalog::factory_keys()`), so a vendor whose schema registration is missing fails. `scripts/check_contract_sweep.py` no longer parses `DeviceKey{...}` literals in `*_catalog.cpp` files (a second key written any other way passed silently); it still requires every `create_*` call in those files to be called by a registry entry, and a `BACKEND_ALLOWLIST` entry covers such a call only under the catalog file's own vendor. `scripts/check_layering.py`'s AlpacaHTTP vendor-include baseline drops from 35 to 33.
