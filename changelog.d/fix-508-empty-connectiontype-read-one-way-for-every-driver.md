### Fixed
- **ZWO AM mount: an empty or missing connection type now means auto-detect, like every other mount** (AlpacaCore, issue #508; `AlpacaCore/src/vendors/zwo/zwo_schema.cpp`, `AlpacaHTTP/web/app.js`): a ZWO mount created or saved with `connectionType` `""` or absent was refused by the API and, when saved, read as `serial` with a warning. It is now accepted as `auto`, with no warning, and finds the mount at connect. A non-empty unknown value (for example `bogus`) is unchanged. The web edit form shows a saved empty type as Auto instead of Serial (`test_catalog_builtins.cpp`, "ZWO telescope connection type and endpoint rules"). Refs #508.
