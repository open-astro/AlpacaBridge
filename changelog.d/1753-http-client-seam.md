### Changed (internal)

- **AlpacaCore: one outbound HTTP seam, `util::HttpClient`, and the WeeWX driver moved onto it**, issue #1753 (slice 1 of the `remotealpaca` vendor, decision 0023). The interface offers GET and PUT with a form body. Its libcurl implementation (`alpacacore_http_client`) keeps the bounds the WeeWX fetch already had: a 1 MiB response body cap, `http` and `https` only on the request and on every redirect, and a per-call timeout. Tests get a scripted `FakeHttpClient`, a `LockedHttpClient` decorator for the `[stress]` runs, and one shared loopback HTTP server that replaces the two the WeeWX and catalog tests each kept. New loopback tests hold each bound; the redirect allow-list had none. WeeWX behaviour, messages and link-loss handling are unchanged. Decision 0007 item NS-10 is now `fixed`.
