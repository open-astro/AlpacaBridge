### Fixed
- **The Software Update card loads when the page opens** (issue #1103, follow-up to PR #1329): the card was filled in only by **Check for Updates** or the Refresh button, so after a reload the **Update channel** selector showed Stable on a beta host, stayed disabled, and the installed version read `...`. The page now reads `GET /management/v1/update/status` on load (`update.test.js`, "the update card loads its status when the page opens").
- **The headless beta opt-in no longer duplicates the apt source** (follow-up to PR #1329): `docs/beta-channel.md` told headless users to add `beta` to the `openastro.list` line. On such a host the card showed Stable while apt installed betas, choosing Stable changed nothing, and choosing Beta wrote `alpacabridge-beta.sources` beside it, so every `apt update` warned that each beta target "is configured multiple times". The page now writes the same `alpacabridge-beta.sources` file the card writes and says to put an edited `openastro.list` back to `trixie main`. `docs/software-update.md` describes the case.
