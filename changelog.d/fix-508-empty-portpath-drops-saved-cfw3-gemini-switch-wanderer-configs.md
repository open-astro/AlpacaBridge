### Fixed
- **A saved QHY CFW3, Gemini hub or WandererAstro device with a serial connection and no port path now stays registered instead of vanishing after a restart** (AlpacaCore catalog and drivers, issue #508; `AlpacaCore/src/vendors/{qhy,gemini,wandererastro}/*_catalog.cpp`): the entry used to be dropped as "failed to load". It is now registered and listed, logs a warning, and its connect fails with a message naming `portPath` instead of auto-detecting, the way the mount arms already behave. The configuration API still rejects an empty port path (`AlpacaHTTP/tests/test_routing.cpp`, "serial with empty portPath registers and warns (#508 item 1)" for each vendor; the connect text is asserted by the "Connect with empty serial port names portPath" case in each driver's test file). The iOptron filter wheel and the Gemini cover calibrator keep their current behaviour. Refs #508.
