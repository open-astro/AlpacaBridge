### Changed

- **Polled-state module**, Astroasis and QHY focuser drivers, issue #1597. The poll cadence (start to start, missed ticks skipped), the fault latch after three failed polls, the 30 s stale-to-lost rule and the served-frame rules now live once in `util::PolledState` (`AlpacaCore/include/alpacacore/util/polled_state.h`), and both focusers compose it in place of their identical hand-written copies; behaviour is unchanged (`test_astroasis_focuser.cpp` and the QHY focuser tests pass as before) with two exceptions: a poll-fault error now names the driver by its log tag ("Astroasis communications compromised: ..."), and the lost-link error from `served()` reads "Astroasis link lost; ..." and "QHY link lost; ..." where the old text was "Focuser link lost; ...", and `move()` in both drivers now reads the served frame, so a `Move` against a frame older than the 30 s staleness bound latches the loss and throws `NotConnected` where it used to reach the wire (decision 0009). The QHY target and last-change time now live in the polled frame so the poll no longer takes `status_mutex_`; a frame that a `Move` overtook is still dropped with them and `IsMoving` stays true while the motor settles, as before (`QHY Q-Focuser Snapshot - a frame a Move overtook does not clear the target`). The module's cadence, latch, loss and served rules are covered by `AlpacaCore/tests/test_polled_state.cpp`. [Decision 0010](docs/decisions/0010-snapshot-served-state.md) gains rule 7 and a per-row Symbol column in its Adoption table, and [decision 0016](docs/decisions/0016-getters-never-wait-on-device-io.md) rule 2 names the module's mutexes as leaves.
