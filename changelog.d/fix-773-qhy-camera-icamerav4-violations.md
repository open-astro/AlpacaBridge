### Breaking changes
- **QHY camera: calls that used to return a value now return an error** (AlpacaCore, issue #773): `StopExposure` returns a not-implemented error; `HeatSinkTemperature` returns a not-implemented error; `ElectronsPerADU` (was 1.0) and `FullWellCapacity` (was 0.0) return a not-implemented error; `CCDTemperature` returns a not-implemented error on a camera with no temperature sensor (was 0.0 on a camera with no cooler, and the setpoint or 20.0 on a cooled camera that reports no temperature), and an invalid-operation error on a cooled camera until the first temperature reading is available (was the setpoint or 20.0); `ImageArray` read during an exposure returns an invalid-operation error at once (it waited up to 60 s); `StartExposure` above `ExposureMax` returns an invalid-value error (it was not checked). **After upgrading:** call `AbortExposure` instead of `StopExposure`, do not rely on `HeatSinkTemperature`, `ElectronsPerADU` or `FullWellCapacity` returning a value, retry `CCDTemperature` until a reading exists, read `ImageArray` only after `ImageReady` is true, and keep exposures within `ExposureMax`.

### Fixed
- **QHY camera ASCOM conformance** (AlpacaCore, issue #773): a failed exposure (camera error, timeout or watchdog) is now raised by `ImageReady` and `ImageArray` until the next `StartExposure`, instead of `ImageReady` quietly reading false. `CanStopExposure` is now false; `AbortExposure` is unchanged and keeps a finished frame. The calls that now return errors instead of made-up values are listed under Breaking changes. Covered by new cases in `AlpacaCore/tests/test_qhy_camera.cpp`.
