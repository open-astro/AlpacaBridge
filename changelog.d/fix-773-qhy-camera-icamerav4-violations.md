### Breaking changes
- **QHY camera: three calls that used to succeed now return an error** (AlpacaCore, issue #773): `StopExposure` returns a not-implemented error, `HeatSinkTemperature` returns a not-implemented error, and `CCDTemperature` on a camera with no temperature sensor returns a not-implemented error instead of 0.0. A client that called `StopExposure` must call `AbortExposure` instead; a client must not rely on `HeatSinkTemperature` or on `CCDTemperature` of an uncooled camera.

### Fixed
- **QHY camera ASCOM conformance** (AlpacaCore, issue #773): a failed exposure (camera error, timeout or watchdog) is now raised by `ImageReady` and `ImageArray` until the next `StartExposure`, instead of `ImageReady` quietly reading false. `CanStopExposure` is now false (see Breaking changes for `StopExposure`; `AbortExposure` is unchanged and keeps a finished frame). `HeatSinkTemperature`, `ElectronsPerADU` and `FullWellCapacity` return a not-implemented error instead of made-up values, and `CCDTemperature` returns an invalid-operation error while no reading is available, rather than 0 or 20 °C (see Breaking changes for the uncooled case). `StartExposure` above `ExposureMax` is refused as an invalid value, and `ImageArray` during an exposure returns an invalid-operation error at once instead of waiting 60 s. Covered by new cases in `AlpacaCore/tests/test_qhy_camera.cpp`.
