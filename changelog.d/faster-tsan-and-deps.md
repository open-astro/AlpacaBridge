### Changed (tooling)
- **The TSan stress suite runs one shard per core** (CI, `.github/workflows/ci.yml`, `sanitizers-tsan`): the 138 `[stress]` cases ran serially in one process, about 7.75 min of a 9.4 min job, which now sets the merge queue's critical path. They run as Catch2 shards (`--shard-count`/`--shard-index`) in parallel processes, each with its own log group and its own zero-test guard; one failing shard fails the job and names its index.
- **libgpiod and the bundled libgphoto2 are cached between CI runs** (CI, `.github/workflows/ci.yml`): the all-vendors shards, `sanitizers-tsan` and `clang-tidy` built both from source on every run (about 35 to 45 s per job). They now restore one staging tree keyed on the libgpiod pin and `scripts/build_bundled_gphoto.sh` (which holds the libgphoto2 pins), build into it only on a miss (`make install DESTDIR`, `build_bundled_gphoto.sh --destdir`, no root) and copy it into `/`.
- **The merge queue skips the coverage report** (CI, `.github/workflows/ci.yml`): on a `merge_group` run the all-vendors shards no longer collect and upload gcovr data (about 30 s each) and `build-vendors` only checks that every shard passed, skipping its checkout, gcovr install, download and merge (about 40 s). The queue needs pass or fail; the pull request's own run publishes the report.
