### Changed (tooling)
- **The ten scan jobs in CI are one `Static checks` job** (CI, `.github/workflows/ci.yml`): `unicode`, `docs-drift`, `connect-error-hook`, `serial-port-ownership`, `layering`, `stress-registration`, `contract-sweep`, `conformu-reports`, `shellcheck` and `javascript` each took seconds but held a runner, ten of the 19 jobs per run on an organization limited to 20 concurrent jobs, and the merge queue runs `ci.yml` a second time for every PR. Over 40 recent runs the 90th-percentile wait for a runner was 195 s, and `build-vendors`, which sets CI's wall-clock, waited up to 668 s. They are now steps of one `static-checks` job with the same 31 commands in the same order; each step runs even when an earlier one failed, so one run still reports every red gate by name, and the ConformU step stays PR-only. `Static checks` replaces `Unicode scan` and `ShellCheck` as a required check on `main`, so the other eight scans, which were not required before, now block a merge too.
