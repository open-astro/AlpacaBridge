### Changed (CI)
- **The instrumented all-vendors build's compiler cache works** (CI): ccache 4.9 rejects `-fprofile-update=atomic` as an unknown profiling option and cached none of the coverage build's compiles (4888 of 4888 uncacheable, run 39102485820), so every run compiled from scratch (about 244 s). The option now comes from a small compiler wrapper ccache does not see, with `CCACHE_COMPILERCHECK=content` so the cache key follows the wrapper, which records the real compiler's version line and sha256. The report step runs gcov once instead of three times: the combined report writes gcovr's JSON, and the AlpacaCore and AlpacaHTTP reports are filtered from it. Measured on a warm manual run of the merged job (run 39108242958): 304 of 306 compiles hit the cache and the job took 481 s, against 441 s for `build-vendors` plus 749 s for the separate coverage job on `main` before.
- **One all-vendors test run, with coverage, on every pull request** (CI): the separate `coverage` job ran the same 2413 all-vendors tests as `build-vendors`, both at `-O0`, so CI ran the suite twice; #1303 had then limited it to pushes and manual runs to shorten pull-request CI. `build-vendors` ("Build + test (all vendors, arm64)") now builds with gcov instrumentation, runs the suite once and writes the coverage report, on every pull request, and the `coverage` job is gone. The compiler wrapper lives in `.github/scripts/coverage-compilers.sh`, which `clang-tidy` also uses so it restores the same cache. `build-vendors`' timeout goes from 25 to 30 minutes.
