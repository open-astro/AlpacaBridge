### Breaking changes
- **An iOptron mount on a host whose clock is not NTP-synchronised no longer takes the host time at connect** (AlpacaCore, issue #2419): with `syncTimeOnConnect` on (the default), the connect used to write the host clock into the mount whatever its state; it now does so only once the host clock is trusted (see the Fixed bullet). A host with no network time, a Raspberry Pi 5 on its battery RTC included, now leaves the mount on its own clock, and `UTCDate` reports that clock instead of the host's. **After upgrading:** on a rig without network time, have the client write `UTCDate` (or use the web UI's Sync Time) after connecting, as Ara's time sync does, or enable NTP on the host.

### Fixed
- **iOptron: the mount clock is no longer set from an untrusted host clock, and follows the host clock when it is corrected** (AlpacaCore, AlpacaHTTP, issue #2419): a Raspberry Pi with no RTC boots on the time of its last shutdown, and the connect's clock sync wrote that time into the mount with `:SUT` (RC51 on 2026-11-19: 6 h 48 min slow, about 102 degrees of RA, until power-off), and nothing re-synced it after the Pi clock was stepped. The connect now sends `:SG`/`:SDS`/`:SUT` only when the host clock is trusted: the kernel reports it NTP-synchronised, or a client UTCDate write stepped or confirmed it, or Sync Time set it, or the server saw it step. A clock the kernel loaded from a hardware RTC does not count (for the consequence on a host without network time, see Breaking changes). Otherwise the site is still sent, the mount keeps its own clock (which UTCDate reports), and one WARN names it. The server's 1 s timer now watches the realtime clock against the monotonic one and the trust state, and on a step or on the trust edge the new `TelescopeDriver::on_host_clock_changed()` hook re-syncs the iOptron mount on its clock-sync slot: it waits while a driver GOTO, Park, FindHome or MoveAxis is under way, reads `:GUT#`, leaves a mount within 2 s alone, otherwise sends the full site and time body and logs the old and new mount UTC; a re-sync that supersedes the connect's own pass before it finished runs that pass in its place, so the site still reaches the mount. A clock-sync body that starts after a disconnect's join now sends nothing. The unused `sync_mount_clock_with_host_locked()` is removed.

### Added (tests)
- **Host clock trust and step detection** (issue #2419): `HostClockStepDetector` and `HostClockTrust` unit cases; iOptron cases for the untrusted connect, a step re-sync, a trust-edge re-sync, a mount that already agrees, a re-sync waiting out a MoveAxis, a re-sync that supersedes the connect's unfinished pass still sending the site, no re-sync while disconnected or with clock sync off, and a host clock change racing a disconnect; router cases for the step and trust-edge dispatch and the UTCDate trust latch. Existing iOptron cases that expect a connect `:SUT` now pin a trusted host clock (`HostClockTrustGuard`).
