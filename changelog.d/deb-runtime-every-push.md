### Fixed (tooling)
- **Dependency graph: the built package's run-time libraries dropped out as soon as `main` moved** (`scripts/dependency_snapshot.py`, `dependency-submission.yml`, `nightly-build.yml`, issue #1239): the nightly submitted the resolved Depends as a separate snapshot against its own commit, and the graph stopped showing it after the next push (88 entries right after the nightly, 76 two merges later). `dependency-submission.yml` now reads the latest nightly `.deb` on every push and passes it with `--deb`, which puts its resolved Depends and Recommends in the main snapshot under their own `source_location` (`debian/rules`); the nightly's submission step and `--deb-snapshot` are removed.
- **Dependency graph: `dash` and `coreutils` evidence came from every vendored `.rules` file** (`scripts/dependency_snapshot.py`, issue #1239): it now comes only from the udev rules `debian/rules` installs, so a copy the package never ships cannot keep them listed. The module docstring's first line, which still said the graph parses only the action pins, is corrected.
