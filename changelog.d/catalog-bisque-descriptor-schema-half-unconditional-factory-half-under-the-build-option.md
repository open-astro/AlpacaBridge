### Changed
- **Bisque / Paramount (TheSkyX) telescope moved into the device catalog** (AlpacaCore, AlpacaHTTP): the schema (`bisque_schema.cpp`, every build) and factory (`bisque_catalog.cpp`, only under `ALPACACORE_ENABLE_BISQUE`) replace the router's register arm, its sanitize branch and its driver include. The vendors-OFF text stays "Bisque support not enabled. Rebuild with -DALPACACORE_ENABLE_BISQUE=ON", and an empty host is still refused from the API with "Host is required for Bisque/TheSkyX connection" and warned about for a saved config. `GET /management/v1/devicecatalog` now lists the `bisque` telescope descriptor. The registration log line now reads "Registered Bisque telescope", and a wrong-type value is refused with the catalog's "Device config field '<key>' has the wrong type" message. `scripts/check_layering.py`'s AlpacaHTTP vendor-include baseline drops from 33 to 32. An out-of-range `siteLatitude` or `siteLongitude` sent through the API is now refused with the catalog's "siteLatitude is out of range (min -90) (max 90)" text instead of "siteLatitude 200 is out of range: must be between -90 and 90 degrees", and the saved-config warning now reads "config normalized: ..." instead of "... The coordinate is ignored; set a valid one in the web UI."
