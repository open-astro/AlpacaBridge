### Breaking changes
- **A serial port can belong to one device only** (AlpacaCore, issue #1202): two devices configured on the same serial port used to both report connected while they fought over the line; the second connect is now refused and the message names the device that holds the port. Another program (a GPS scanner, ModemManager, a terminal) can no longer open a port AlpacaBridge holds. If you relied on either, give each device its own port, or stop the other program while AlpacaBridge is connected.

### Fixed
- **Serial devices no longer disturb each other's ports** (AlpacaCore, every serial driver, issue #1202): many vendors use the same CH340 USB adapter, so one device's auto-detect scan matched every other device and opened their live ports at its own baud rate. A Gemini flat panel scan left a connected Gemini power hub faulted until restart. Every serial driver now opens its port through one shared helper: a scan never opens a port a connected device holds and waits its turn on a port another scan is probing, a second auto-detect device of the same kind keeps its index while the first is connected, a connected port is locked against other programs, and a port whose line settings another program changed gets them back on the next timed-out read. For two devices on one port, see Breaking changes.
- **A retuned serial port can no longer hang Disconnect or service stop** (AlpacaCore, every serial driver, issue #1202): reads relied on the port's `VTIME` setting, so a port another program switched to `VMIN=1` parked the reader forever (a WandererRotator move monitor, an OnStep mount after Park), and Disconnect and `systemctl restart` waited on it. All serial reads and writes are now non-blocking and bounded with `poll()`.
- **Auto-detect picks ports in a fixed order** (AlpacaCore, issue #1202): `/dev/serial/by-id` entries were probed in directory order, which can change between scans, so an auto-detect index could name a different device after a reconnect. They are now sorted by name.

### Added (tooling)
- **Serial port ownership gate** (CI, issue #1202): `scripts/check_serial_port_ownership.py` (the `serial-port-ownership` CI job and pre-flight gate 2e2) fails on a serial port opened, configured or locked outside `util::SerialLink`.
