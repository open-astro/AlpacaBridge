### Changed
- **ZWO camera moved into the device catalog** (AlpacaCore, AlpacaHTTP, issue #999): the schema (`zwo_schema.cpp`, every build) and a new optional `Factory::bind` hook (`zwo_catalog.cpp`, only under `ALPACACORE_ENABLE_ZWO`) replace the router's ZWO camera arm, its sanitize branch, `read_zwo_selector` and the last ZWO include in `router.cpp`; `GET /management/v1/devicecatalog` now lists the `zwo` camera. The bind hook is also the catalog's first way for a descriptor to see the other stored entries of its key (`BindContext::peers`) and to hand learned config back (`BindResult::learned` / `erased`, merged into the stored entry by the router); `Schema::forget_dropped_selectors` replaces the router's `zwo` vendor test for erasing a stored selector that normalize dropped. The identity-string refusals, "ZWO camera requires cameraIndex or cameraId", the duplicate `serialNumber` / `uniqueId` refusal, claimed serials, UniqueID reuse and generation and the learned serial and model name keep their behaviour and API texts (`AlpacaCore/tests/test_zwo_camera_catalog.cpp`, `AlpacaCore/tests/test_catalog_builtins.cpp`, and the unchanged ZWO camera cases in `AlpacaHTTP/tests/test_routing.cpp`). Two edges differ: a `cameraIndex` or `cameraId` outside -1 to INT_MAX is refused with the catalog's range text (`cameraIndex is out of range (min -1) (max 2147483647)`, as the other ZWO device types) instead of "expected an integer from -1 to 2147483647", and a selector that is not an integer is refused as the wrong type.

### Breaking changes
- **A saved ZWO camera entry whose `cameraIndex` or `cameraId` is not a JSON integer (for example the string `"1"`) is no longer loaded** (AlpacaHTTP, issue #999): the catalog's JSON bridge refuses the entry, so it is skipped at start-up with "Failed to load persisted device", as every other catalog device already is. The deleted arm dropped a bad selector and registered the camera. The web UI writes integers, so only a hand-edited `registered_devices.json` is affected; fix the value there.
