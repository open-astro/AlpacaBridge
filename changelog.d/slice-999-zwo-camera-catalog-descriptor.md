### Changed
- **ZWO camera moved into the device catalog** (AlpacaCore, AlpacaHTTP, issue #999): the schema (`zwo_schema.cpp`, every build) and a new optional `Factory::bind` hook (`zwo_catalog.cpp`, only under `ALPACACORE_ENABLE_ZWO`) replace the router's ZWO camera arm, its sanitize branch, `read_zwo_selector` and the last ZWO include in `router.cpp`; `GET /management/v1/devicecatalog` now lists the `zwo` camera. The bind hook is also the catalog's first way for a descriptor to see the other stored entries of its key (`BindContext::peers`) and to hand learned config back (`BindResult::learned` / `erased`, merged into the stored entry by the router); `Schema::forget_dropped_selectors` replaces the router's `zwo` vendor test for erasing a stored selector that normalize dropped, and now also drops a stored selector that is not an integer (such as the string `"1"`) so the entry still loads, as the arm did. The out-of-range selector text ("Invalid value for cameraIndex: expected an integer from -1 to 2147483647"), the identity-string refusals, "ZWO camera requires cameraIndex or cameraId", the duplicate `serialNumber` / `uniqueId` refusal, claimed serials, UniqueID reuse and generation, and the learned serial and model name keep their behaviour and API texts (`AlpacaCore/tests/test_zwo_camera_catalog.cpp`, `AlpacaCore/tests/test_catalog_builtins.cpp`, and the ZWO camera cases in `AlpacaHTTP/tests/test_routing.cpp`). One edge differs: `configuredevice` with a selector that is not an integer (`"1"`, `true`, `1.5`) is still refused, but with the catalog's "has the wrong type" text instead of "expected an integer from -1 to 2147483647".
- **ZWO ASI533MC Pro and ASI120MM Mini re-validated with ConformU 4.5.1** (issue #999): both Linux arm64 reports under `AlpacaCore/conformu/ZWO/ASI/` are replaced by runs on ASI Camera SDK 1.41 with the camera on the device catalog, and the ZWO notes in `SUPPORTED-DRIVERS.md` name both cameras (the ASI120MM Mini report ends "no errors, warnings or issues found", the ASI533MC Pro report "all members returned within their target response times").

### Fixed
- **A JSON integer above 9223372036854775807 in a device config was read as a negative number** (AlpacaHTTP, issue #999): `config_from_json` wrapped `18446744073709551615` to -1, which an integer field with a "not set" sentinel (the ZWO -1 selectors) accepted. An integer field now refuses it as the wrong type, and a double field keeps it as a large double (`AlpacaHTTP/tests/test_catalog_json.cpp`, "an unsigned integer above INT64_MAX is the wrong type").
