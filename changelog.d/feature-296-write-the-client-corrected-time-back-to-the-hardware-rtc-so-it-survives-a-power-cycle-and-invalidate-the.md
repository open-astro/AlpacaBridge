### Added

- **A corrected system clock is written back to the hardware RTC** (HostClock, issue #296, also #307): after a client `UTCDate` write or a Sync Time press steps the clock, `HostClock` writes the system time to the RTC the host booted from (`RTC_SET_TIME`), so the correction survives a power cycle, and re-probes the RTC so `ClockSource` reads `rtc` instead of `none` on a battery-less RTC; a skipped or failed step writes nothing, a write failure logs one WARN and leaves the step result alone, and `debian/alpacabridge.udev` gives the service group write access to `/dev/rtc*` (cases in `test_host_clock.cpp`).
