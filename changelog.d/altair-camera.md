### Added
- **Altair Astro camera driver** (AlpacaCore + AlpacaHTTP): Altair cameras (ToupTek OEM hardware) are a new `altair` camera vendor over Altair's own SDK, altaircamsdk 60.31589.20260531 (`libaltaircam.so`, shipped in the `.deb` with its udev rule). The SDK is MIT licensed (confirmed by Altair Support): its `license.txt` and a `debian/copyright` entry carry the required notice. The camera runs the ToupTek camera driver with Altair identity strings (`ALTAIR_SN_<serial>` unique id), so readout modes, ROI rounding, the exposure guards and the thermal poller behave exactly as on a ToupTek camera. It registers through the device catalog (`altair_schema.cpp` / `altair_catalog.cpp`, persisted field `cameraIndex`), adds no vendor include to the router, and appears in the web UI as "Altair" with its own camera-index field. Build option `ALPACACORE_ENABLE_ALTAIR` (requires `ALPACACORE_ENABLE_TOUPTEK`). Validated on the ALTAIR178M3 with ConformU 4.5.1: 0 errors, 0 issues, 0 timing issues. On the OrangePi 3 LTS use a USB 2 port: its USB 3 port loses full frames at every camera speed level, even through the vendor SDK alone.

### Changed
- **ToupTek SDK wrapper is now shared by the ToupTek SDK family** (AlpacaCore): the wrapper body moved into `ToupcamFamilySDK<Api>` (`AlpacaCore/src/vendors/touptek/toupcam_family_sdk.h`, private to the vendor sources), and `ToupTekSDKWrapper` and the new `AltairSDKWrapper` supply only a traits struct generated from one function and constant list, so the two brands cannot drift. ToupTek behaviour and error text are unchanged. `ToupTekSDKWrapper::instance()` now returns the `ToupTekSDK` interface, and the deprecated, unused `open_camera_by_index()` is gone.

### Added (tests)
- **Altair camera cases** (AlpacaCore + AlpacaHTTP): `test_altair_camera.cpp` (identity, connected identity over the fake SDK, error codes, value ranges, state machine, unsupported members), the `altair_concurrency_stress.cpp` `[stress]` registration, contract-sweep tier 1 and tier 2 entries, and the HTTP config round-trip, sanitize, device-catalog fixture and built-out-vendor cases.

### Changed (tooling)
- **Stress-registration gate understands delegating factories** (`scripts/check_stress_registration.py`): a vendor `*_driver.cpp` that only builds another vendor's driver class (the Altair camera factory over the ToupTek camera driver) has no `get_device_type()` override, so the gate read it as an unknown device type with no `[stress]` coverage. A new `DELEGATING_FACTORIES` table names each such file, the device type it builds and why; an entry whose file is gone or now has its own override fails the gate, and the self-tests cover the lookup.
