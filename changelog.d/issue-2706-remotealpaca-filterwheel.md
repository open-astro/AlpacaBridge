### Added
- **remotealpaca: FilterWheel of an upstream Alpaca server** (AlpacaCore, AlpacaHTTP, web UI, issue #2706, slice 5 of #1753): the "Remote Alpaca" vendor now also serves the FilterWheel device of another Alpaca server as a device of this server, with the same four settings (upstream host, port, device number, poll period) and the same Connect, snapshot and link rules as the other proxied devices. `Position` answers from the poll's snapshot, so it reads -1 while the upstream's wheel turns. `Names` and `FocusOffsets` are read at each Connect, replace what this server held, and keep answering while the link is faulted and while disconnected; a names or offsets write changes this server's copy only. An upstream error on `Names` or `FocusOffsets` fails the Connect with that error. A `Position` write checks the slot against the upstream's count (`InvalidValue`), is forwarded in the command slot and reads -1 at once; while the link is faulted it and the `Position` read throw `DriverException`. Built under `ALPACACORE_ENABLE_REMOTEALPACA`; fake evidence only, ConformU against the simulators is a rig step.
- **remotealpaca client: integer arrays** (AlpacaCore, issue #2706): `RemoteAlpacaClient::get_int_list` reads a `Value` that is an array of whole numbers inside int (a FilterWheel's `FocusOffsets`); anything else is a `RemoteTransportError`.

### Added (tests)
- **remotealpaca FilterWheel over a scripted upstream** (issue #2706): `test_remotealpaca_filterwheel.cpp` (12 cases), four `[stress]` cases, the contract-sweep entry with its tier-2 host (which also runs the shared filter wheel slot-data case), tier-3 recipe and snapshot rig, two catalog cases, two `test_routing` cases (the config round trip and the router's self-loop refusal) and `get_int_list` checks in the client's Value-type case. `AlpacaUpstreamScript` gains a FilterWheel kind whose Position write reads -1 until `finish_wheel_move()`.
