### Changed

- **Faster reconnects for auto-detected Gemini and iOptron devices**, Gemini Power & Data Hub, Gemini flat panels (Lite, Rev2, Pro) and iOptron mounts, issue #1452. After an auto-detect succeeds, the port or `host:port` is remembered in `config/device_locations.json`, keyed by the device's `UniqueID` and its index (a `/dev/serial/by-id` path when one resolves to the port). The next connect, also after a service restart, checks that one place with a single identity handshake (only when the entry's index is unchanged) and runs the full search only when it fails, so a connect no longer waits 5-13 s for a search that finds the same device. A port that another connected device holds is never probed, and a port or address you configure yourself is used as given and never stored. A missing, corrupt or unwritable file only means the full search runs, as before. Covered by `AlpacaCore/tests/test_device_location_store.cpp`, `test_gemini_remembered_location.cpp`, `test_ioptron_remembered_location.cpp` and `test_ioptron_serial_ownership.cpp`.
