### Fixed
- **OnStep: FindHome on a mount built with a tangent arm or a sector gear is no longer reported as failed** (AlpacaCore), issue #2296. Neither OnStep 4.x nor OnStepX reports At Home after such a home, which only centres that axis. The driver reads `:GXEF#`/`:GXEG#` at the first FindHome of a session and does not watch the home on such a mount, so `AtHome` stays false and no failure is kept. If the flags do not read, the home is watched as before, and an OnStepX mount whose version did not read is still asked about a sector gear.
- **OnStep: the park and home time limit now follows a slow mount's slew rate** (AlpacaCore), issue #2296. The limit is worked out at connect from the base slew rate the mount reports (`:GX93#`, `:GXE4#`), never below 20 minutes and never above 24 hours, so a healthy park or home on a slow mount is no longer failed at 20 minutes. A park carried over a relink keeps its limit, and a mount whose rate does not read keeps 20 minutes.
- **Power-port switches (ASIAIR Pro and Plus, iMate PowerBox, StellaVita) refuse a port wrapper whose port count differs from the configured port table** (AlpacaCore), with InvalidValue at construction, on every board. Only the StellaVita test seam checked this before. Every production factory builds both from the same config, so no real setup is affected.

### Changed
- **OnStep: a GOTO repeated into a limit that stands logs one warning, not one per attempt** (AlpacaCore), issue #2296 and decision 0007 rule 9. The first stop with a given reason and code is logged at WARN and its repeats at INFO, whichever member started the GOTO, until a status shows another code. The client still gets the failure every time.
- **OnStep 4.x: AbortSlew may leave tracking off while the mount still holds an older limit code** (AlpacaCore), issue #2296. OnStep 4.x keeps the `:GU#` code of its last limit stop until an unpark, a home reset, a reboot or a `:Te#` from another program (setting Tracking through AlpacaBridge does not clear it). A slew aborted short of its target while that code is held reads as stopped at the limit, so the abort succeeds but does not turn tracking back on. Set Tracking to true after the abort if you want it. OnStepX, and OnStep 4.x with no code held, restore tracking as before.
- **OnStep docs: the limits of the motion watch are written down** (docs), issue #2296: a GOTO that ends away from its target with no stop code (a handset abort) still reads as landed, a failed OnStepX switch home can still report At Home, and neither can be told apart from what the mount sends.
- **StellaVita Switch: the factory no longer copies the whole config to build its board profile** (AlpacaCore); the chip path and port table move into the power box, as on the ZWO and iOptron boards.
- **`scripts/check_docs_drift.py` check 5 holds `SHARED_DRIVER_HEADERS` to the vendors that instantiate each shared driver class** (tooling), in both directions (`SHARED DRIVER VENDOR UNLISTED`, `STALE SHARED DRIVER VENDOR`, `SHARED DRIVER CLASS NOT FOUND`).

### Added (tests)
- **OnStep tangent-arm and sector-gear homes, the slew-rate park and home limit, repeated limit-stop logging, and the status poll through a park** (issue #2296).
- **Power-port Switch pins**: the port-count refusal and destruction warning over a scripted wrapper, each board's NotConnected and out-of-range texts, the StellaVita destruction warning through a fake power box whose `close()` can throw, and contract-sweep `SetSwitchValue` probes just outside each board's static range while disconnected (InvalidValue before NotConnected).
