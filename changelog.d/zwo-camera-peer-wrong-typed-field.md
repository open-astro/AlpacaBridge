### Fixed
- **A stored ZWO camera with one wrong-typed field still claims its uniqueId** (AlpacaHTTP router, review of #1163): since the ZWO camera moved into the device catalog, a stored camera entry with one field of the wrong JSON type (a hand-edited numeric `serialNumber`) was skipped as a whole when another camera was registered, so its `uniqueId` was no longer checked and `configuredevice` accepted a second camera with the same UniqueID. Only the wrong-typed field is now left out, as before the move. Pinned by the new case in `test_routing.cpp`.
- **A duplicate uniqueId in stored ZWO camera entries is cleared from the file** (`AlpacaCore/src/vendors/zwo/zwo_catalog.cpp`, issue #1166): two stored cameras with their own serials and one `uniqueId` logged "Ignoring duplicate ZWO camera uniqueId in the stored entry" on every start, because the cleared id was kept out of memory but never written back. The first entry's copy is now written back cleared, as a cleared serial already was, so the next start finds no duplicate. The UniqueID clients see does not change: a camera with a serial reports `ZWO_SN_<serial>`. Pinned by a new case in `test_routing.cpp` and the updated stored-duplicate case in `test_zwo_camera_catalog.cpp`.
