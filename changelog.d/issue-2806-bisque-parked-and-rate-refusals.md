### Breaking changes
- **Bisque refuses AbortSlew on a parked mount** (Bisque driver, issue #2806): AbortSlew while AtPark is true used to return and send TheSkyX an Abort(); it now raises `InvalidWhileParked` (0x408), as ITelescopeV4 requires. A client that sends AbortSlew to a parked Paramount, for example at the end of a session, now gets an error. **After upgrading:** check AtPark before AbortSlew, or treat `InvalidWhileParked` from it as "nothing to stop".
- **Bisque refuses Tracking = true on a parked mount** (Bisque driver, issue #2807): writing Tracking true while AtPark is true used to send TheSkyX SetTracking and start tracking on the parked mount; it now raises `InvalidWhileParked` (0x408), as ITelescopeV4 requires. **After upgrading:** Unpark before turning Tracking on.
- **Bisque refuses a MoveAxis rate above the AxisRates maximum** (Bisque driver, issue #2808): a rate above 512x sidereal (about 2.139 deg/s) used to start a jog at the 512x preset; it now raises `InvalidValue` (0x401), as ITelescopeV4 requires. **After upgrading:** keep MoveAxis rates inside the range AxisRates reports.

### Fixed
- **Bisque AbortSlew while parked raises InvalidWhileParked** (Bisque driver, issue #2806): ConformU's `Parked:AbortSlew` check failed. The refusal sends TheSkyX nothing. A Park still in flight is not AtPark, so AbortSlew then still sends Abort() and cancels the Park. For the effect on clients, see Breaking changes. Tests: two `[bisque]` AbortSlew cases in `test_bisque_telescope.cpp`.
- **Bisque Tracking = true while parked raises InvalidWhileParked** (Bisque driver, issue #2807): ConformU's `Parked:Tracking = true` check failed. No SetTracking reaches TheSkyX. Tracking = false on a parked mount is still sent. For the effect on clients, see Breaking changes. Tests: "Bisque Tracking - true is refused while parked and false is still sent (#2807)" in `test_bisque_telescope.cpp`; the fake counts SetTracking commands.
- **Bisque MoveAxis checks its rate against AxisRates** (Bisque driver, issue #2808): ConformU's MoveAxis checks for a rate above the maximum and below the minimum failed on both axes. A |rate| above 512x sidereal is now `InvalidValue`, before the connection check, and nothing reaches TheSkyX. A rate inside the range still snaps to the nearest of the nine presets, and the 1e-9 stop threshold is unchanged. For the effect on clients, see Breaking changes. Tests: "Bisque MoveAxis - a rate beyond the AxisRates maximum is InvalidValue and the maximum moves (#2808)" in `test_bisque_telescope.cpp`.
