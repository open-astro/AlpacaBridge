### Added
- **Celestron CGX: SkyPortal WiFi (AUX over TCP) transport in the AUX link** (AlpacaCore, private, no issue): `CelestronCgxProtocol::connect_tcp()` talks to the SkyPortal adapter from source 0x20. It re-sends a read-only motor query once when its reply is lost (300 ms, within the caller's deadline) and never re-sends a motion or write command. It resyncs past collision debris and bad checksums, discards the adapter's startup backlog and treats the adapter closing the connection as a lost link. The USB path is unchanged.
- **Celestron CGX: the driver runs over SkyPortal WiFi** (AlpacaCore, private, no issue): a CGX configured with a numeric adapter host (port 2000 by default) connects over TCP instead of USB. Over TCP each exchange gets 1 s (room for the one re-send of a lost read-only query, version and model probes included), every Connect takes the mount over with a verified stop, every Disconnect closes the socket and drops the home reference (FindHome again after a reconnect), one adapter serves one device, a motor controller's report is acknowledged and anything but a low-battery warning costs the reference, a stop nobody acknowledges ends with send-only stops, and the description counts the lost replies a re-send recovered. The USB driver is unchanged.
- **Celestron CGX over SkyPortal WiFi: a lost motion reply is settled by the axis status, never re-sent** (AlpacaCore, private, no issue): when a home start, GOTO, label write, guide pulse or stop gets no reply within 300 ms, the link reads the axis status instead (home searching, the GOTO closer to its target, the label read back, the guide active, the axis still). A command that took effect counts as done, with a warning and the recovered-reply count; one that did not fails as before. A stop the status cannot confirm gets the send-only stop at once instead of after three rounds, and stop checks over WiFi get 600 ms more to finish. USB is unchanged.

- **Celestron CGX: USB or SkyPortal WiFi, chosen in the device form** (AlpacaCore, AlpacaHTTP, private, no issue): the CGX entry's Connection Type picks the mount's direct USB port or the SkyPortal WiFi adapter (its numeric IPv4 or IPv6 address, 1.2.3.4 on the adapter's own hotspot, port 2000); a name is refused, and a saved CGX entry with no connection type stays USB. A "Find adapter" button on the form lists the adapters heard within 5 s (`GET /management/v1/networkadapters?vendor=celestron`, one search at a time, holding no lock) and fills the address in; Save still applies it. Hotspot mode only: join this board to the adapter's network by hand.
- **Celestron CGX: SkyPortal WiFi adapter beacon listener** (AlpacaCore, private, no issue): `listen_for_aux_beacons()` listens on UDP port 55555 for a bounded window and lists each SkyPortal adapter it hears (source address, SSID, module) for the form's "Find adapter" button. It sends nothing.
