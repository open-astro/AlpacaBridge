### Added
- **Celestron CGX: SkyPortal WiFi (AUX over TCP) transport in the AUX link, not yet selectable** (AlpacaCore, private, no issue): `CelestronCgxProtocol::connect_tcp()` talks to the SkyPortal adapter from source 0x20. It re-sends a read-only motor query once when its reply is lost (300 ms, within the caller's deadline) and never re-sends a motion or write command. It resyncs past collision debris and bad checksums, discards the adapter's startup backlog and treats the adapter closing the connection as a lost link. No config or UI uses it yet; the USB path is unchanged.
- **Celestron CGX: the driver can run over SkyPortal WiFi, not yet selectable** (AlpacaCore, private, no issue): a CGX configured with a numeric adapter host (port 2000 by default) connects over TCP instead of USB. Over TCP each exchange gets 1 s (room for the one re-send of a lost read-only query, version and model probes included), every Connect takes the mount over with a verified stop, every Disconnect closes the socket and drops the home reference (FindHome again after a reconnect), one adapter serves one device, a motor controller's report is acknowledged and anything but a low-battery warning costs the reference, a stop nobody acknowledges ends with send-only stops, and the description counts the lost replies a re-send recovered. Nothing in the catalog, config or web UI selects it yet; the USB driver is unchanged.
- **Celestron CGX over SkyPortal WiFi: a lost motion reply is settled by the axis status, never re-sent** (AlpacaCore, private, no issue): when a home start, GOTO, label write, guide pulse or stop gets no reply within 300 ms, the link reads the axis status instead (home searching, the GOTO closer to its target, the label read back, the guide active, the axis still). A command that took effect counts as done, with a warning and the recovered-reply count; one that did not fails as before. A stop the status cannot confirm gets the send-only stop at once instead of after three rounds, and stop checks over WiFi get 600 ms more to finish. USB is unchanged.

### Added (tests)
- **CGX AUX over TCP cases** (private, no issue): a loopback fake SkyPortal adapter with per-request fault scripting, 13 transport cases and one USB guard case; then 8 more transport cases, a USB timeout guard and 7 driver cases; then a motor model in the fake, 5 status-confirmation transport cases, a USB guard and 4 driver cases (one USB).
