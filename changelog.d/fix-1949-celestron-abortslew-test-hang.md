### Fixed (tests)

- **Celestron fake-time stepping loops wait for the task under test, not only the status poll** (AlpacaCore tests, issue #1949): the stepping loop of `Celestron Slewing read - a read that lands after AbortSlew is not applied` in `AlpacaCore/tests/test_celestron_telescope.cpp` waited for one task-clock waiter, and the paused status poll is always one. A slew thread that reached the clock late found all 400 steps used up, slept on a clock nobody advanced, and the test hung in `join()` until the 900 s CTest timeout. Each step now waits up to 5 s for two waiters (the poll and the slew); if the slew does not arrive, the test fails, and the new `FakeTaskClock::drain_until` (`AlpacaCore/tests/fake_task_clock.h`) steps the clock until the slew thread ends so `join()` returns. In `AlpacaCore/tests/test_celestron_async_park.cpp`, `advance_until` now takes the waiter count of each caller, the RA-offset case's `finish` waits for two waiters, and its stepper's start rendezvous waits for two waiters (the paused poll and slew 2's body). With a 300 ms delayed body each of these failed at random before the change (the stepper case aborted the process); the two sync-slew cases also drain the clock before `join()`. The case's fake mount now answers the AUX slew-done query (`MC_SLEW_DONE`) from its slewing flag, as it already did for `L`. Before that, at host sidereal times where the target lies across the meridian, the stale read went through the meridian-flip path and read "done", so the test passed even with the post-AbortSlew generation check removed.
