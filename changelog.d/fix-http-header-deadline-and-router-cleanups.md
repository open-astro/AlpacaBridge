### Security
- **HTTP: a slow client can no longer pin every worker** (AlpacaHTTP, issue #1694): the request line and headers of every request, keep-alive ones included, must now arrive within 10 s of a worker starting to read them, or the server answers 408 and closes the connection. Before, each header byte reset the 30 s receive timeout, so a LAN host trickling one byte at a time held a worker for about 150 s, and 32 such connections (the default pool, which the default per-address connection cap also equals) made NINA and ConformU requests queue behind them. A real client sends its headers in one write and is unaffected. Decision 0007's resource budget now names the header deadline.
- **AlpacaHTTP: more invisible characters in log text are escaped** (issue #2087): `util::escape_for_log` now also writes U+200E and U+200F (left-to-right and right-to-left marks), U+061C (Arabic letter mark), U+FEFF (byte-order mark) and U+2028 and U+2029 (line and paragraph separators) as `\xNN` per UTF-8 byte, so a client-supplied value cannot shift or break how a log line displays.
- **AlpacaHTTP: every router log line escapes exception text** (issue #2087): 25 log calls in the router (the description handler, configured devices, failed devices, device errors, API versions, build info, device catalog, camera listings, log files, persisted devices, saved state, power-on state, the motion watchdog and the generic router error) wrote an exception's message to the log unescaped, so a future message that quoted a client value could forge a log line. They now go through `util::escape_for_log`, as the device-call path already did.

### Fixed
- **Web UI: the header clock drops a stale "clock error" when the server stops answering** (issue #2087): once the server had refused to report its time and then became unreachable, the header kept showing "clock error" and clicking it still advised Sync Time, which cannot work while the server is down. A failed fetch now clears the error and keeps the last known offset, so the clock keeps ticking locally until the next refresh. The page loads `format.js` and `app.js` under new version numbers, so a browser cannot pair the new `app.js` with a cached `format.js` that lacks the helper it calls.
- **Server config: a tab-indented key stays in its section** (AlpacaHTTP, issue #2087): tabs are not valid YAML indentation, but in a hand-edited config file a key indented with a tab used to end its section, both when the server read the file (that key and the rest of the section were ignored) and when the web UI saved a setting (the setting was written above that line and the old value left below it). A leading tab now counts as indentation in both places, so such a key now takes effect, and a saved setting keeps the line's own indentation.

### Added (tests)
- **Header deadline, log escaping, clock error and tab indent cases** (issues #1694, #2087): a socket test that trickles headers past a shortened header deadline on a fresh and a keep-alive connection and then gets the only worker back, a `test_log_text` case for the six new code points and their neighbours, a routing case that logs a throwing driver's message escaped, a routing case for a tab-indented config key read back through `Config`, and two web cases: the clock state after a failed fetch, and the header clock's use of it with the script versions bumped.
