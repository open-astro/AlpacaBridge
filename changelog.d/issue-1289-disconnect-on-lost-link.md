### Fixed

- **A client Disconnect after a lost link now reaches the driver and settles the loss**, AsyncConnectable, OnStep and Sky-Watcher telescope drivers, issue #1289. A Disconnect queued against an in-flight Connect used to be dropped when the link was lost meanwhile (`Connected` already read false), so the lost session was never reset; the connection task now always runs it. A client's own Disconnect now also consumes the link-loss stamps (OnStep's loss and last-alive times, Sky-Watcher's `link_lost_at`), so the next Connect is a fresh one and no longer sends the #521 relink stops (`:Q#` and `:Qn/s/e/w#` on OnStep, `:K` on Sky-Watcher) that would end a slew started meanwhile from the handset. A relink after a loss with no Disconnect in between still stops motion after a long outage. Covered by `test_async_connectable.cpp`, `test_onstep_link_loss.cpp` and `test_skywatcher_link_loss.cpp`; [decision 0009](docs/decisions/0009-link-loss-and-relink-policy.md) point 4 and rule 4 now say so.
