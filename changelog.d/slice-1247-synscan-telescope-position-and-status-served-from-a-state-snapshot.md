### Changed

- **SynScan telescope: position, status and `DeviceState` are served from a state snapshot** (AlpacaCore, issue #1247; `synscan_telescope_driver.cpp`): one poll body reads the hand controller every second (slewing flag and RA/Dec each tick, Alt/Az, pier side and tracking mode every fourth) and every getter and `DeviceState` answers from memory, so the first `DeviceState` no longer costs four serial round trips (issue #617) and the 2 s position cache is gone (`test_synscan_telescope_snapshot.cpp`: at 100 ms per handset transaction no getter or `DeviceState` call reaches the handset and each returns under 20 ms). `TimeStamp` is the time of the measurement. `SetTracking` is read back at once, and a poll that sampled before a write cannot overwrite it (`a setter's value is read back at once and a stale poll does not undo it`). Three failed polls in a row latch a link fault (getters throw a `DriverException` "communications compromised" while `Connected` stays true); a fault standing 30 s is a lost link: `Connected` reads false, operations throw `NotConnected` and `DeviceState` is empty with no `TimeStamp` (`past the staleness bound DeviceState is empty with no TimeStamp`). A pointing state that is neither E nor W still reads as `SideOfPier` -1 (pierUnknown) from the snapshot, with no handset transaction (`a pointing state that is neither E nor W reads as pierUnknown, not an error`); `SideOfPier` throws only until the handset has answered `p` once. PulseGuide still asks the handset whether a slew is running, so a slew started on the keypad refuses the pulse at once (`PulseGuide refuses while the handset slews even when the frame is older`), and a status tick that starts as the GOTO landing hunt takes the line makes no handset exchange (`a tick that passed its first hold check makes no exchange once the hunt holds the line`). A slewing re-read that finds the value unchanged no longer drops the poll tick in flight, so the position keeps updating during a GOTO or Park while the slew loop re-reads the slewing flag every 250 ms (`a slewing re-read that finds no change does not drop the poll's frame`). The poll's retry of an unread site (`w`) no longer holds the driver lock, so a getter does not wait on a handset that ignores it (`a getter does not wait while the poll retries an unread site`); `DestinationSideOfPier` with no site refuses a faulted link like every other frame read (`DestinationSideOfPier with no site refuses a faulted link like the other reads`); and the landing hunt's wait for a status tick already sampling ends on a stop or a newer slew and is bounded at 1.5 s (`a new slew while the hunt waits on a held status tick starts at once`, `the hunt reads past a held status tick once its wait bound runs out`). ConformU not re-run (fake-only validation, no hardware).

### Changed (tooling)

- **CI caches compiler output with ccache** (`.github/workflows/ci.yml`): the `build-test`, `build-vendors`, `sanitizers`, `sanitizers-tsan` and `coverage` jobs restore a per-job ccache directory before they compile and set it as the CMake compiler launcher, so a source that has not changed is not compiled again. Only a push to `main` or `stable/**` saves the cache; a pull request reads its base branch's cache and writes none. The longest job, `coverage`, took about 11.4 min with no cache, of which about 4 min was compiling.
