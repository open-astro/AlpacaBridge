### Added
- **Stable/Beta update channel switch in the web UI** (issue #1103): the Software Update card has an **Update channel** selector. Choosing a channel starts the root unit `alpacabridge-channel@stable.service` or `alpacabridge-channel@beta.service` (`debian/alpacabridge-channel@.service`, helper `debian/alpacabridge-set-update-channel`), which writes or removes the apt source `/etc/apt/sources.list.d/alpacabridge-beta.sources` and runs `apt-get update`; the polkit rule allows exactly those two instances plus the existing update unit. The update check reads the matching index (`dists/trixie/main/...` for Stable, `.../beta/...` for Beta) from the same mapping that names the apt component, so the two cannot disagree (`test_software_update`, "channel mapping ties the check URL, the apt component and the unit name"). `POST /management/v1/update/channel` takes `{"Channel":"stable"|"beta"}`, answers HTTP 400 for anything else, and is refused with `InvalidOperation` while an install or a switch runs; the status payload gains `Channel`, `ChannelOverridden` and `ChannelSwitch`. Choosing Stable on a beta build says the build stays until the stable release overtakes it (`channelDowngradeNotice`, `update.test.js`). `apt purge` removes the beta source.
- **`update_packages_url` follows the channel unless overridden** (issue #1103): unset, or equal to the stock stable index, the check URL follows the channel; any other non-empty value is used as is and the card shows the selector disabled with "set by update_packages_url". The shipped `default.yaml` now carries the key as a commented example. `docs/beta-channel.md` puts the web UI path first and keeps the manual two-edit path for headless installs.
