### Changed
- **ZWO telescope, filter wheel, focuser, rotator and switch moved into the device catalog** (AlpacaCore, AlpacaHTTP, issue #999; the camera follows in a later slice): one schema (`zwo_schema.cpp`, every build) and one factory (`zwo_catalog.cpp`, only under `ALPACACORE_ENABLE_ZWO`) replace the router's five register arms, its sanitize branches for those types and seven driver includes (tests `Builtin catalog - register_builtin_schemas describes the ZWO devices in every build`, `Builtin catalog - register_builtin_factories makes the ZWO devices available only when built`). The refusals keep their texts: a missing index or id, an unknown `switchType`, a `gpioChip` or `devicePath` that is not the board's, an ASIAIR port line that is missing, foreign or repeated, and the telescope's connection type and endpoint rules (tests `Builtin catalog - ZWO normalize keeps the arms' refusals and texts`, `Builtin catalog - ZWO telescope connection type and endpoint rules`). `GET /management/v1/devicecatalog` now lists the five `zwo` descriptors, and a saved ZWO entry keeps only the fields its device type declares (a filter wheel drops a stale `focuserIndex`; test `Builtin catalog - ZWO sanitize keeps the declared fields per device type`). An ASIAIR `ports[]` entry that is not an object now reads as an entry with no `gpio` and is refused with "ASIAIR port entry requires integer 'gpio'". An RK3568 `ports[]` entry that is not an object, which the old arm skipped, now becomes a default-named "Port N" port (test `RK3568 null port entry keeps its position`). `scripts/check_layering.py`'s AlpacaHTTP vendor-include baseline drops from 13 to 6.
