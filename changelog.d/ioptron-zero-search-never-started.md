### Fixed
- **iOptron HAE29C FindHome** (AlpacaCore): a zero sensor search that the mount never starts no longer runs for the whole 120 s bound. In a Wi-Fi ConformU run the HAE29C ignored `:MSH#` and read status 0 for 120 s, and then FindHome failed. A running search reads status 2 (HAE29C traces over USB and Wi-Fi). So past the 5 s hold, a status that is neither 2 nor 7, with no status 2 seen since `:MSH#`, now sends `:MSH#` once more from the Slewing or AtHome read that watches the search (never from an initiator's own status read), with its own 5 s start grace that MoveAxis cannot cut short. If the second search does not start either, the driver stops it at once with a "did not start" error that Slewing raises.
- **iOptron HAE29C FindHome response time** (AlpacaCore): FindHome on a zero-search model no longer reads the mount status before it sends `:MSH#`, unless a search is already running and may need its overdue stop. The search ignores the at-home status. Right after ConformU's AbortSlew and Tracking writes the HAE29C took 0.8 s over USB and 1.36 s over Wi-Fi to answer that read, and FindHome came in at 0.94 s and 1.40 s against its 1 s target.
- **iOptron HAE29C ConformU over Wi-Fi** (AlpacaCore, docs): issue #2424. ConformU 4.6.0-rc.1 passed over Wi-Fi on the build with these fixes (0 errors, 0 issues, 0 timing violations; FindHome 0.052 s), with ConformU and AlpacaBridge on a StellaVita CM4 and the mount on the board's own access point (TCP port 8899). The report is `AlpacaCore/conformu/iOptron/HAE29C/Linux-arm64-wifi.txt`, and `SUPPORTED-DRIVERS.md` lists the HAE29C as USB/Serial and Wi-Fi.
