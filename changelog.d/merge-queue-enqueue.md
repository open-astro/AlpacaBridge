### Fixed (tooling)
- **`/pr-checker` and `/submit-pr` add a PR to the merge queue with GitHub's `enqueuePullRequest` call** (`.claude/commands/pr-checker.md`, `.claude/commands/submit-pr.md`): they said `gh pr merge --merge` would queue a PR into `main`, but with a merge queue required `gh` turns on auto-merge instead, and the repository has auto-merge off, so the call failed with "Auto merge is not allowed for this repository" (PR #1961). The skills now queue the PR with the GraphQL mutation only after a one-pass check finds an approval on the PR's current head, pinned to that head, and say not to turn auto-merge on, since an auto-merge PR can land before the review verdict. A PR into `stable/X.Y`, which has no queue, still merges with `gh pr merge --merge`, and a merge-down into `main` now goes through the queue like any other PR into `main`.
