### Added

- **OnStep: a Switch device for the controller's auxiliary features** (OnStep driver, web UI, issue #2222): an OnStepX controller's auxiliary features (power switches, PWM outputs, dew heaters) can be added as one **OnStep** Switch device, with the telescope's connection fields (Auto-Detect with the mount index, Serial, Network). It shares the controller's one serial port or TCP connection with the telescope, the focusers and the rotator, connects and disconnects on its own, and a lost link reaches every device on it (decision 0009). Connect refuses OnStep 4.x ("requires OnStepX firmware") and reads the feature slots (`:GXY0#`, `:GXY<n>#`): switch ids 0..N-1 are the included slots in slot order, under the firmware's names, fixed until the next connect. An on/off output is a 0/1 switch, a PWM output 0-255, a dew heater a 0/1 enable; intervalometers and hidden switches are left out, and an unknown purpose is left out with an INFO line naming the slot. Values are polled with `:GXX<n>#` (the first field; power telemetry is not read), so a change in the OnStepX web page shows in the client. Every switch is writable with `:SXX<n>,V<v>#`, a value outside the range is `InvalidValue` with nothing sent, a refusal reports its `:GE#` reason, and nothing is async. Fake-tested only; the ConformU Switch check on an OnStepX rig is tracked in #2126. This is the last slice of #2214.

### Changed

- **Switch DeviceState TimeStamp** (issue #2222): `SwitchDriver` gains the `device_state_age()` hook the focuser, rotator and telescope bases have (decision 0010). The existing switch drivers do not use it, and their output is unchanged.
