### Added
- **iOptron iGuider guide camera** (AlpacaCore, AlpacaHTTP): a new Camera driver for the iOptron iGuider 1 (USB 0130:1466), a 1280x960 mono UVC guide camera, chosen in the web UI as the vendor "iOptron iGuider" so it is never confused with the iCAM imaging cameras. It talks to the kernel's V4L2 driver with no vendor SDK, streams continuously from connect to disconnect the way the vendor's Windows driver does (a stopped iGuider often will not restart), maps exposures onto the camera's 12 steps from 0.01 to 3.5 s, exposes Gain 0 to 13, crops subframes in software, and has no ST-4 port, so guide pulses go to the mount. Because a control write reaches the camera's frames up to four frames late (measured on hardware), an exposure uses the 4th frame after any setting change. A stall latches a link fault that the next frame clears; an unplug, or a fault that stands for 30 s, drops `Connected` until the client connects again (decision 0009). An optional device path pins one camera; blank finds the first iGuider. The `.deb` now adds the service user to the `video` group for `/dev/video*` access. ConformU 4.5.2 validated on a Raspberry Pi CM4: 0 errors, 0 issues, 0 timing issues.

### Added (tests)
- **iGuider driver cases over a V4L2 fake** (AlpacaCore): the required driver cases plus connected cases (streaming at connect, exposure rounding and ticks, frames taken only once a new exposure has reached them, subframe crop, gain mapping, supersede, stall fault and recovery, link loss on an unplug and past the staleness bound, relink, failed connects) over `FakeIGuiderV4L2` behind `LockedIGuiderV4L2`, a `[stress]` registration, contract-sweep tier 1 and tier 2 entries, and HTTP round-trip and device-path refusal pins.
