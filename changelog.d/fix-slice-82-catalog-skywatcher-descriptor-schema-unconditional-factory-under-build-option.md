### Changed
- **Device catalog: the Sky-Watcher direct (motor controller) telescope is the first catalog-driven telescope** (AlpacaCore/AlpacaHTTP, issue #744; `AlpacaCore/src/vendors/skywatcher/skywatcher_fields.h`, `skywatcher_schema.cpp`, `skywatcher_catalog.cpp`, `AlpacaCore/src/catalog/builtin_catalog.cpp`, `AlpacaHTTP/src/http/router.cpp`, `scripts/check_layering.py`): the vendor's twelve config fields, its source rules and its factory move out of the router into a descriptor, the schema compiled in every build and the factory only under `ALPACACORE_ENABLE_SKYWATCHER`, and the router loses one more vendor include (layering baseline 38 to 37). The API still refuses a config with no site, an unknown `connectionType` or an empty port path or host with the same text, a saved config with no site still logs the same #274 WARNING and registers, and auto-detect still resolves at connect (#659). Three client-visible changes: an out-of-range site is refused as "siteLatitude is out of range (min -90) (max 90)" (was "siteLatitude 200.000000 is out of range: must be between -90.000000 and 90.000000 degrees"); a saved config's unknown `connectionType`, empty endpoint or out-of-range site is logged through the catalog's "config normalized" wording; and a saved config keeps every declared field whatever the connection type (decision record 0004: a serial config keeps `host`/`udpPort`, a network config keeps `portPath`; `tcpPort` still drops). A fractional `baudRate`, `udpPort`, `mountIndex` or `responseTimeoutMs` (9600.5) is now refused as the wrong type instead of being truncated; for saved entries, see Breaking changes.
