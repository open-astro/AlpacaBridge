### Fixed

- **Parallel `imagearray` GETs no longer each fetch and encode the frame, and builds run one at a time** (Camera, issue #1716): GETs for the same camera and encoding that arrive while a build is running share it, so `get_image_array()` is called once and each response still carries its own ClientTransactionID and ServerTransactionID; image builds are capped at one at a time and later requests wait. A StartExposure, AbortExposure, StopExposure, Connected, Connect or Disconnect PUT on the camera ends sharing, and nothing is kept after the build, so a later GET always reads the current frame. Covered by `test_routing.cpp` (parallel JSON, ImageBytes and error GETs call the getter once and match a lone request byte for byte; a GET after StartExposure or AbortExposure gets the new frame).
