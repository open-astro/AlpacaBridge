### Fixed
- **Camera: "Image not ready" answers no longer logged at ERROR** (AlpacaCore, AlpacaHTTP, issue #1167): reading `ImageArray` or `ImageArrayVariant` before any exposure, or while one is still running, gets the `InvalidOperation` that ICameraV4 requires, and the router logged every one at ERROR, so a normal client poll looked like a server fault. `AlpacaException::asked_too_early()` now flags these answers and the router logs them at DEBUG. The ZWO, QHY, ToupTek (and Altair), SVBONY, Player One and GPhoto camera drivers use it at each "no image yet" throw site. An `InvalidOperation` that reports a fault ("Exposure stopped during image retrieval", "Exposure start is in progress", a setting refused mid-exposure) is still logged at ERROR. The error code and message sent to the client are unchanged.

### Added (tests)
- **"Image not ready" log level** (issue #1167): a tier-2 contract-sweep case over every camera fake (ImageArray before any exposure is a flagged `InvalidOperation`), mid-exposure cases for ZWO, SVBONY and QHY, an `AlpacaException` unit case, and a routing case that checks the router logs the flagged answer at DEBUG and an unflagged `InvalidOperation` at ERROR, with the response unchanged.
