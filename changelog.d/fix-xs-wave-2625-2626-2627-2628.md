### Changed
- **zizmor updated to 1.33.1** (CI), issue #2625: the workflow audit job and pre-flight install the 1.33.1 arm64 release, checksum-pinned. The release fixes an audit failure on a `services:` clause written as an expression. Its new `unsafe-checkout` audit flags the review bot's fork-head checkout in `claude-review.yml`, which is label-gated and only read; that line now carries an inline `zizmor: ignore[unsafe-checkout]`, like the workflow's `dangerous-triggers` ignore.

### Fixed
- **Cameras: a second geometry write after an exposure is no longer refused while the exposure's body returns** (AlpacaCore, every camera on `CaptureSession`), issue #2627: a body that had published its frame still counted as "returning" once a BinX or NumX write dropped that frame, so the next write (BinY, NumY) failed with "cannot change camera settings during an exposure" until the body thread finished. A body that published its frame no longer locks the settings; a cancelled or failed body still does.

### Fixed (tooling)
- **Falsified-by gate accepts a lone `- None` bullet** (CI), issue #2626: a PR that adds or renames no test case can write `- None` (or `- None: <reason>`) under `## Falsified by`; `scripts/check_falsified_by.py` reads it as no cases, and refuses it beside a case line.

### Fixed (tests)
- **SkyWatcher limits: the floor-before-first-sample case waits for the start command, not a sampled run state** (issue #2628): on a loaded host the guard could start and stop the axis between two samples, so the case never saw it running. It now waits for the `:J` the fake counted.

### Added (tests)
- **CaptureSession: a dropped frame does not lock the settings while its body is still returning** (issue #2627): one test case.
