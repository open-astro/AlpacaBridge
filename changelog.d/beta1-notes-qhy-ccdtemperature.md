### Added (tooling)
- **Beta pre-releases carry the arm64 `.deb`** (release process, `release.yml`, `docs/beta-channel.md`, `docs/development.md`): a new `beta-deb` job, run only for a `vX.Y.Z-beta.N` tag, builds the package with `scripts/build_deb.sh` in a Debian trixie container on the arm64 runner (installing `debian/control`'s Build-Depends through `apt-get build-dep ./`) and attaches `alpacabridge_X.Y.Z-beta.N_arm64.deb` and its `.sha256` to the pre-release, so a tester can install a named beta with `sudo apt install ./<file>` before or without the apt `beta` component. The asset takes the tag spelling because GitHub does not keep the Debian `~` in a file name; dpkg reads the version from the package. A `workflow_dispatch` dry run of a beta tag also builds the `.deb` and uploads nothing. Stable releases stay notes-only, with the `.deb` on apt.openastro.net alone. The 5.0.0-beta.1 notes and the beta guide describe the hand install. `/bump-release` Step 6 says a beta run takes several minutes, checks the two assets before the beta is announced, re-runs a failed `beta-deb`, and builds and uploads the `.deb` by hand when the Release itself had to be created by hand.
