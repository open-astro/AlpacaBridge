### Added (tests)

- **iOptron iEFW, iEAF and iMate PowerBox stress runs connected**, iOptron drivers, issue #1068. The three `[stress]` registrations used to fail every connect, so only the failed-connect path was stormed; each now connects over a fake before the storm (`REQUIRE(settle_connected(...))`), runs the connect/disconnect/operate storm, and has a racing-disconnect case (`connect_then_disconnect_settles_disconnected` and both `connected_then_connect_disconnect_settles_disconnected` routes) and a destruction-during-connect case. The iEAF uses `FakeIoptronIeaf`, the iEFW a pty fake in `AlpacaCore/tests/test_ioptron_concurrency_stress.cpp`, and the iMate a `FakeGpio` in `AlpacaCore/tests/test_ioptron_switch_concurrency_stress.cpp`. The only product change is a test seam: the iMate wrapper now reaches libgpiod through `IoptronGpioBackend` (`create_ioptron_switch(..., IoptronGpioBackend&)`); the default backend runs the same libgpiod calls in the same order.
