### Changed
- **OnStep telescope moved into the device catalog** (AlpacaCore, AlpacaHTTP): the schema (`onstep_schema.cpp`, every build) and factory (`onstep_catalog.cpp`, only under `ALPACACORE_ENABLE_ONSTEP`) replace the router's register arm, its sanitize branch and its driver include. The vendors-OFF text stays "OnStep support not enabled. Rebuild with -DALPACACORE_ENABLE_ONSTEP=ON", the API still refuses an unknown connection type with "Invalid connection type. Use 'auto' or 'serial'" and an empty serial port with "Serial port path is required", and a saved unknown connection type is still read as `serial` (test `Builtin catalog - OnStep normalize accepts '', auto and serial, and refuses network from the API`). The auto-detect factory still constructs without a scan (the scan runs at connect). `GET /management/v1/devicecatalog` now lists the `onstep` telescope descriptor. A saved config keeps its `portPath` and `baudRate` even when its connection type is unknown, and an out-of-range `siteLatitude` or `siteLongitude` sent through the API is now refused with the catalog's "siteLatitude is out of range (min -90) (max 90)" text instead of "siteLatitude 200 is out of range: must be between -90 and 90 degrees". `scripts/check_layering.py`'s AlpacaHTTP vendor-include baseline drops from 32 to 31.
