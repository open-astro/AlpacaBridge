### Fixed

- **Celestron NexStar: Name, Connected, RightAscension and the other getters no longer wait behind a mount exchange** (Celestron, issue #1437): the whole NexStar driver now exchanges with the mount under the protocol wrapper's per-link lock with the driver state lock free: connect and disconnect (under a transition lock no getter takes), the FindHome dispatch and completion check, slew, park, sync, abort, MoveAxis, pulse guide, `set_tracking`, `set_guide_rate`, site and time writes and `CommandString`. A getter returns at once instead of waiting one exchange timeout. The safety stop still goes out on the third failed FindHome check, and a failure stop (FindHome poll, Slewing poll) is skipped when a new motion command has taken the mount first, so it cannot cut that motion short ("the failure stops are skipped when a new goto took the mount first"). A stop that finds an initiator busy without a new motion (a sync, a pulse guide) stays pending and the status poll sends it once the lock is free ("the failure stops still go out when a sync held the initiator lock"); an Unpark with no park in flight, and a motion command that fails before anything goes out, leave it pending too ("the failure stops still go out after an Unpark", "the failure stops still go out when an async goto fails before it is sent", "the failure stops still go out when Park cannot start its body", "the failure stops still go out when a sync follows an async goto that was not sent"). A slewing read taken while a newer motion command (AbortSlew) took the mount is not applied, so Slewing stays false after the abort ("a read that lands after AbortSlew is not applied"). A connect that fails after the port opened closes it again and leaves Connected false ("a failed time write closes the link and leaves Connected false"). Covered by the `[iolock]` cases in `test_celestron_telescope.cpp`.
