### Fixed
- **A stored UniqueID is never replaced** (AlpacaHTTP router, issue #1507): the router kept only version 4 UUIDs, so a ZWO camera's stored `ZWO_UID_<hex>` was replaced by a new GUID on the first start and on `configuredevice`, against the Alpaca rule that an assigned UniqueID never changes. A stored or client-sent ID is now kept when it is a GUID or printable ASCII of 12 to 128 characters that is not a device-number ID (`SkyWatcher_0`), and no other entry holds it (`Unique id - a stored ID is kept when it is a GUID or a long non-slot string`, `every configured device gets a persisted GUID as its UniqueID`, `a stored entry gets a GUID once at load and keeps it across restarts`). Only an entry with none, a device-number ID or a duplicate gets a GUID, once. Decision 0018 is amended.

A ZWO camera with a readable serial used to report `ZWO_SN_<serial>` even when its entry stored a `ZWO_UID_<hex>`. It now reports the kept stored value, so that camera's UniqueID changes once from the serial-based value (to the stored `ZWO_UID_`, or to a minted GUID when none is stored), then never again.
