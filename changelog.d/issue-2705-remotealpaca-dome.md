### Added
- **remotealpaca: Dome of an upstream Alpaca server** (AlpacaCore, AlpacaHTTP, web UI, issue #2705, slice 5 of #1753): the "Remote Alpaca" vendor now also serves the Dome device of another Alpaca server as a device of this server, the first Dome driver in AlpacaBridge, with the same four settings (upstream host, port, device number, poll period) and the same Connect, snapshot and link rules as the other proxied devices. `Slewing`, `Azimuth`, `Altitude`, `AtHome`, `AtPark`, `ShutterStatus` and `Slaved` answer from the poll's snapshot; the eight `Can*` capabilities are read once at Connect and keep answering while the link is faulted. The poll skips a member whose capability the upstream reports false and serves the Connect's one answer for it, so a poll makes 1 to 7 calls. The slews, `FindHome`, `Park`, `SetPark`, `SyncToAzimuth`, the shutter commands and the `Slaved` write are forwarded in the command slot; a command writes only its in-progress state through (`Slewing` true, `ShutterStatus` Opening or Closing), and only a later poll says the dome has stopped. A slew or shutter command whose reply is lost reads its in-progress state too, as the upstream may have acted, and `SyncToAzimuth` reads the synced `Azimuth` back from the upstream. From the start of a Disconnect no command but `AbortSlew` reaches the upstream, also one queued behind a running command. `AbortSlew` is forwarded even while the link is faulted or a Disconnect runs, and writes nothing, as the dome may coast. While the link is faulted the frame getters and every other command throw `DriverException`, so a link lost mid-slew never reads `Slewing` false. `DeviceState`'s `TimeStamp` is the frame's age (the Dome base gains `device_state_age()`, as the Rotator base has). Built under `ALPACACORE_ENABLE_REMOTEALPACA`; fake evidence only, ConformU against the simulators is a rig step.
