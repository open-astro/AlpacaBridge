# Snapshot-served state: adoption

The roster of [decision 0010](../decisions/0010-snapshot-served-state.md). It is kept out of the record so a PR that
adds or changes a row needs no `ADR authorized` comment; `scripts/check_docs_drift.py` check 23
compares it with the code.

## Adoption

The roster of drivers that serve polled telemetry from a snapshot. The Symbol column names what the driver's source uses for it: `PolledState` once the driver composes `util::PolledState` (rule 7), `StateSnapshot` where it holds the snapshot itself. Sky-Watcher and ZWO stay on `StateSnapshot` (evaluation on #2490): the Sky-Watcher fault latch, 30 s loss verdict and recovery epoch live in its protocol wrapper and count every exchange, so the module's poll-fed latch would be a second latch; the ZWO telescope publishes in stages, judges loss from the last mandatory RA/Dec sample, and pauses the poll for guide pulses with the loss clock running from the pulse end. The Decision section of [decision 0010](../decisions/0010-snapshot-served-state.md) records the Sky-Watcher, Celestron, Bisque, OnStep, Celestron CGX and iOptron telescope choices; each other driver's per-getter choices are owned by its instruction file. `scripts/check_docs_drift.py` check 23 holds the roster to the code.
