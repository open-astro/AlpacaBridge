# AlpacaBridge 5.0.0-beta.1

This is a beta. It is for people who want to try the next release early and tell us what breaks, so only install it on a rig where a problem tonight is acceptable. Version 5.0 tightens how every mount, camera and rotator follows the ASCOM rules, adds alignment and safety-limit settings for Sky-Watcher, SynScan and Celestron mounts, and fixes a long list of problems found at the telescope.

## Read this first

Some changes in 5.0 can stop a setup that worked on 4.2.0. Check each one that matches your gear before you upgrade.

- **Mounts: the old "wait until the slew ends" commands are gone.** Clients must use the normal slew commands that return at once and then watch for the slew to finish. NINA, PHD2 and other current apps already do this. If an older script or app stops slewing after the upgrade, this is why. For the same reason, mounts now report `CanSlew` and `CanSlewAltAz` as false.
- **SynScan mounts must be tracking before a GoTo.** Turn tracking on in your app before you slew.
- **SynScan mounts need a site latitude to track.** Set your latitude in your app or in the web UI device settings.
- **SynScan AZ-EQ5 and AZ-EQ6: pick how the mount is set up.** The handset cannot tell AlpacaBridge whether you are running in Alt-Az or equatorial mode, so tracking is refused until you choose. In the web UI, edit the device and set **Alignment Mode** to Alt-Az or Equatorial.
- **iOptron mounts: a GoTo the mount refuses now fails.** AlpacaBridge used to quietly lower the mount's altitude limit and change its meridian setting to force the slew through. It no longer touches either setting. If a target you could reach before is refused, change the limit on the hand controller or in iOptron Commander yourself.
- **QHY cameras report missing values as missing.** Heat sink temperature, electrons per ADU and full well capacity now return an error instead of a made-up number, and so does sensor temperature on a camera without a sensor. Stop Exposure is gone; use Abort, which keeps a finished frame. Exposures longer than the camera's maximum are refused. Reading the image during an exposure now fails at once instead of waiting up to 60 seconds, so read it only after the camera reports the image is ready. Most imaging apps handle all of this already.
- **Paramount (TheSkyX) guide pulses are limited to 30 seconds.** Longer pulses are refused.
- **A camera frame with bad geometry now returns an error** instead of an empty or cut-off image. If you see this, check the camera's subframe and format settings.
- **A failed connect now looks like a failure to your app.** It used to report success after 8 seconds while the connect was still running. Now your app waits until the connect actually finishes, up to 60 seconds, and gets the real reason if it fails. If your app gives up sooner than that, raise its connect timeout.
- **ZWO cameras keep one unique ID.** AlpacaBridge now tells ZWO cameras apart by their serial number. 4.2.0 reported the serial-number ID only while a camera was connected, and a different ID (`ZWO_` and the device number) while it was not. 5.0 reports the serial-number ID either way, so if an app saved a camera's ID while it was disconnected, the app may ask you to pick the camera again. A camera whose serial number cannot be read gets a fixed ID that AlpacaBridge stores for it. If a saved camera is unplugged or replaced, connecting to it now fails with a message naming the missing serial instead of quietly opening a different camera.
- **Some saved devices may not load after the upgrade.** Check the Devices tab after upgrading. A device that says it failed to load needs to be added again or re-saved from the web UI. This affects:
  - **ZWO ASIAIR, iOptron iMate and ToupTek StellaVita power ports** saved with power-port settings the board does not have. The form now only offers the board's real values.
  - **Sky-Watcher, Celestron, Paramount, SVBONY, Player One, Canon/Nikon and WeeWX devices** saved with a decimal or true/false in a whole-number field, such as a baud rate of `9600.5`. Re-save with a whole number.

## New gear you can plug in

- **ZWO ASI294MC Pro** has been tested end to end and is confirmed working.

## Things that just work better

- **See at a glance which devices are connected.** The Devices tab shows a dot in front of each device: green when it is connected and answering, yellow when it is set up but not connected, red when something is wrong. Hover over it to see why.
- **Sky-Watcher direct: altitude and meridian limits.** Two new optional settings stop a GoTo below a minimum altitude, and stop manual moves and tracking when the scope crosses the altitude floor or goes past the meridian limit. Both are off until you set them. Set the altitude limit at least 3 degrees above your real clearance.
- **Sky-Watcher direct: Dec direction setting.** If your board is new to AlpacaBridge and the Dec axis homes the wrong way, a new **Dec axis sense** setting lets you flip it. The device name in the web UI shows where the current setting came from.
- **Celestron forks on a wedge** can now be told they are equatorial with the new **Alignment Mode** setting, so they track and report correctly.
- **SynScan GoTos land closer.** After a slew, AlpacaBridge checks where the mount ended up and nudges it until it is within a few arcseconds of the target, up to three times.
- **Rotators remember their sync.** On WandererAstro and ZWO rotators, the angle you sync to is kept across reconnects and restarts.
- **Camera downloads are faster and use less memory.**
- **Optional protection against malicious web pages.** A new **Restrict Host names** setting in the web UI blocks a known trick that lets a hostile web page reach AlpacaBridge through your browser. It is off by default. If you turn it on and open the web UI by a name such as `astropi.lan`, add that name to **Allowed host names** in the same place.

## Fixes worth knowing about

- **ZWO cameras no longer swap places after a restart.** With two or more ZWO cameras, a reboot could change the order the cameras were found in and hand your app the guide camera instead of the main camera. Each saved camera now finds its own camera by serial number, and editing the camera in the web UI keeps that link. A camera whose serial number cannot be read is matched by model instead.
- **SynScan: RA and Azimuth were wrong in precise mode** and raced through 24 hours on a still mount. Fixed.
- **Sky-Watcher direct: another program opening the mount's serial port** could knock out the link. AlpacaBridge now holds the port for itself, and a link that went quiet recovers on its own.
- **Sky-Watcher direct: the connection could freeze** on some USB serial adapters when the mount went quiet, hanging every request until the service was restarted. Fixed, along with the same hang during auto-detect.
- **Sky-Watcher direct: guiding and tracking now agree.** Turning tracking on or off during a guide pulse could leave RA running or stopped the wrong way. Fixed in every case we found.
- **Sky-Watcher direct: a manual move or sync during a guide pulse** could leave the other axis turning. Fixed.
- **ZWO mounts: Park, Home, manual moves and Abort right after a GoTo** could be overtaken by that GoTo and slew the mount away. They now cancel it first.
- **ZWO mounts: stopping one axis no longer stops the other.**
- **iOptron mounts: Abort now always stops the mount,** even after a few communication errors, and a queued GoTo can no longer start after Abort returns. Occasional read errors spread over a night no longer lock the driver up.
- **OnStep, Celestron and SynScan: a stop that failed was reported as stopped.** Now your app is told the mount may still be moving.
- **SynScan: an Abort whose tracking restart failed** left the mount reported as slewing after it had stopped. It now reports stopped, and your app gets the tracking error.
- **Celestron and SynScan: guiding and slews no longer get mixed up** when one interrupts the other, and a slew that was cancelled no longer reports success.
- **Paramount (TheSkyX): a connect that timed out blocked every later connect** until the service was restarted. Fixed. A slow reply no longer throws every later reply out of step, and Abort no longer freezes the driver while a guide pulse runs.
- **Gemini focuser and flat panel: a slow reply** could be read as the answer to the next command. Fixed.
- **Gemini PDH Advanced 3: unplugging it** made AlpacaBridge use a whole CPU core. Fixed.
- **ZWO ASIAIR Pro and Plus: a dew heater port at partial power** was sometimes left off when you disconnected. It now stays on.
- **QHY cameras: changing binning during an exposure** froze the camera until the frame ended. It now fails at once. A failed exposure is now reported to your app instead of looking like a frame that never finished.
- **QHY cameras: the sensor temperature right after connecting** gave an error until the first background reading came in. It is now read once while connecting, so your app sees a temperature at once.
- **QHY filter wheel: a failed move** no longer shows "moving" forever.
- **WandererAstro rotator: a move with no power** no longer claims it arrived.
- **WeeWX weather:** a few readings now follow the ASCOM rules more closely.
- **Wi-Fi: networks with unusual names** broke the Wi-Fi scan. They now show up and can be joined.
- **Saving a setting in the web UI** no longer deletes the help comments in your config file or adds a duplicate line.
- **Network discovery** now always advertises the right port and ignores packets that are not Alpaca discovery requests.
- **The server is harder to overload or confuse** from the local network. Requests are now limited to 64 KB, down from 10 MB, which no Alpaca app comes near; a script that posts very large requests to the management API would now be refused. Log lines are cleaner too.
- **Behind the scenes:** many more automated tests, stricter checks before each release, and the new beta channel itself.

## Upgrading

Install this beta by hand. The apt `beta` channel is not open yet, so `apt upgrade` still gives you 4.2.0.

1. Download `alpacabridge_5.0.0-beta.1_arm64.deb` and `alpacabridge_5.0.0-beta.1_arm64.deb.sha256` from the Assets of this release.
2. Check the download, then install it:

   ```sh
   sha256sum -c alpacabridge_5.0.0-beta.1_arm64.deb.sha256
   sudo apt install ./alpacabridge_5.0.0-beta.1_arm64.deb
   ```

Do not add `beta` to your apt line yet, and do not change `update_packages_url`. Both point at a channel that does not exist yet: apt warns about the missing component, and the web UI update card finds nothing.

Afterwards, open the Devices tab, re-add any device that failed to load, and go through the "Read this first" list for your gear.

**To go back to 4.2.0**, ask apt for that version by name. apt does not downgrade on its own, so it needs the extra flag:

```sh
sudo apt update
sudo apt install --allow-downgrades alpacabridge=4.2.0
```

When the stable 5.0.0 release comes out, a normal `apt upgrade` moves you onto it.
