# AlpacaBridge 6.0.0-beta.1

This is a beta. It is for people who want to try the next release early and tell us what breaks, so only install it on a rig where a problem tonight is acceptable. Version 6.0 adds Altair cameras, direct USB for the Celestron CGX and CGX-L, the Celestron focus motor and the iOptron iFR and iGuider, makes every driver report a failure as a failure, and fixes a long list of problems found at the telescope.

## Read this first

6.0 is a major release, and some changes can stop a setup that worked on 5.0.2. The common thread is that AlpacaBridge used to guess, or repeat an old value, where it now reports an error. Current imaging apps cope with most of this, but sequences and scripts may not. Check each item that matches your gear before you upgrade.

**Every setup**

- **Your imaging app sees your devices as new, once.** The first start gives most saved devices a new permanent ID and rewrites the saved device file. Apps that remember devices by ID, such as NINA equipment profiles, will need you to pick each device again. A ZWO camera that already has a stored ID keeps it. Rotator sync offsets move across on their own.
- **A lost device now reads disconnected, and stays that way until your app connects again.** A pulled cable usually shows at once. A device that goes silent with the cable still in shows as disconnected after 30 seconds. This applies across mounts, cameras, focusers, filter wheels and rotators. Nothing reconnects on its own, so an unattended sequence stops unless your app reconnects.
- **Short dropouts now show as errors.** After three failed reads, many devices answer "communications compromised" until a good read clears it, with no reconnect needed. A sequence set to stop on any error will stop.
- **Apps get an error instead of a made-up value.** Examples are electrons per ADU, full well capacity and sensor name on cameras that cannot report them, percent complete outside an exposure, and cooler values on a camera with no cooler. A device whose reads all fail now returns an empty device state. Reads on a disconnected device report that it is not connected.
- **Check the Devices tab after upgrading.** A device that failed to load shows a red card in the web UI, and your apps no longer see it at all. Open it to fix or remove it. This affects:
  - **SynScan and QHY devices** saved with a decimal or true/false in a whole-number field, such as a baud rate of `9600.5`. Re-save with a whole number.
  - **WeeWX devices** with a timeout above 60000 ms. Lower it.
  - **Gemini Power and Data Hub** entries with no port or a negative hub index. Fix the port or index.
  - **QHY CFW3, Gemini hub and WandererAstro** entries saved as serial with no port. They now stay listed, and connecting names the missing port. Set the port.
- **Each address can hold 32 connections.** Extra connections are closed with no response, and so is a client that stalls for 30 seconds. Almost nobody will notice. If you do, raise `http.max_connections_per_ip`, or set it to 0 to turn the limit off.
- **Check your config file.** A port written as `6810.0` or `6810x` used to load as 6810. It is now rejected and the server uses 6800, so write a plain number. A log line saying `Ignoring http.port` means this happened. A config path that cannot be read now stops the server instead of starting on defaults.
- **Log files now split at 5 MiB.** A day's log can be several files, and the oldest part goes past the 20th, so a very heavy day loses its earliest lines. The log viewer shows the parts. Anything that collects one daily file must read them all. The log download is capped at 32 MiB and builds one at a time, so older days may need downloading on their own.
- **Scripts that call AlpacaBridge directly may need changes.** A missing or badly formed parameter now gets an HTTP 400 with a plain text message, not a 200 with an error number. Whole-number parameters must be whole numbers. The `mount` path, `dome canslew` and `observingconditions seeing` are gone, as they were never part of the Alpaca standard. Use `telescope` for the first. Switch `cancelasync` now reports not implemented. The configured devices list and `apiversions` answer only `GET`, and failed devices have moved to their own list at `/management/v1/faileddevices`.
- **Image Array Variant no longer returns pixels, on any camera.** Use Image Array or ImageBytes. Current imaging apps already do.

**All mounts**

- **Turn tracking on before an equatorial slew.** Sky-Watcher direct, Paramount, Celestron NexStar, iOptron, ZWO AM and OnStep now refuse the slew with tracking off, as SynScan did already. Remember this after Park, Unpark and Find Home. Most imaging apps do it for you.
- **iOptron and OnStep: turn tracking off before an Alt/Az slew.** It is now refused while tracking.
- **A failed slew, Park or Find Home now stays reported** on Celestron, SynScan, Sky-Watcher, OnStep, Paramount and ZWO. Your app sees the error until the next command or a reconnect. A Celestron or SynScan Park that misses by more than 600 arcseconds now fails instead of reporting parked.
- **Site elevation reads as unset until something sets it,** because 0 m is a real place. On ZWO and Sky-Watcher direct, enter it in the device form in the web UI. On Paramount, NexStar, SynScan, iOptron and OnStep, have your app write it once and AlpacaBridge saves it.
- **Refraction now reports "not implemented"** on Paramount, NexStar, iOptron, SynScan, Sky-Watcher and ZWO, because these drivers never applied any. OnStep still reports what its firmware does.
- **The mount's date and time no longer fall back to the host clock.** On SynScan, iOptron, ZWO AM and OnStep, a clock that cannot be read now gives an error until your app writes the time or time sync at connect succeeds. A Sky-Watcher direct time write is refused while the host clock is NTP-synced, which is the better clock anyway.

**Sky-Watcher direct**

- **Turn off NINA's "Primary Reversed" and any secondary reverse option.** Manual moves now follow the sky in both hemispheres and on both pier sides, so a reverse option would send them the wrong way.
- **Site reads give an error until the site is set.** The web UI requires latitude and longitude, so this only affects very old saved devices.
- **Adding a new mount:** SynScan and EQMOD are now one **Sky-Watcher** vendor, and **Connection** starts on the hand controller. Choose **Direct cable (EQMOD)** for a direct mount. Saved devices are not affected.

**ZWO mounts**

- **Park can now fail.** A Park the mount ignores used to report parked. On the AM3, AM5 and AM7 it now reports `Park failed` after about 5 seconds, so check the mount before treating it as safe. The AM5N, and a mount that does not answer the park query, behave as before.
- **Connect now checks it has a real AM mount.** The model and serial number must both read back, and two entries cannot claim one mount. If a connect is refused, check the driver, port or host, and that the firmware answers the serial query.
- **A replaced mount is refused until you allow it.** Save the device again in the web UI or restart the service.
- **Time does not carry over between connections.** Write the time after connecting, or turn on host time sync at connect.
- **Reads now fail when the link does.** Position, site and telemetry reads give an error rather than old values, and a lasting fault needs a reconnect.

**ZWO cameras, EAF and CAA**

- **USB Limit now defaults to 40,** so downloads may be slower. Set **USB Limit** in the camera's device form if 40 does not suit you. A value set there that the camera will not take now refuses the connect.
- **Read the image before changing binning or subframe.** A change after the frame is ready throws that frame away, and a change during an exposure is refused.
- **Abort only works while exposing.** An Abort during download is now refused, and the frame still arrives.
- **Image Ready turns true later,** after the download rather than before it. A failed exposure trigger now shows up on Image Ready and the image read, not on Start Exposure.
- **A saved camera ID outside the valid range is dropped.** An entry with no other way to find its camera stays listed and needs setting up again.
- **EAF and CAA slots:** connecting by index refuses a slot whose details cannot be read. Fix the device. Do not change the index to point at another one.
- **EAF with a stored max step of 0** connects, but every move is refused. Set **Max Step** in the device form.

**Power ports (ZWO ASIAIR, ToupTek StellaVita, iOptron iMate)**

- **Connect no longer turns ports on.** On ASIAIR Pro, Plus CM4, StellaVita and iMate, ports now stay as the board left them. To power them at boot, add the `gpio=` line from the [power ports guide](https://github.com/open-astro/AlpacaBridge/blob/main/AlpacaCore/PowerPorts.md), or set **At server start** to **Restore the last setting** in the device form and turn the ports on once.
- **ASIAIR Plus PWM ports** no longer come on at connect, so a dew heater that relied on that stays off. Set the port from your app or use **At server start**.

**QHY**

- **Connect fails if the exposure range cannot be read,** instead of guessing limits.
- **A failed mode change or configuration now shows.** Exposure limits, gain, offset and binning limits give an error until you retry successfully or reconnect. While a readout mode change runs, exposure limits give an error, so retry once it finishes.
- **A new connection waits for cooler shutdown to finish.** Retry after it does.

**Cameras from several brands**

- **Frames past their deadline are now failed exposures** on QHY, Canon and Nikon, ToupTek and Altair. Start a new exposure rather than waiting for a late frame.
- **Player One, iCAM, ToupTek and Altair: starting an exposure during an exposure is refused.** Abort or wait for the frame first.
- **ToupTek and Altair: the last-exposure values give an error until an image succeeds,** and only a new exposure or a reconnect clears a failed one.
- **ToupTek and Altair: turn the cooler off before the fan.** Fan speed 0 is refused while the cooler runs, because it was silently stopping the cooling.
- **Player One: percent complete gives an error during download.** There is now a Download state during readout.

**Focusers and rotators**

- **A focuser move past either end now goes to that end,** where it used to be refused. This affects the iOptron iEAF, iAFS and iFR, QHY Q-Focuser, ToupTek AAF and ZWO EAF. A bad position in a script becomes a real move, so keep positions in range.
- **A rotator Sync that cannot be saved now fails** on WandererAstro and ZWO, rather than losing the offset at the next restart.

**Celestron NexStar**

- **Guide pulses are limited to 25.5 seconds.** Longer pulses are refused, so split them.
- **Time reads give an error when the mount clock cannot be read.**

**OnStep**

- **Manual moves no longer stop on their own after 10 seconds.** They run until your app stops them, except near the horizon or overhead limit. Anything that relied on the time limit as a stop must send one.
- **A slew during a GoTo or homing is refused,** including one started from the handset. Wait, or Abort first.
- **Commands the mount refuses now fail** with the mount's reason. This covers Tracking, Set Park, Unpark, Sync, and Park or Find Home on a still mount. Park needs a park position set.
- **Guide pulses over 9999 ms are refused.** They used to be cut short.
- **With an unknown site,** side of pier, sidereal time and Alt/Az slews are refused. Set the site in the device form, or have your app write latitude and longitude.
- **A reconnect after 5 seconds or more out stops any motion left running,** unless the mount is parking.

**Paramount (TheSkyX)**

- **Turn on Use Computer Clock in TheSkyX,** and set the time on that computer. With it off, sidereal time, destination side of pier and the date and time give errors. Writing the time from your app is refused.
- **A slew during a Park is refused.** Abort or Unpark first.

**Gemini and WeeWX**

- **Gemini Rev2 and Pro panels:** after a failed command, cover or light state reads Error until the next command of that kind.
- **WeeWX feeds must use http or https.** Other address types now fail to connect.

## New gear you can plug in

**Altair**

- **Altair Astro cameras** have their own vendor, **Altair**. Tested on the ALTAIR178M3 and ALTAIR662M2. On an OrangePi 3 LTS use a USB 2 port, because its USB 3 port loses full frames.

**Celestron**

- **CGX and CGX-L direct USB,** with no hand controller. Pick the direct USB protocol in the Celestron device form. It covers Home, GoTo, Sync, Park, Tracking and guiding. Run Find Home before the first slew. Not yet tested on a real mount in the southern hemisphere. Guide rates of 0.25x passed our checks, while 0.5x stopped at a guiding check, and the first Dec guide pulse after a direction change can overshoot by up to about 2.7 arcseconds.
- **Celestron focus motor** on its own USB port, vendor **Celestron**. Calibrate it from the device card in the web UI.

**iOptron**

- **iFR focuser-rotator,** vendor **iOptron iFR**. One unit appears as a focuser and a rotator over one connection. Pick the 2", 3" or 4" model. Only the 3" has been tested.
- **iGuider guide camera,** vendor **iOptron iGuider**. It has no guide port, so guide pulses go to the mount.

## More hardware confirmed working

ZWO ASI178MC and ASI6200MM Pro, ToupTek G3M678C, Canon EOS 600D and the TeSeek HM-17 on OnStep all pass full ASCOM validation.

## Things that just work better

- **Pick the update channel in the web UI.** The Software Update card has an **Update channel** switch for Stable or Beta.
- **Choose what power ports do at startup.** ASIAIR, StellaVita and iMate have a new **At server start** setting: leave them, restore the last setting, or turn them off after a reboot.
- **Pick your ZWO camera from a list.** The form lists attached cameras with their model and serial number, so a camera is saved by serial. The manual index box is still there for a camera that is not plugged in yet.
- **Reads no longer wait on your gear.** Most drivers now keep a live status in the background, so a status poll answers at once even during a slow connect or a slew.
- **Reconnecting is faster on iOptron and Gemini.** Auto-detected mounts and Gemini devices remember their port and skip the 5 to 13 second search, even after a restart.
- **Replug a ZWO camera, EFW or CAA and connect once.** It reopens by serial number, with no service restart. This was checked on real cameras and an EFW. The same works on an EAF, tested in simulation only.
- **Clearer status dots.** The Devices tab now says "Idle, no client connected" or "Client connected", and a red dot names the actual problem.
- **Sky-Watcher direct: optional GoTo backlash compensation** per axis, off by default. Not available on boards that do not report a worm count, such as the Wave 100i and EQ-AL55i.
- **Canon bulb exposures beyond 30 seconds,** up to 3600 seconds on bodies with a bulb setting.
- **Nikon long-exposure noise reduction** has a new setting. It has only been tested in simulation.
- **ZWO EAF: set Max Step** from the device form. A connected EAF, EFW or CAA also shows its firmware.
- **iOptron and Celestron mounts report their GPS fix** through a new `gps_status` action. This has not yet been tried on a real mount.
- **Newer vendor libraries.** ZWO, QHY, ToupTek, Player One and libgphoto2 are all updated. Player One's update removes horizontal stripes in HDR mode on the Uranus and Xena 585M at hardware bin 2.
- **The log can no longer fill your SD card** with TRACE left on or an error looping.
- **The server is harder to knock over.** A client that stops reading can no longer tie up the server, and six image downloads at once can no longer run a 4 GB Pi out of memory.

## Fixes worth knowing about

**Mounts**

- **ZWO AM: Park did nothing on a tracking AM5** on firmware 1.8.8. Park now stops tracking first, and the mount parks.
- **ZWO AM: a slew from another client racing a Park, Find Home, jog or Abort** could leave the mount slewing afterwards. Fixed.
- **ZWO AM: Park, Find Home, GoTo and jogs could report finished too early,** and a Sync could send the wrong coordinates. Fixed.
- **OnStep: Find Home restarted tracking** and drove the mount off home. Park or Find Home sent during a jog could report success while the mount never parked. A reconnect could abort a park. All fixed.
- **OnStep: Alt/Az slews with an unknown site went to the wrong place.** They are now refused.
- **OnStep: position reads are far quicker,** down from 157 ms to 25 ms on an HM-17 at 9600 baud. A noisy line can no longer block commands for hours, and the mount's time is no longer 10 hours off with a time zone set elsewhere.
- **Sky-Watcher direct: background work could still write to the board** after a link fault or restart, including commands that could start an axis. It no longer does.
- **Sky-Watcher direct: a GoTo, Park or Find Home refused at the start** could leave the axes running. They now stop. A tracking read during a GoTo could also end the motion-limit guard. Fixed.
- **Sky-Watcher direct: Abort during a jog** turned tracking off, so later GoTos landed untracked. Tracking now comes back.
- **SynScan and Celestron NexStar: a replaced slew could reach the mount after the Abort** that replaced it. Commands now go out in order.
- **SynScan and Celestron: a Park that never reached its position** could still report parked. It now fails.
- **iOptron: a long guide pulse made the mount read as slewing,** which stopped the guider. Pulse guiding also stayed on about half a second too long, slowing PHD2 and NINA. Both fixed.
- **iOptron: Abort during a GoTo left the mount stopped,** so the next slew was refused. It now keeps tracking.
- **iOptron: with the USB cable pulled, Park, Abort and Tracking could report success.** The mount now reads disconnected at once.
- **Sidereal time moved in one-second steps** on six mount drivers and could read up to 15 arcseconds behind, which also affected hour angles and park targets. Fixed.
- **Paramount: a slow connect or failed slew check** could freeze reads or look like success. Fixed.

**Cameras**

- **ZWO: one unreadable camera stopped every other ZWO camera from connecting.** Fixed.
- **ZWO: a pulled cable left the camera reading Connected** while exposures failed with error 1280. It now drops the link and fails the exposure at once.
- **ZWO: a Stop or Disconnect could spoil the next exposure,** ending it with no image. An exposure that never finishes now ends in an error. Fixed.
- **ZWO USB 2.0 cameras such as the ASI120:** long exposures failed soon after a download, so a 10 second frame took about 20 seconds. Fixed.
- **QHY: changing the frame size after an exposure** could crop or zero-pad the finished frame. Changing readout mode with binning above 1 failed the next exposure. Both fixed.
- **QHY: a failed mode refresh could stop cooler regulation for good.** A cooler OFF could also be lost around a disconnect. Both fixed.
- **ToupTek ATR2600M: turning the fan off silently stopped the cooler.** It is now refused.
- **ToupTek and Altair: an Abort during the start of an exposure** reported success and the exposure ran on. It now takes effect.
- **Player One: starting an exposure during one silently threw away the running frame.** A disconnect and connect also left a cooled camera with its cooler off. Both fixed.
- **Canon: with mirror lock-up on, every exposure failed** after a 60 second stall. Fixed.
- **Canon and Nikon: a failed exposure now reaches your app,** rather than Image Ready staying false forever.

**Focusers, wheels and power**

- **ZWO EFW: wheels that report their details only once opened** failed every connect with "No ZWO EFW wheels detected". Fixed.
- **QHY Q-Focuser: several fixes.** Long moves tripped "communications compromised" after about 10 seconds, a unit without its 12 V supply hung the connect forever, and it read -111 C with no probe attached. Fixed.
- **QHY integrated wheel: "moving" could stay on forever.** It now fails after a deadline.
- **QHY CFW3: a failed move was only logged.** It now reaches your app.
- **Power ports read as on after a connect,** whatever the board held. They now show their real state.

**Server and web UI**

- **A crash or full disk could damage your saved devices or config.** Saves are now safe against that, and a damaged device file is kept rather than overwritten.
- **Saving a Wi-Fi profile could lose static IP or other settings.** They are now kept. A hotspot with an empty passphrase is refused.
- **A bad device number could reach the wrong device.** It is now refused.
- **Security:** the bundled Canon and Nikon library fixes eight published vulnerabilities, a WeeWX feed can no longer read local files, and update mirror passwords no longer show in status or logs. Web pages from other sites can no longer frame the web UI.
- **`alpacabridge --help` started a full server.** It now prints usage, and `--version` is new.
- **Behind the scenes:** many more automated tests and stricter checks before each release.

## Help us test

A lot of this beta has only been tested in simulation, so real reports count. Please tell us how these go on your rig:

- **Pull a cable mid-session.** Try it on a mount, focuser or flat panel, then connect again. Pulled-cable handling on iOptron, SynScan, NexStar and Gemini has not been tried on real gear.
- **Sequences running all night,** especially any that hit the new reconnect behaviour.
- **QHY Q-Focuser:** connect within 10 seconds of a move.
- **QHY integrated filter wheel:** a USB pull, which on the current library can still leave it reading connected.

Please report problems at [GitHub Issues](https://github.com/open-astro/AlpacaBridge/issues) with your log attached.

## Upgrading

Copy your saved settings first, because the first start rewrites them:

```sh
sudo cp -a /var/lib/alpacabridge/config ~/alpacabridge-config-5.0.2
```

The Software Update card on 5.0.2 has no channel switch yet, so add the beta source by hand. You do this once:

```sh
printf '%s\n' 'Types: deb' 'URIs: https://apt.openastro.net' 'Suites: trixie' \
    'Components: beta' 'Architectures: arm64' \
    'Signed-By: /usr/share/keyrings/openastro-archive-keyring.gpg' \
    | sudo tee /etc/apt/sources.list.d/alpacabridge-beta.sources
sudo apt update && sudo apt upgrade alpacabridge
```

Afterwards, the Software Update card on the Server Info tab shows **Update channel** set to **Beta**, and later betas arrive from there or through `apt upgrade`. Then open the Devices tab, fix any device that failed to load, and go through the "Read this first" list for your gear.

**Still opted in from the 5.0 betas?** Your next `apt upgrade` installs this beta. To tidy up, change the line in `/etc/apt/sources.list.d/openastro.list` back to `trixie main`, add the source above, and remove the beta `update_packages_url` line from your config, which would otherwise lock the channel switch.

**Rather install just this one beta?** Download `alpacabridge_6.0.0-beta.1_arm64.deb` and `alpacabridge_6.0.0-beta.1_arm64.deb.sha256` from the Assets of this release, then:

```sh
sha256sum -c alpacabridge_6.0.0-beta.1_arm64.deb.sha256
sudo apt install ./alpacabridge_6.0.0-beta.1_arm64.deb
```

apt does not offer the next beta to a copy installed this way. If you have the GitHub CLI, you can also check that the file was built by this project's release workflow: `gh attestation verify alpacabridge_6.0.0-beta.1_arm64.deb --repo open-astro/AlpacaBridge`.

**To leave the beta**, set **Update channel** back to **Stable**. You stay on this build until a stable release overtakes it.

**To go back to 5.0.2 now**, set **Update channel** to **Stable** first, or the next `apt upgrade` brings the beta back. Then ask apt for that version by name and put your saved settings back:

```sh
sudo apt update
sudo apt install --allow-downgrades alpacabridge=5.0.2
sudo systemctl stop alpacabridge
sudo cp -a ~/alpacabridge-config-5.0.2/. /var/lib/alpacabridge/config/
sudo systemctl start alpacabridge
```

When the stable 6.0.0 release comes out, a normal `apt upgrade` moves you onto it.
