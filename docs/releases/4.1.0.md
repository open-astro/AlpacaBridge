# AlpacaBridge 4.1.0

Three Canon bodies and another Nikon join the DSLR list, and a mount left slewing by a crashed client now stops on its own. Under the hood, a large batch of Sky-Watcher, DSLR and error-reporting fixes found on the bench and by a new cross-driver test sweep.

## Read this first

- **A mount that is slewing with nobody talking to it will stop by itself.** While a goto, park, find-home or MoveAxis is running, if no request reaches that telescope for 30 seconds (your imaging software crashed, the laptop went to sleep, the WiFi dropped), AlpacaBridge stops the axes and writes an ERROR line to the log. The mount stays connected, so you can just reconnect and slew again. This never fires on a mount that is only tracking or guiding, and any normal polling from N.I.N.A., PHD2 or a planetarium app keeps it disarmed. To change the 30 second limit or turn it off, set `motion_watchdog_seconds` under `server:` in `/var/lib/alpacabridge/config/default.yaml` (edit it as the `alpacabridge` user: `sudo -u alpacabridge nano /var/lib/alpacabridge/config/default.yaml`), then run `sudo systemctl restart alpacabridge`. Details are in the troubleshooting guide.

## New gear you can plug in

- **Canon DSLRs.** The Canon EOS 4000D, EOS 70D and EOS 250D (sold as the EOS 200D II in Asia) are validated. Pick "DSLR / Mirrorless" in the web UI. Two things to know from the bench: put the lens on MF, since autofocus makes every exposure fail, and put the 70D's mode dial on M, not B, since on B the shutter-speed list is empty. The 70D has no separate bulb control, so its longest exposure is 30 seconds.
- **Nikon D3300.** Validated on the same rig as the D5300 and D3200 with no changes needed. Long bulb exposures were also proven on real hardware for the first time, with 60 and 300 second frames. Dial on M with the shutter on Bulb, lens on MF, and Long exposure NR off.
- **Sky-Watcher EQM-35 Pro over an EQDIR cable.** Confirmed working on an FTDI EQDIR cable at 9600 baud with auto-detect, the same as over the mount's built-in USB port.

## Things that just work better

- **Devices that were not powered on at boot no longer show "(failed to load)".** A WiFi mount still joining the network, or a USB adapter powered after the Pi, used to make the auto-detected device fail at startup and stay failed until you restarted the service. The device now loads, the search for it runs when you connect, and a failed search tells you why in N.I.N.A. and the web UI. The first connect after a restart pays for the search, so it can take a few seconds longer.
- **The DSLR camera no longer calls itself "gphoto2".** The web UI option, the device name while no camera is attached, and the connect error messages now say "DSLR / Mirrorless". Saved configurations are unaffected.
- **A goto that fails partway now tells you.** On Sky-Watcher direct, SynScan, iOptron, Celestron and ZWO mounts, a slew that failed after it started used to look exactly like one that had landed. Your software now gets the error on its next check of Slewing.
- **Disconnected devices answer "not connected" instead of made-up values.** Reading ImageReady, camera temperature, cooler state, AtPark or AtHome on a device you have not connected yet now gives the proper error rather than a plausible-looking zero or false.

## Fixes worth knowing about

- **Sky-Watcher direct: guiding in RA while a Dec pulse was running left the Dec axis turning.** Each axis now has its own pulse, so one never cancels the other.
- **Sky-Watcher direct: guide pulses reported "still pulsing" for about a second after the axis stopped.** IsPulseGuiding now clears the moment the stop lands, so guiders see the true state.
- **Sky-Watcher direct: a lost stop command on a noisy EQDIR cable overshot the guide pulse.** Stop commands are now retransmitted quickly instead of waiting out a full timeout.
- **Sky-Watcher direct: an EQM-35 Pro in the north, or a Wave 150i in the south, pointed 12 hours out.** The pointing model now flips correctly with the hemisphere on those boards.
- **Sky-Watcher direct: the EQ-AL55i Pro is now a known board.** It reports its real name instead of "Mount (code 0x09)", and in the southern hemisphere it no longer points 12 hours out. This board is not ConformU-validated yet, since its pulse-guide accuracy is still being worked on.
- **Sky-Watcher direct: pulling the cable mid-slew and plugging it back in left the mount moving with nothing to stop it.** After a reconnect, a brief interruption keeps the motion under your control, while a long one stops the axes before the connect completes. Either way the log says what happened.
- **Sky-Watcher direct: a mount that was powered off with the USB adapter still plugged in kept reporting a position that ticked along at sidereal rate.** After three silent polls the driver now reports a communications fault instead of stale numbers, and recovers on its own when the board answers again. A board that was power-cycled is flagged as needing a reconnect.
- **Nikon bulb exposures over 30 seconds failed at the shutter close and hung the camera until a power cycle.** Fixed, and validated with 60 and 300 second frames on a D3300. Bodies with long-exposure noise reduction on are now waited for properly too.
- **A Pi whose clock booted at 1970 confused the web UI clock.** The server now reports the out-of-range clock as an error and the web page handles it without breaking.
- **Bad numbers no longer reach the mount.** A NaN or infinite coordinate, site value or guide rate is now refused by the server and by every telescope driver instead of being stored or sent to the mount.
- **Every telescope driver now refuses an out-of-range axis number the same way** for CanMoveAxis and AxisRates, and a missing Axis parameter is an error instead of silently meaning axis 0.
- **A disconnected device's DeviceState is now the empty list**, as the ASCOM specification requires, instead of a lone timestamp.
- **The full test suite now actually runs in CI.** Three of the four build jobs had been running zero core unit tests since they were created. They do now, and a new cross-driver contract sweep checks every driver against the ASCOM error rules, which is where several of the fixes above were found.

## Upgrading

```sh
sudo apt update && sudo apt upgrade alpacabridge
```

No configuration changes are needed. If you would rather the new motion watchdog did not stop your mount, set `motion_watchdog_seconds: 0` under `server:` in `/var/lib/alpacabridge/config/default.yaml` after upgrading, editing it as the `alpacabridge` user, then run `sudo systemctl restart alpacabridge`.
