# AlpacaBridge 4.0.0

This is a big one. Nine new drivers, a pile of new cameras and mounts validated on real hardware, a server that keeps its own clock straight at a dark site, and dozens of fixes found by running gear on the bench. The full technical list is in the changelog linked at the bottom.

## Read this first: three things that changed on purpose

- **Sky-Watcher mounts on the direct (EQDIR / USB / WiFi) driver now need a site.** Enter your latitude and longitude for the mount in the web UI before you connect. Without them the mount will refuse to connect and tell you why. This is what makes gotos land where they should.
- **The server will set its own clock from your imaging software.** A Raspberry Pi with no internet and no battery clock boots with the wrong time. When that happens, AlpacaBridge now takes the time your client (N.I.N.A., APT, etc.) sends and fixes the system clock. If your rig already keeps its own time, turn this off on the Server Info tab: untick "Sync time from client on connect" under "Clock from clients".
- **Scripts that poke the management API from another website now need the right headers.** Normal use through the web UI and your imaging software is unaffected. If you wrote a browser script against the server from a different origin, it will get a 403 until it sends the expected headers.

## New gear you can plug in

- **DSLR and mirrorless cameras** (Canon, Nikon and Sony through libgphoto2). Validated on the Nikon D5300 and D3200. ISO shows up as the camera's real ISO list, long exposures use bulb mode, and RAW files are decoded to a proper 16-bit image.
- **Sky-Watcher mounts, talking straight to the motor board.** Wave 100i and 150i, AZ-GTi class, and EQ mounts like the EQM-35 Pro over USB or the mount's own WiFi. No SynScan handset needed. Comet and satellite tracking rates are supported.
- **QHY Q-Focuser** and the **QHYCFW3 filter wheel on its own USB cable.**
- **iOptron iEAF and iAFS2/3 focusers**, the **iEFW-15 and iEFW-18 filter wheels**, and the **iCAM178M camera** (iCAM462C and iCAM464C validated too).
- **Gemini Power & Data Hubs Advanced 3** power and USB hub, and the **Gemini Motorized Flat Panel V3.**
- **SVBONY SC715C and SC571CC cameras** (they are ToupTek cameras inside, so pick ToupTek in the web UI).

## More hardware confirmed working

Every driver in this project is checked against the official ASCOM ConformU tool on the real device. Newly validated in this release: ZWO ASI533MC Pro, ASI120MM Mini and the EAFN focuser, ToupTek GPM662M, QHY5III585M, iOptron HAE16 EQ, and Sky-Watcher EQM-35 Pro.

## Things that just work better

- **Your site coordinates stick.** Latitude, longitude and elevation set from your imaging software are now saved, not lost on restart.
- **A failed connect tells you why.** The reason now shows up in N.I.N.A. and in the web UI instead of a bare "Connection failed" with the real message buried in a log.
- **Unplugging a cable is noticed.** Serial devices (Sky-Watcher, QHY Q-Focuser, Gemini, WandererAstro) now report the link as down instead of quietly serving stale readings.
- **Devices with a bad port setting no longer vanish from the web UI.** They stay listed so you can fix the setting.
- **Faster and friendlier networking.** Connections are reused instead of reopened for every request, the server listens on IPv6 as well as IPv4 (which fixes slow first contact from .NET clients), and big camera images are assembled much faster.
- **Park is non-blocking on every supported mount**, so imaging software that polls during a park no longer times out.
- **Auto-detect is quicker** when several USB-serial adapters are plugged in, and it no longer opens ports that belong to other devices.
- **The web UI header clock shows local time** and the version badge shows the branch when you are running a development build.

## Fixes worth knowing about

- Sky-Watcher direct driver: gotos were landing six hours off, tracking ran backwards in the southern hemisphere, and slewing to the pole read back wrong. All fixed and re-validated on hardware.
- iOptron HAE16 EQ gotos now settle exactly on target, same as the HAE29C fix.
- SynScan handset connects no longer stall your client or report a link that is not there.
- QHY cameras disconnect promptly instead of waiting on a background temperature poll.
- Dozens of thread-safety fixes across the focuser, switch, telescope and camera drivers, caught by the new concurrency stress suite that now runs in CI on every change.

## Upgrading

```sh
sudo apt update && sudo apt upgrade alpacabridge
```

Then, if you use a Sky-Watcher mount on the direct driver, open the web UI and add your site latitude and longitude before connecting.
