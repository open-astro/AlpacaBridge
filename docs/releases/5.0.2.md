# AlpacaBridge 5.0.2

This is a small fix release for mount users. Restarting the bridge no longer hangs behind a long slew, and SynScan and Celestron mounts stop reporting stale values when the handset stops answering.

## Fixes worth knowing about

- **Restarting or stopping the bridge is quick again during a slew.** Before, a stop that arrived while a long slew or a connect was in progress could wait up to 90 seconds and then be killed. Now the waiting client gets an error right away saying the server is stopping. A slew already under way keeps going, so check whether the mount is still slewing.
- **SynScan Tracking tells the truth after a failed restore.** If the handset missed the command that turns tracking back on (after an abort, a manual move or a guide pulse), the bridge used to keep saying tracking was on. It now asks the handset, or reports tracking off until the next abort, move, park, reconnect or tracking change.
- **SynScan and Celestron NexStar mounts report a lost handset instead of old values.** When the handset stops answering, reads such as tracking, slewing, park state, pier side and site or time now return a communication error rather than the last values the bridge saw. Service comes back by itself once the handset answers again. If your imaging software stops on that error, retry once the handset responds, or reconnect the mount.

## Upgrading

```
sudo apt update && sudo apt upgrade alpacabridge
```
