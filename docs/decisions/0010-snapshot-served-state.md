# Snapshot-served state

Status: accepted

## Context

A driver's getters and `DeviceState` each ask the device, or read driver fields under different locks. Request/response drivers pay a round trip per property (`TtlStatusCache` answered that for SDK-backed drivers, open-astro#294); poll-fed drivers read plain fields that a poll and a client write both change. Two defects follow: a client write can be lost to a poll that sampled before it, and a getter cannot tell a fresh value from one the link stopped refreshing.

## Decision

1. **What is served.** Getters for polled telemetry (position, tracking, slewing, status flags) read `util::StateSnapshot<T>` (`util/state_snapshot.h`) and never touch the device. Static capability and metadata answers stay outside it.
2. **One value, its age, a stale flag.** `read()` returns the frame, its `measured_at` on the task clock ([decision 0005](0005-task-clock.md)) and `stale` (age greater than `max_age`). A stale frame is still returned; the driver decides per getter whether stale means refuse (see [decision 0009](0009-link-loss-and-relink-policy.md)). Before the first publish, `read()` returns nothing.
3. **Write-through.** A client write changes the snapshot at once with `write(fn)`, so the next read sees it before the next poll. The write leaves `measured_at` at the last publish: a client write is not a measurement, so polled fields it did not touch must not read as fresh. A write with no frame held (before the first publish, after `reset()`) is not retained and `read()` keeps returning nothing, but it still drops a poll in flight (point 4); the next poll measures the device. `reset()` also drops a poll in flight, so a poll that sampled before disconnect cannot republish after it. The `write()` callback runs under the snapshot mutex and must not block or do device I/O.
4. **Publish-sequence guard.** A poll takes `begin_poll()` before it samples the device. Any write or `reset()` after that makes `publish()` drop the frame and return false. The next poll publishes. Chosen over comparing `measured_at` with the last write time: a counter needs no clock reading and cannot tie on a coarse or virtual clock. The cost is that a poll that overlaps a write loses its other fields too, for one poll period.
5. **Target fields.** OnStep and SynScan keep `target_ra_hours_`, `target_dec_degrees_` and the `target_*_set_` flags under `mutex_`: the setters and the getters all take it, so there is no data race today (checked against `onstep_telescope_driver.cpp` and `synscan_telescope_driver.cpp`; the review of open-astro#663 raised it, and the code does not bear it out). The adopted drivers keep the target pair under `mutex_` (SynScan and Bisque among them), since it is client-set state (point 2 of the Sky-Watcher adoption below); no driver moves it into the frame.
6. **Design.** A standalone type that takes a `TaskClock`, not an extension of `TtlStatusCache`: that cache fetches inside `get()` under its lock and ties validity to a TTL and link health, while the snapshot is fed by a separate poll and must never hold its lock across device I/O. Link health stays with the existing helpers.
7. **Slice scope.** The utility, this record and fake-clock tests (`tests/test_state_snapshot.cpp`). No driver is moved in that slice; Sky-Watcher is the first (see Sky-Watcher adoption). ConformU not re-run.

### Sky-Watcher adoption

The Sky-Watcher direct driver is the first on the snapshot (open-astro#1011). These points are decided for it; accepted after the rig ConformU pass: EQM-35 Pro, full Telescope suite, 2026-10-11, 0 errors, 0 issues, 0 timing violations (`AlpacaCore/conformu/Sky-Watcher/EQM-35 Pro/Linux-arm64-direct.txt`).

1. **TimeStamp is `measured_at`.** `TelescopeDriver` gains one protected virtual, `device_state_age()`, default `nullopt`. `get_device_state()` stays `final` and inline: it reads the age once, before the getters, and stamps `TimeStamp` with the system time minus that age (`device_state_timestamp(system_clock::time_point)`). Sky-Watcher returns the task clock now minus the frame's `measured_at`. The age, not a time point, crosses the hook, so the steady task clock ([decision 0005](0005-task-clock.md)) is never mixed with wall time. Telescope drivers that have not adopted a snapshot inherit `nullopt` and their output does not change. Rejected: dropping `final` so one driver overrides `get_device_state()` (it could drift from the omit-on-throw contract the base enforces), and a virtual on `AlpacaDriver` (every device type for one driver's need). Reverse: delete the hook and the override; TimeStamp is request time again.
2. **The frame holds what the poll measured.** `PolledFrame`: the raw axis angles and the per-axis status flags (running, speed mode), nothing derived. The dead-reckoned position stays a function of the model at read time (anchor angle + commanded rate x elapsed), so the PR #221 rate-offset continuity keeps its anchor model. Commanded rates, tracking and every other client-set value stay in the driver under `mutex_`, where the setter changes them and the next getter reads them, so write-then-read holds before the next poll. What a driver write changes about the frame goes through `write()`: a rate setter's in-place re-anchor, a sync, an invalidation and the end of a slew all drop the poll in flight, and all but the re-anchor also mark the status flags as not current (`status_current`), so Slewing cannot read true from a poll that sampled before the operation ended. A direct board read on a control path publishes without dropping the poll in flight, so the model never adopts a poll sample taken before its anchor. Rejected: a frame holding the dead-reckoned position (it bakes the rate in at poll time, so a rate setter would not be seen until the next poll, and #221 continuity breaks).
3. **One poll body, owned by the driver for the connection.** An `AsyncOperation` slot started at the end of a successful connect and cancelled and joined before disconnect closes the transport, waiting on the `TaskClock`. Period 100 ms start to start, ticks missed behind a slow link are skipped, never made up. The first frame is taken at the end of connect, so the getters have an answer, status flags included, when Connect returns. The exchanges run without `mutex_` (the protocol wrapper serialises them) so a getter never waits behind a slow link; the snapshot mutex is never held across I/O (point 3 above). The poll takes `mutex_` only around its exchanges, never across one: before them, to check that its connection is still open and read the counts per revolution, and after them, to publish and re-anchor the model. Its exchange results feed the existing link latch: with the getters off the wire it is the only silence detector while the mount is idle. Motion control (`wait_for_slew_complete`, the stop waits, the landing settle, goto planning) keeps its direct reads: they are control, not getters.
4. **Two bounds, never one.**
   - *Freshness*, `max_age` 200 ms: two poll periods, under the live limit guard's 250 ms MoveAxis poll. It drives only the guard (open-astro#436): the guard reads the snapshot while the frame is not stale and keeps its direct read while it is. A link whose four-transaction poll takes longer than 200 ms (the 100 ms-per-transaction fake) reads stale on every frame and the guard stays on its direct read; the getters still serve the frame. Stale is never a refusal.
   - *Lost*, [decision 0009](0009-link-loss-and-relink-policy.md) unchanged: `util::kLinkStalenessBound` of latched fault, or transport-gone evidence at once. Lost: the getters and setters throw `NotConnected`, `Connected` reads false, `DeviceState` is the empty list, `link_lost_at` is stamped (serial and UDP), the poll body ends and the frame is dropped. A frame older than the bound with no latch (a poll that stopped answering the clock) is lost too, but nothing ends its poll body or drops it then: a Connect relinks, stamps `link_lost_at` at the moment the frame crossed the bound, and drops the frame. Faulted (latched, younger than the bound): the getters throw the `DriverException` with the fault text, `Connected` stays true.
   - Rejected: a 200 ms `NotConnected` bound (decision 0009 alternative B: it drops `Connected` on any Wi-Fi hiccup) and a single bound for both (it cannot be both under 250 ms and at least twice the link latency). Reverse: revert the slice; the getters return to per-call reads.

#### Celestron telescope adoption (#1337, #2493)

- One status poll per connection, 1 s start to start, through `util::PolledState<PolledFrame>` (rule 7): equatorial pair, slewing flag, and every fourth tick alt-az, pier side and tracking mode. The driver holds no `PolledLinkHealth`, poll slot or loss latch of its own. The tick is the module's probe, and it returns the frame or throws. The sample and site exchanges run without the driver `mutex_`, and the module publishes the frame. The FindHome completion check, and every other Celestron exchange (connect, slews, park, sync, setters, pulse guide), also runs without `mutex_` (#1437, the Celestron slice of #295; [decision 0016](0016-getters-never-wait-on-device-io.md) rule 1): the probe reads the FindHome state under it, exchanges, and applies the result under it. `kSnapshotMaxAge` is 3 s and stale is served, never refused.
- Served from the frame: RightAscension, Declination, Altitude, Azimuth, Slewing, SideOfPier, Tracking, DeviceState (`TimeStamp` is `measured_at`). AtHome is a driver flag (`at_home_`), not a frame field. The 2 s position cache and its stamps are gone. Control-path reads (the frame read at a slew, Park or FindHome end, SetPark, the slew loops) measure directly and write through (`write()`): they do not renew `measured_at` and feed no fault latch, and only the poll's probe does.
- Slewing carries a `slewing_known` flag: a connect whose slewing query failed serves "not available yet" until a poll answers, not a guessed `false`.
- The site read the probe does for a mount whose connect-time read failed (retried every 30 s, so a link whose location never reads still samples on most full ticks) stores its result only while no client write has made the site valid. A site read that times out is a failed probe: it throws, the tick ends there with no sample, and it counts toward the fault latch and the frame-age loss like a failed sample. Thirty seconds apart, it never makes three failures in a row on a link whose sample answers.
- A FindHome completion check that fails is the FindHome's own failure, also a failed poll: its counter stops the mount on the third and the getters raise the FindHome failure text first, and the probe throws after the stop exchanges, with no sample, so the module counts the tick like any failed probe and a standing fault stays latched.
- Lost link: [decision 0009](0009-link-loss-and-relink-policy.md) applies through `PolledState`: `kLinkFailureThreshold` failed probes latch the fault, and `util::kLinkStalenessBound` of fault, or of a frame no probe refreshed, makes the link lost and closes the transport on the poll thread. A serial port the wrapper released (a pulled cable) is positive evidence: `CelestronProtocolWrapper::link_alive()` still makes `Connected` read false at once, and the probe reports it with `PolledState::lose_link()`, so the poll ends in that tick. A tick ends at its first failed exchange (the FindHome completion check, the location read, the Slewing and RA/Dec exchange, then each slow field), so a Disconnect waits for one exchange timeout. The tick on which the third FindHome check fails stops the mount first (up to three stop exchanges), so on a dead link that tick can wait longer; the stops go out with `mutex_` free, under the wrapper's per-link lock.

#### Bisque telescope adoption (#1367)

- One status poll per connection, 1 s start to start, through `util::PolledState<PolledFrame>` (rule 7; #2494): equatorial pair, alt-az, side of pier and Tracking, with `max_age` 3 s (it undercuts `util::kLinkStalenessBound`, which the module checks). Served from the frame: RightAscension, Declination, Altitude, Azimuth, SideOfPier, Tracking, DeviceState (`TimeStamp` is `measured_at`). The 2 s position cache (`kPositionCacheTtl`) and its stamps are gone.
- Slewing stays control-path state (`slewing_cached_`): the poll asks `IsSlewComplete` only for an async slew past its 8 s force window with no `SlewToCoordinates` wait running, and clears Slewing in the same step as the landed frame. The probe takes its token with `PolledState::begin_poll()` under `mutex_`, samples without it, and publishes with `PolledState::publish()` under `mutex_` in the same hold that applies the slew outcome, then returns `std::nullopt`, so the module publishes nothing over it: a write between the token and the publish (an abort, a retarget, a Tracking write) drops the frame and the outcome together. A good tick that the guard dropped still counts as a reply for the fault latch.
- Control-path ends that move the mount (sync, slew complete, FindHome, Park, pulse-guide end) measure the position at once and publish it, so a read right after sees where the mount is; every one of them takes the token (`PolledState::begin_poll()`) under `mutex_`, samples without it and publishes (`PolledState::publish()`) under it (a write since drops the publish), and every other Bisque exchange also runs without `mutex_`, under the protocol wrapper's per-link lock (#1438, the Bisque slice of #295; [decision 0016](0016-getters-never-wait-on-device-io.md) rule 1). A slew start, an abort and a move only drop the tick in flight.
- The slew Tracking gate reads TheSkyX live, writes the result through, and falls back to the frame's value when that read fails. When the frame never knew Tracking, the gate treats it as off, where the Tracking getter throws.
- Lost link: [decision 0009](0009-link-loss-and-relink-policy.md) applies through `PolledState`: three failed ticks latch a fault, a fault that has stood for `util::kLinkStalenessBound`, or a frame no tick refreshed for that long, is a lost link, and the module closes the transport through `on_lost` on the poll thread. The driver holds no `PolledLinkHealth`, poll slot or loss latch of its own, and `get_link_fault()` is the module's fault text. The first probe of a connect (the seed) publishes a frame with nothing known when TheSkyX does not answer the position, so the connect does not fail on it.

#### OnStep telescope adoption (#1783)

- One status poll per connection, 1 s start to start, fills `StateSnapshot<PolledFrame>`: the `:GU#` status, the `:GRa#`/`:GDe#` pair, and every second tick `:GA#`/`:GZ#` (and a site the connect could not read). The tick takes the operation lock for its exchanges, as a command does (decision 0016), and publishes under `mutex_` with it released. A `PulseGuide` adds one tick, in a slot of its own, 50 ms after the pulse's end (the 1 s ticks run on through the pulse), and `IsPulseGuiding` stays true until a frame sampled then is published (at most 2 s more), so a position read after the pulse is not one from mid-pulse. `kSnapshotMaxAge` is 3 s and stale is served, never refused. On OnStepX every tenth tick also reads the pier-side settings (`:GX96#`, `:GX94#`, `:GXE9#`/`:GXEA#`, `:GXEe#`/`:GXEw#`, #2179) into driver state under `mutex_`, outside the frame; a failed settings read keeps the previous settings and ends the tick only when the link is lost. The tick also reads `:GX90#` when the `:GU#` pulse-guide digit changes, `:GXTR#`/`:GXTD#` (OnStepX) when the known rate or the frame's compensation, tracking, parked or at-home flags change, and `:GT#` on every slow tick while tracking compensation hides the rate letter and the mount tracks, into driver state under `mutex_` outside the frame; a failed read keeps the previous value and ends the tick only when the link is lost (#2214). `DestinationSideOfPier` and `CanSetPierSide` read the frame and those settings, with no exchange (details in `.github/instructions/onstep.instructions.md`).
- Served from the frame: RightAscension, Declination (both through the rate-offset model below while an offset runs), Altitude, Azimuth, Tracking, AtPark, AtHome, Slewing, SideOfPier (on an OnStepX German mount the frame's `:GU#` pier-side letter, otherwise or when the mount reports no side the hour-angle rule from the frame's RA, #2179), DeviceState (`TimeStamp` is `measured_at`). AlignmentMode and TrackingRate are mount settings kept in driver state, not telemetry served from the frame (#2214): the poll and the control-path `:GU#` reads keep them current from the `:GU#` letters. AlignmentMode comes from the mount-type letter, which both firmwares always send, and a status without one throws `DriverException` as no status does. TrackingRate on OnStepX throws `DriverException` while no `:GU#` has answered since the connect, and then comes from the rate letter; while tracking compensation hides it, the last rate the driver knew (the last letter seen, its own writes, `:GT#`), sidereal until one of those answers. GuideRate is driver state too: the mount's `:GX90#` pulse-guide rate once read, and until then the half-sidereal informational value it served before #2214. The three 2 s caches and the getters' single read under the operation lock are gone, `util::LockGate::single_read()` with them. Client commands write through; control paths (the slew and sync GOTO checks, Park and FindHome and their body, the synchronous slew's wait, AbortSlew's tracking decision, the MoveAxis re-send tick) keep their direct `:GU#` reads and write them through, a status equal to the frame's left unwritten so a re-reading loop does not drop every tick. The synchronous slew publishes a full measurement where it ends (a failed one counts as a failed tick). The tracking restore an ended GOTO owes is sent by the tick that reads the end.
- While a rate offset runs (#2241), RightAscension and Declination, and DeviceState with them (it calls the same getters), serve a commanded model instead of the frame, which is up to one poll period old and moves in the mount's whole steps: an anchor (a position and its task-clock time) plus the offsets, in arcseconds per sidereal second, times the sidereal seconds since the anchor (the task clock's SI seconds divided by 0.9972695663), RA wrapped into [0, 24) hours and Dec clamped to +/-90 degrees. The model is driver state under `mutex_`, built from snapshot data and the stored offsets only, so rule 1 holds and the getters make no exchange. It runs only on OnStepX, with a non-zero offset at TrackingRate sidereal, while the frame says tracking and not slewing, pulse guiding, moving an axis, homing, parking or parked, and no MoveAxis, slew grace, pending Park or FindHome or pulse of the driver's own is under way; in every other state the frame is served as read, and the next frame measured in a state the model runs in anchors it again (a frame sampled before a pulse's end plus 50 ms does not). Each published frame is checked against the model at the time of its `:GRa#`/`:GDe#` read: within 2 arcsec on both axes keeps the anchor, beyond either re-anchors on the measurement (RA in RA-axis arcseconds, hours x 54000; 2 arcsec is four 0.5 arcsec steps of the TeSeek HM-17, and a mount with larger steps needs at least four of its own), and a frame 30 minutes or more after the anchor re-anchors on the measurement anyway. Before any stored offset changes the model re-anchors under the old offsets: a `RightAscensionRate` or `DeclinationRate` write (before its send), the `TrackingRate` change that zeroes the offsets, and an offset change the poll reads; with the offsets zero the last anchor holds until a frame measured after the change is published, so the position does not jump back to an older frame. A sync anchors at the synced position, and a GOTO, park, home, MoveAxis start, a MoveAxis stop that ends a move or a pulse, a pulse guide, the stops or a `Tracking` write drop the anchor. A frame whose `:GRa#`/`:GDe#` read is older than the model's last such change (a re-anchor, a sync, a drop) changes nothing: the poll publishes under `mutex_` alone, so a tick that sampled before a command can publish inside or after it, and it neither ends that hold nor anchors the model. Extrapolation stops `kSnapshotMaxAge` (3 s) after the last publish: a stale frame is served as it is (rule 6), never refused and never extrapolated. `DeviceState`'s `TimeStamp` stays `measured_at` (rule 5). Rejected: a faster poll (more serial and Wi-Fi traffic, still up to 4 arcsec of lag at 40 arcsec/s at 100 ms, and no fix for offsets below one step per poll period).
- Lost link: [decision 0009](0009-link-loss-and-relink-policy.md) applies; three failed ticks latch the fault, a tick ends at its first failed exchange, and the poll's failed ticks turn a fault standing past the bound into a lost link (a getter only throws the fault).

#### Celestron CGX telescope adoption (#1940)

- One state poll per connection, 250 ms start to start, through `util::PolledState<CgxFrame>` (rule 7): the raw RA and Dec encoder pair, two `MC_GET_POSITION` exchanges with `mutex_` free. Sky values are computed when a getter reads the frame, from the current UTC, site and mechanical hemisphere, so a frame never carries an old sidereal time. `max_age` is 1 s, and stale is served, never refused. The poll flushes a desynchronized stream with `CelestronCgxProtocol::resync()` on the fd it holds and never reopens a port.
- Served from the frame: RightAscension, Declination, Altitude, Azimuth, SideOfPier, DeviceState (`TimeStamp` is `measured_at`). Tracking, TrackingRate, Slewing, AtHome, AtPark and IsPulseGuiding stay driver state and read no wire (IsPulseGuiding is true while a guide slot runs, until the mount reports its packet inactive, or while a slew, Park or FindHome waits on the mount for the packet of a pulse it superseded, #2263). The 30 ms stationary raw-pair cache and its key are gone, and no getter takes `motion_start_mutex_`.
- The [decision 0011](0011-cgx-logical-reference-continuity.md) guards come before the frame: the site, link health, a pending stop, unverified motion and the session reference. A getter reads the frame under `mutex_`, and every reference change (FindHome, the meridian-flip rebase, Sync) writes its new labels through under the same lock, so a getter never pairs a new reference with old labels. A reference change writes the labels rather than calling `reset()`, which would leave a connected driver with no frame until the next poll.
- Control-path reads (Sync's branch read and label check, slew planning and arrival, PulseGuide's polarity read) measure the axes directly and write the pair through.
- Lost link: [decision 0009](0009-link-loss-and-relink-policy.md) applies through `PolledState` (its Adoption row says what is done). A timed-out poll is a session error: the stream recovers on the next reply and the reference needs FindHome (decision 0011 rule 2).

## Rules

The rules a change is checked against. Each names where it applies and what checks it; the reasoning is in the Decision above.

1. In a driver whose Adoption row is adopted, getters for polled telemetry read the `util::StateSnapshot` and never touch the device. Scope: `AlpacaCore/src/vendors/*/*_driver.cpp`. Checked by: review (trace polled getters to snapshot reads with no device exchanges); the roster by `scripts/check_docs_drift.py` check 23.
2. A client write goes through `write()` and leaves `measured_at` at the last publish. Scope: `AlpacaCore/src/vendors/*/*_driver.cpp`, `AlpacaCore/include/alpacacore/util/state_snapshot.h`. Checked by: `AlpacaCore/tests/test_state_snapshot.cpp` (the type), review (a driver that changes a frame field outside `write()`).
3. A poll takes `begin_poll()` before it samples, and a write or `reset()` after that drops its publish. Scope: `AlpacaCore/include/alpacacore/util/state_snapshot.h`, `AlpacaCore/src/vendors/*/*_driver.cpp`. Checked by: `AlpacaCore/tests/test_state_snapshot.cpp` (the type), review (a driver poll that samples before `begin_poll()`).
4. The snapshot mutex is never held across device I/O, and a `write()` callback does no I/O. Scope: `AlpacaCore/src/vendors/*/*_driver.cpp`. Checked by: review (snapshot callbacks and critical sections contain no device exchanges or blocking work).
5. A telescope that serves `DeviceState` from the snapshot supplies its measurement age through `device_state_age()`: `measured_at`, or the mandatory-sample timestamp named in its Adoption row for staged publication. Partial publication and client writes never renew an existing mandatory sample's age. Scope: `AlpacaCore/include/alpacacore/telescope_driver.h`, `AlpacaCore/src/vendors/*/*_telescope_driver.cpp`. Checked by: `AlpacaCore/tests/test_skywatcher_snapshot.cpp`, the `[timestamp]` cases in `AlpacaCore/tests/test_zwo_telemetry_concurrency_stress.cpp`, review (the hook returns task-clock age, not a wall-clock time point).
6. Each adopter states per getter what a stale frame means, in its instruction file; stale alone never refuses. Scope: `.github/instructions/*.instructions.md`, `AlpacaCore/src/vendors/*/*_driver.cpp`. Checked by: `AlpacaCore/tests/test_contract_sweep.cpp` (the "Contract sweep snapshot" cases: a stale frame is served, never refused, for every adopted driver), `scripts/check_contract_sweep.py` (rule 6: the sweep roster matches the Adoption table), review (the per-getter statement in the instruction file).
7. A poll-fed driver whose Adoption row names `PolledState` serves its frame through `util::PolledState` (`util/polled_state.h`) and holds no `PolledLinkHealth`, poll slot or loss latch of its own for that frame. The probe returns `std::optional<Frame>`: a frame is published by the module; `std::nullopt` means the device answered and the probe published through `PolledState::begin_poll()` and `PolledState::publish()` itself (to apply a result under the driver's `mutex_` in the same hold as the frame), or had nothing to publish. Both count as a good probe for the fault latch, and a frame no publish refreshed for `util::kLinkStalenessBound` is a lost link. Scope: `AlpacaCore/src/vendors/*/*_driver.cpp`. Checked by: review (no `PolledLinkHealth`, `StateSnapshot` or `link_lost_` in the driver; a `begin_poll` is the module's forwarder, taken under `mutex_`), `AlpacaCore/tests/test_polled_state.cpp`.
8. In a driver whose Adoption row is adopted, a getter or control path that needs a value only the device supplies (status, position, telemetry) and has no answer for it since the connect, because no frame is held, the frame lacks that field or the control path's own read failed, throws `DriverException`, never `InvalidOperation`: ASCOM's `DriverException` "includes communication errors", and `InvalidOperation` rejects a command for a state the client can change. A value the client can set and has not (the site under [decision 0019](0019-connect-without-site.md), `UTCDate`) is outside this rule. Scope: `AlpacaCore/src/vendors/*/*_driver.cpp`. Checked by: review (a refusal for an unanswered device value thrown with a code other than `DriverException`).

## Alternatives rejected

- **Extend `TtlStatusCache`.** Different ownership of the fetch (see point 6).
- **Compare `measured_at` with the last write time for the guard.** Ties on equal clock readings (point 4).
- **A per-field sequence.** More state for a poll period of lost fields.

## How to reverse

Each adopter in the Adoption table moved in its own PR; reverting that PR restores its field reads. Once no adopter is left, delete the header and its test.

`util::PolledState` (rule 7) reverses by reverting the PR that added it: the header, its test, the Astroasis and QHY adoptions and the amendments to this record and to [decision 0016](0016-getters-never-wait-on-device-io.md) go together, and the two focusers return to their hand-written poll glue. Each later adopter reverts its own PR.

## Consequences

- Getters for polled telemetry answer from memory and carry their age; each driver that moves onto the snapshot states per getter what stale means.
- A client that writes at least once per poll period keeps every poll's frame dropped, so the frame ages and reads stale; that is intended, because the device was not measured.
- A write before the first publish is lost (point 3); drivers that need it set it through the device or hold it outside the snapshot.
